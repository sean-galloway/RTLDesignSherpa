# Regenerating a PeakRDL block

The `.rdl` is the only source. The regblock RTL, the docs page and every
regmap are outputs, and an output that was not regenerated is a lie that every
test agrees with -- they all read the stale copy. This note is the mechanics;
[[generated-rtl-discipline]] is the why, and `/CLAUDE.md` Rule #0 is the
enforcement.

Always through `bin/peakrdl_generate.py`, never raw `peakrdl`: the wrapper
emits the RTL, the docs and the regmap in lockstep, and raw peakrdl skips the
last two.

## What one invocation emits

```
python3 bin/peakrdl_generate.py <block>.rdl -o <outdir> --no-html
```

```
<outdir>/rtl/<top>.sv          regblock
<outdir>/rtl/<top>_pkg.sv      its package
<outdir>/docs/<top>.md         register documentation
<outdir>/<top>_regmap.py       RegisterMap dict, read BY NAME ([[registers-by-name]])
```

`--no-html` is usual; drop it only if someone wants the HTML book. **The
`.vlt` Verilator waiver beside a block is NOT generated** -- it is
hand-maintained and named directly by the filelists, so regeneration never
touches it and deleting it breaks the build.

`-o` is mandatory in practice. The default can write an orphan the build never
reads, which then drifts silently; that case and its 95-file cleanup are in
[[generated-rtl-discipline]].

## ONE RUN EMITS ONE REGMAP

`--regmap-output` **renames** the emitted regmap. It does not add a second one.
So a block whose DV testbenches load a regmap under a different filename needs
**two invocations**, and a single combined command silently produces only the
renamed file:

```
# WRONG -- emits only dv/.../pumice_regmap.py; regs/generated/pumice_csr_regmap.py
# is left at whatever it already contained
python3 bin/peakrdl_generate.py $P/rtl/macro/pumice_csr.rdl \
    -o $P/regs/generated --no-html \
    --regmap-output $P/dv/tbclasses/pumice_regmap.py
```

```
# RIGHT -- two runs, one per destination
python3 bin/peakrdl_generate.py $P/rtl/macro/pumice_csr.rdl \
    -o $P/regs/generated --no-html

python3 bin/peakrdl_generate.py $P/rtl/macro/pumice_csr.rdl \
    -o $P/regs/generated --no-html \
    --regmap-output $P/dv/tbclasses/pumice_regmap.py
```

The second file is not a copy of the first: the usage docstring inside a
regmap derives from its own filename, so the two differ by more than their
path and `cp` is not a substitute for the second run.

This shape is common, not exotic -- stream, rapids, pumice, hpet, pic_8259,
pit_8254 and rtc all carry a second DV-facing regmap.

**What it costs when the second run is skipped.** `16eda8ed7` added
`SCHED_WR_WM.wr_batch_max` to pumice and regenerated `regs/generated/` only.
The TB copy kept a month-old layout in which the field did not exist and
`RSVD` still spanned `31:16`, straight across its bits, so every component
test read-modify-wrote zeros over `[23:16]`. It presented as "`csr_write_field`
clobbers the whole register" (PUMICE-047) and sent a session after a
testbench-framework bug that was never there. Nothing looked wrong: the file is
stamped *"Auto-generated … DO NOT EDIT MANUALLY"*, so it reads as current.

## Establishing a block's invocation

An artifact does not record the command that produced it -- regmaps from
different runs carry byte-identical "Generated by" banners. So do not guess:

1. Run the candidate invocation into a scratch directory.
2. Diff against what is committed.
3. Iterate until it matches byte-for-byte.

Only then is the invocation known. A guessed one reports permanent staleness
and blocks every commit.

## Then put it in the manifest

`bin/check_rdl_regen.py` carries a `MANIFEST` of invocations and the tracked
files each must reproduce. It regenerates into a temp directory and diffs;
it never writes into the tree. Wired into `bin/hooks/pre-commit` and CI, so a
`.rdl` edit without its regen is caught at commit rather than by a silent
divergence months later.

One manifest entry per INVOCATION, not per block -- a block with a second
regmap destination is two entries, which is exactly how stream and pumice
appear there.

Coverage is partial (TASK-088 tracks the rest of the 24 blocks). A block not in
the manifest is not gated, so adding yours is part of touching it.

## After regenerating

Every generated `.sv` has just changed, so a run against stale build
directories reports green for the OLD design -- the precise failure Rule #0
exists to prevent:

```
cd <component>/dv/tests && make clean-all && make run-all-gate
```

For pumice specifically the char-framework sim is also the board gate before
any RTL commit (PUMICE-023).
