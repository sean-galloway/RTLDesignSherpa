# BUG-022: the ADDR_MAP.bank_lsb constraint is too permissive by log2(DFI_RATE)

`pumice_csr.rdl`'s comment on `ADDR_MAP.bank_lsb` states the software
constraint as

    Constraint: log2(BL/DFI_RATE) <= bank_lsb <= COL_WIDTH (RTL clamps).

The correct bound is **`log2(DRAM_BL)`**. The stated one is `log2(DFI_RATE)`
bits too low, and a map programmed at the stated minimum splits a single DRAM
burst across several banks.

**Severity: LOW, and the reason matters.** Nothing has ever programmed it.
Every build, every test and the reset value ship `bank_lsb = 0x0A` = COL_WIDTH
= ROW_MAJOR, which satisfies any bound. This is a trap for the first person to
enable bank interleaving, not a live defect -- and interleaving is a real
planned axis, which is why it is worth fixing before someone follows the text.

**Not in the generated registers.** The wrong formula lives in `//` comments in
the RDL, so it does not reach `regs/generated/docs/pumice_csr.md` or the
regmap: the generated `desc` for the field is just "Bank field LSB in the word
address (=COL_WIDTH -> ROW_MAJOR)", which is correct. Only the RDL source and
`addr_mapper.sv`'s header carry the formula.

## Why log2(DRAM_BL) is the bound

`addr_mapper` indexes **device words** -- `BYTE_OFFSET_WIDTH =
log2(DRAM_DEVICE_WIDTH/8)` -- and `pumice_core` derives `SUB_COL_STRIDE =
DRAM_BL` in those same units, describing it as "one JEDEC burst". So a burst
spans `DRAM_BL` columns at this block's granularity and the bank field must sit
above all of them. `BL/DFI_RATE` is the burst measured in DFI WORDS, which is
not the unit the column field counts in.

## Measured, not derived

`scoria`'s port of this block has a case that finds the smallest `bank_lsb`
keeping an aligned burst inside one bank
(`test_scoria_addr_mapper.py::minimum_bank_lsb_is_measured`). Same RTL, same
geometry family:

| burst (device words) | measured minimum bank_lsb | log2(burst) |
|---|---|---|
| 4 | 2 | 2 |
| 8 | 3 | 3 |
| 16 | 4 | 4 |

At pumice's shipping geometry (DRAM_BL=4, DFI_RATE=2) the stated minimum is
`log2(4/2) = 1` where the measured minimum is 2. At bank_lsb=1 with BW=3 a
4-word burst starting at word 0 decodes to banks 0,0,1,1 -- it straddles two.
At the DDR3 point (BL8 over a 1:4 gear) the stated minimum reads 1 against a
true 3, and an 8-word burst spans banks 0-3.

## Fix

Two lines of `pumice_csr.rdl`: `log2(BL/DFI_RATE)` -> `log2(DRAM_BL)` in the
"minimal col_lo" line and in the Constraint line. No RTL change -- the mapper
clamps to [0, COL_WIDTH] and otherwise does exactly what the knob says; this is
a specification error, not a behaviour one.

Worth doing in the same pass: `addr_mapper.sv`'s header states the same bound a
THIRD way, as `log2(cols/burst)`, which for a 1024-column page and an 8-word
burst is 7. That one is too RESTRICTIVE -- wasteful rather than unsafe (it
interleaves every 512 bytes instead of every burst) -- but it is still wrong,
and having three mutually inconsistent versions of one bound in one component
is how the next reader picks the wrong one.

## Where it came from

scoria inherited all three statements with the port. The equivalents there are
fixed, with the bound measured rather than asserted, and the scoria RDL now
carries the derivation. This item exists so pumice does not keep the original.

A caution for whoever fixes it: an earlier revision of scoria's corrected
header credited `log2(BL/DFI_RATE)` as the right formula while fixing
`log2(cols/burst)`. Two wrong bounds in opposite directions make it easy to fix
one by adopting the other.
