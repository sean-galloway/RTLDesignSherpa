# MC-001: Macro names to the `*_layer` convention on every memory controller

> Source: owner direction, 2026-10-04 (pumice examples given inline).
> Scope: `projects/components/mem-ctrl-ip/{pumice-ddr2-lpddr2,scoria-ddr3-lpddr3,andesite-ddr4-lpddr4}` — basalt (gen 5, reserved) adopts the convention at birth.

**Priority:** P3
**Status:** open
**Owner:** TBD

The macro tier of every memory controller should read as the layer it is:
`*_layer`, matching the already-correct `*_dfi_layer`. Today two macro
names break the convention on the older controllers, and andesite inherits
one of them.

Renames (pumice examples given by the owner):

| Controller | From | To |
|---|---|---|
| pumice | `rtl/macro/pumice_axi4_ifc.sv` | `rtl/macro/pumice_axi4_layer.sv` |
| pumice | `rtl/macro/pumice_mem_cmd_scheduler.sv` | `rtl/macro/pumice_scheduler_layer.sv` |
| pumice | `rtl/macro/pumice_dfi_layer.sv` | — no change (already conventional) |
| scoria | `rtl/macro/scoria_axi4_ifc.sv` | `rtl/macro/scoria_axi4_layer.sv` |
| scoria | `rtl/macro/scoria_mem_cmd_scheduler.sv` | `rtl/macro/scoria_scheduler_layer.sv` |
| scoria | `rtl/macro/scoria_dfi_layer.sv` | — no change |
| andesite | `rtl/macro/andesite_mem_cmd_scheduler.sv` | `rtl/macro/andesite_scheduler_layer.sv` |

Module names inside the files rename with the files. Out of scope, by the
owner's examples: the FUB `*_ifc` training blocks (`wrlvl_ifc`,
`rdlvl_ifc`, `ca_train_ifc`) — those are interfaces, not macro layers, and
keep their names.

- [ ] Rename the five files + their module names across the three trees.
- [ ] Chase every reference: instantiations (`u_*` parents in `rtl/top/*`,
  `rtl/macro/*`), filelists (`rtl/filelists/**`, the aggregate `*_all.f`
  files, and the flattened `rtl/lint_reports/verilator/*.f` — regenerate or
  sed), the DV side (`dv/tb/**`, tbclasses, `dv/filelists/**`), and the
  books (HAS/MAS pages, `docs/kmaps/gen_*.py` paths where they name these
  files, scoria/pumice carry-diff invocations in task notes).
- [ ] `grep -ri "mem_cmd_scheduler\|axi4_ifc" projects/components/mem-ctrl-ip`
  returns only the in-scope FUB training `*_ifc` blocks and historical
  prose, no live macro references.
- [ ] Suites still green on all three trees (at minimum the scoria scheduler
  suite + the andesite arbiter/timers suites that elaborate the renamed
  module's FUBs); `bin/filelist_registry.py --check` PASS.
- [ ] Record the convention in `vault/Tasks/memory-controllers/`: future
  macros are born `*_layer` (a future andesite AXI4 macro is
  `andesite_axi4_layer` at creation, never an `*_ifc`).

Closes when all five renames land with references chased and the trees
still build.
