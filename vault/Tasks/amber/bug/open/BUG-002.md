# BUG-002 — pair rig full: deterministic cross-cache deadlock at SEED=45207 (MISS_FILL × SNOOP)

**Filed:** 2026-10-14
**Cell:** `test_amber_pair_rig.py::test_amber_pair_rig_s016w2l64b64_mon_full`
**Severity:** high — a coherence deadlock corner with a deterministic
reproducer; full-level pair-rig soaks land on it at some rate.

## Reproduction (deterministic, ~22 s solo)

```sh
cd projects/components/cache-ip/amber-mesi-l1/dv/tests
rm -rf local_sim_build/test_amber_pair_rig_s016w2l64b64_mon_full
REG_LEVEL=FULL SEED=45207 SIM=verilator python3 -m pytest \
  "test_amber_pair_rig.py::test_amber_pair_rig_s016w2l64b64_mon_full" -q
```

Hangs; the TB hang monitor dumps state every 25 cycles:

```
HANG c6700 fstate 2 pend 10 buf 00 absp 00 c0st 7 c1st a c0ar 10 c1ar 10 s0ac 01 s1ac 01 s0cr 0 s0cd 01
```

- `c0st 7` = core 0 in `AMBER_CTRL_MISS_FILL`, parked
- `c1st a` = core 1 in `AMBER_CTRL_SNOOP`, parked
- both sides' AR channels and snoop AC channels show outstanding
  (`c0ar/c1ar/s0ac/s1ac` nonzero), snoop response (`s0cr`) never comes

Consistent with a cross-cache dependency cycle: core 0's fill waits on a
snoop response that core 1 cannot issue because core 1 is itself waiting
inside snoop handling on something core 0's fill must produce.
