# BUG-004: amber Genesys2 tally bins always zero — harness drives the MonBus group "drop everything" filter masks

**Priority:** P2 (functional path clean; observation path silent)
**Status:** CLOSED 2026-10-16 (fix committed, board-verified with perf sweep)
**Verification:** axil cosim green with the new observation-alive assertion
(`assert sum(bins) > 0`) across three profile iterations; uart equivalence
cell green; functional bitstream rebuilt (timing clean, 0 failing
endpoints), programmed to Genesys2 serial 200300B818A0; 11-config board
perf sweep (`host/amber_perf_sweep.py`) all runs done + err-free with
coherent MonBus counts (`results/perf_sweep_20261016T111032Z.json`).
Fidelity proven in sim: group record path delivers ~11.2k records for a
4k-transaction run (vs 1.3k with the near-max watermark) — effectively
lossless against the ~2.8 events/access the two caches emit.
**Found:** 2026-10-16, amber board perf-sweep investigation
**Root cause (proven in RTL + waveform, fix pending board re-verify):**
`amber_pair_harness.sv` instantiates `monbus_axil4_axil4_group` with every
`cfg_axi_*`/`cfg_core_*` filter mask tied to `16'hFFFF`, reading FFFF as
"enable all". `monbus_group_core.sv` decodes the `*_pkt_mask` bits as
**drop** masks (`pkt_drop = cfg_axi_pkt_mask[pkt_type]`, likewise CORE;
`pkt_to_write_path = !pkt_drop && !pkt_to_err_fifo`), and the per-event
masks likewise force drops. FFFF = drop every packet type and event, so
the group's record expander never accepted a packet: write FIFO stayed
empty, `m_axil_awvalid` never fired, and `monbus_tally_axil` counted
nothing — every bin zero, UNEXPECTED zero.

## Symptom

Both cycle injectors complete 20000/20000 transactions (err=0, CRCs
stable), and every MonBus tally bin — including the UNEXPECTED catch-all
— reads zero, on the board AND in cosim.

## Evidence chain (each step verified 2026-10-16)

1. Board perf sweep (`host/amber_perf_sweep.py`): injectors ran clean,
   all bin deltas zero across 11 configs. Canonical smoke shows the same.
2. Cosim `test_amber_pair_harness_axil` smoke (AMBER_SMOKE_COUNT=2000)
   passes — its tally reads were `dut._log.info` only, never asserted.
3. FST waveform of that cosim: `mon0_valid` 3880 rising edges,
   `mon1_valid` 3859, `merged_valid` 6373 (arbiter forwards), but
   `group_awvalid` = 0 and `group_wvalid` = 0 across the entire run.
4. RTL decode: masks are drop semantics; FFFF drops all. Repo reference
   `axi4_intf_slave_observer.sv` ties the same leaf masks to `16'h0000`
   with the comment "let everything through" — same convention, opposite
   value.

## Fix

Tie all `cfg_axi_*` / `cfg_core_*` drop masks in `amber_pair_harness.sv`
to `16'h0000` (err_select stays 0; AXIS masks were already 0). Lower
`cfg_flush_watermark` from `16'hFF00` to `48` beats (16 records): the
group drains only on flush triggers, and with the watermark near-max the
drain rate sat ~4x below the event arrival rate — cosim FST showed only
1,280 of ~7,700 emitted events reaching the tally (~17%) even after the
mask fix, with the rest dropped by the caches' monlite under
backpressure. Add an observation-alive assertion to the axil cosim smoke
(`assert sum(bins) > 0`). Board-side: rebuild + reprogram the functional
bitstream, then re-run the perf sweep.

## Process gap (same shape as BUG-003)

Every green check (350/350 unit grid, 6/6 G2 harness, board smoke ALL
PASS twice) verified the FUNCTIONAL path only. Nothing ever asserted
that the observation path counts — the smoke printed bins and moved on.
The axil cosim now asserts it.
