# BUG-008: math_fp8_e4m3_to_fp8_e5m2 converts the top of the e4m3 range to NaN

**Priority:** P2
**Status:** FIXED 2026-10-10 (generator template fix + regenerate + formal re-proof; grid is the regression net)
**Owner:** TBD

## Defect

`rtl/math/math_fp8_e4m3_to_fp8_e5m2.sv` decoded its source specials with the
infinity-style pattern:

```systemverilog
wire w_is_inf = (w_exp == 4'hF) & (w_mant == 3'h0);
wire w_is_nan = (w_exp == 4'hF) & (w_mant != 3'h0);
```

FP8 E4M3 has **no infinity**: exp=15 is entirely finite, and NaN is only
exp=15, mant=7. Every finite e4m3 value with exp=15, mant=1..6 — i.e. the
entire top of the range, 264..448 including e4m3 max-normal — was classified
as NaN and converted to e5m2 NaN (`{sign, 5'h1F, 2'h2}`) with ow_invalid=1.

Example: 448 (0x7E) must convert to e5m2 0x5F (448 is exactly representable:
1.75 x 2^8); the buggy RTL produced 0x7E, which *as e5m2* is exp=31/mant=2 =
NaN. Silent data corruption class: finite magnitudes become NaN downstream.

`generate_upconvert` already emitted the correct format-aware decode
(`w_is_inf = 1'b0`, `w_is_nan = exp==max & mant==mant_max`); the two
narrowing templates (`generate_downconvert`, `generate_same_size_convert` in
`bin/rtl_generators/ieee754/fp_conversions.py`) hardcoded the infinity-style
decode. Only e4m3->e5m2 (same-size) is reachable today with a no-infinity
source, so only that module was wrong; both templates were fixed for any
future no-inf source pair.

## Fix

- Generator: both narrowing templates now branch on `src_has_inf` exactly
  like `generate_upconvert`.
- Regenerated only `math_fp8_e4m3_to_fp8_e5m2.sv` (full `generate_all.py`
  also produces ~115 files of unrelated drift — Created-date stamps plus a
  stale reset-macro template — reverted; see issue/open/ISSUE-002.md).
- Flags: exp=15 inputs no longer raise ow_invalid; finite-in/finite-out.

## Why existing checks missed it

- The pre-grid conversion TB swept `FPTestValues.get_special_values`, whose
  e4m3 list never includes exp=15 finite values.
- The formal wrapper (`formal_math_fp8_e4m3_to_fp8_e5m2.sv`) models e4m3
  correctly, but no assertion covers "finite input converts to a finite
  output" — on the buggy RTL the exp=15/mant=1..6 inputs vacuously satisfied
  everything. **Follow-up: add `p_finite_in_finite_out` (and a maxnorm cover
  point) to the wrapper.**
- The TASK-007 9-cell special-value sweep caught it on first landing
  (+maxnorm/+maxnorm cells) — the regression net now exists.
