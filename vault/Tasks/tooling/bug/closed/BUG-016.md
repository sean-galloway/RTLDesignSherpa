# BUG-016: the one val/amba runner that didn't pin a simulator fell into cocotb-test's icarus default, and the oss-cad-suite vvp wrapper cannot host system libpython3.12

**Priority:** P3
**Status:** closed (filed at close, 2026-10-08)
**Fixed in:** the commit that adds this record (pins `simulator="verilator"` in `val/amba/test_axis4_pattern_pair.py`; 3/3 params re-passed in 31 s)

## What happened

`test_axis4_pattern_pair.py` was the only runner in val/amba that called
`cocotb_test.run()` without `simulator=` — every sibling pins
`simulator="verilator"` explicitly. cocotb-test's default is
`os.getenv("SIM", "icarus")`, so any bare `pytest val/amba/test_axis4_pattern_pair.py`
from a shell without `source env_python` (which exports `SIM=verilator`)
silently ran all three params (ch1/dw128, ch2/dw256, ch4/dw512) on icarus.

The icarus path then dies at time 0 — not in RTL, at dynamic-link time. The
oss-cad-suite `vvp` is a bash wrapper that execs the suite's OWN loader:

```sh
exec .../lib/ld-linux-x86-64.so.2 --inhibit-cache --inhibit-rpath "" \
     --library-path .../lib .../libexec/vvp "$@"
```

`--library-path` hard-forces the suite's lib dir, whose `libm.so.6` tops out at
`GLIBC_2.35`. The VPI module then dlopens the system
`/usr/lib/x86_64-linux-gnu/libpython3.12.so.1.0`, which after a system update
requires `GLIBC_2.38`:

```
Unable to open lib 'libpython3.12.so.1.0':
  .../oss-cad-suite/lib/libm.so.6: version `GLIBC_2.38' not found
```

so `vvp` exits before elaboration and the pytest cell reports
`xml.etree.ElementTree.ParseError: no element found` (empty xUnit output from
the dead simulator). Surfaced 2026-10-08 as 3 red legs during the
pattern_gen→injector rename verification; proven pre-existing/unrelated by a
clean rebuild whose `.vvp` contained the new module names (compile is fine,
only the sim launch breaks) and by a passing gw14 run of the same icarus flow
on 2026-10-05, i.e. the system libpython outgrew the suite libm underneath a
test that had been getting away with it.

## Fix

Pin `simulator="verilator"` in `test_axis4_pattern_pair.py`, matching all five
sibling runners it shares the directory with. Verilator legs never touch the
suite loader, so the libm ceiling is irrelevant to them.

## Residual risk (named, not fixed)

- Any FUTURE cocotb-test consumer that omits `simulator=` inherits the same
  trap the moment system libpython demands > glibc 2.35. `LD_LIBRARY_PATH`
  cannot rescue the icarus path — the wrapper's `--library-path` overrides it.
  If icarus is ever genuinely needed, the durable fix is swapping the suite's
  `libm.so.6` for the system 2.39 one (backward-compatible; suite binaries use
  only ≤2.35 versioned symbols). Deliberately not done unilaterally: it is a
  shared tool install under `/mnt/data/tools` and other agents run sims from it
  continuously.
- Procedural guard already exists: the regressions skill says `source
  env_python` before any bare pytest, exactly because bare pytest silently
  drops `SIM`. This bug was that guard's concrete cost made visible.
