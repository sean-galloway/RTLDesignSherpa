# BUG-003: RegisterMap.walk() crashes on an ERROR response, disabling the board register walk

## Reproduction

    cd projects/fpga-systems/Genesys2/dma-ip/stream/build-obs
    make program
    make host-reg_walk ARGS="--port /dev/ttyUSB0"

Observed (2026-09-26, Genesys 2, fresh build-obs bitstream):

    Invalid response format: b'ERR'      (x7)
    Traceback (most recent call last):
      File ".../build-obs/host/host_reg_walk.py", line 181, in main
        fails = rm.walk(read=br.read, write=br.write,
      File ".../bin/TBClasses/apb/register_map.py", line 177, in walk
        if smask and (got & smask) != (dflt & smask):
    TypeError: unsupported operand type(s) for &: 'NoneType' and 'int'

## Cause

`uart_axi_bridge.read()` returns `None` when the target answers with an ERROR
response (uart_axi_bridge.py:112/115). `walk()` had a sentinel for "no reply at
all" (`WALK_NO_RESPONSE = 0xDEADBEEF`) but no path for `None`, so the value
reached `got & smask` and raised.

The ERROR responses are CORRECT. `2f23fe075` (2026-09-24) added the MON-window
guard in `stream_top_ch8.sv`: with `USE_MON_REGS=0` (= `USE_AXI_MONITORS=0`,
which is build-obs and build-perf) the MON window at 0x1000 deliberately returns
an error so "not built" is distinguishable from "built and reading zero". The
defect is only that the walker cannot survive it.

## Impact

Board register validation for every `USE_AXI_MONITORS=0` build has been dead
since 2026-09-24 and nothing said so: the walk aborts on the first MON register,
so NO endpoint gets a verdict. The last recorded good obs walk is
`build-obs/results/obs_regblock_validation_2026-09-03.txt` -- "6 endpoints, 290
registers, ALL PASS". build-mon was unaffected (its MON window is built) and kept
passing, which is why this stayed invisible.

## Fix applied

`bin/TBClasses/apb/register_map.py`: `None` is now recorded as
"ERROR RESPONSE (bus error -- window not built?)" and the walk continues, at both
the reset-value read and the write-readback. The `WALK_NO_RESPONSE` sentinel keeps
its own distinct message.

## Closed 2026-09-27

**Status:** CLOSED -- both halves done, board-verified.

The MON window is skipped when the bitstream says it is absent. Both stream
walkers (`build-obs/host/host_reg_walk.py`, `build-mon/host/host_reg_walk.py`)
read `BUILD_CONFIG.USE_MONITORS` by name (field offset from the harness regmap,
FAIL OPEN: unreadable means walk everything as before) and, when it is 0, walk
the `stream` endpoint with `names=` restricted to offsets below 0x1000 -- the
MON regfile's window, derived from the regmap (86 registers at >= 0x1000, all
`*MON*`; 57 below, none). Genesys 2, build-obs (`USE_MONITORS=0`):

    stream_apb  STREAM + MON   MON window skipped: 86 regs, BUILD_CONFIG.USE_MONITORS=0
    stream_apb  STREAM + MON   143 regs  PASS
    harness_csr / slvmon_apb / obs_apb / stream_tally_cfg / slave_tally_cfg  PASS
    ALL ENDPOINTS PASS

`walk()` has a test now: `bin/TBClasses/apb/tests/test_register_map_walk.py`, a
dict-backed fake bus that latches only writable non-pulse bits and can answer
ERROR (None) or nothing (the sentinel) at chosen addresses. It pins the three
contracts the board walk relies on -- an ERROR response is ONE failure and the
walk continues, no-reply is a distinct failure, `names=` restricts the walk --
plus `no_write` never poking. 5/5.
