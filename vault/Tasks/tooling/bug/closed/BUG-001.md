# BUG-001: the doc port-table checker's suffix threshold produces false positives

**Priority:** P2. Attribution gaps make the checker skip pages silently and
mis-blame rows on multi-module pages.
**Status:** CLOSED 2026-09-26. Both defects resolved; see Fix below.

**Where.** `bin/check_doc_examples.py`, `name_in_src()`:

```python
return len(n) >= 3 and bool(re.search(rf'\b\w*{re.escape(n)}\b', src_low))
```

The suffix arm exists so a CORRECT page can cite a protocol name -- an AXI-Stream
table says `TDATA` where the port is `m_axis_tdata`, an APB table says `PRESETn`
where it is `presetn`. Sound idea, wrong threshold.

**CORRECTED 2026-09-26 -- the threshold is NOT the defect.** This bug was filed
claiming two false positives from the length gate. Re-measured, only one was ever
a threshold problem and it is already fixed:

| Originally reported | What is actually true |
|---|---|
| `axis4_master.md:222` names `TID` | REAL threshold bug, already fixed. The gate was `>= 4`, so `tid` (3 chars) fell through to the whole-word arm and failed while `TDATA` was absolved. At the current `>= 3` it resolves. |
| `stream 16_monbus_axil_group.md:143` names `monbus_ts` | NOT a threshold bug. `monbus_ts` is an ABBREVIATION of `monbus_timestamp`, not a suffix of it -- `'monbus_timestamp'.endswith('monbus_ts')` is False and `\b\w*monbus_ts\b` does not match. No threshold value resolves it. It was a DOC defect and is fixed: the row now names the real port. |

**So do not lower the bound.** `>= 3` is correct and load-bearing. Lowering it to 2
would admit `\b\w*ts\b`-style matches that absolve almost anything, which is the
failure the bound exists to prevent, and it would not have caught `monbus_ts`
anyway.

**Repro:**

```bash
python3 bin/check_doc_examples.py 2>&1 | grep monbus_ts   # before any fix
```

**Care required -- do not just lower the bound.** The gate is deliberately
permissive already; `\b\w*en\b` would match almost anything, which is why the
bound exists. A length cut is the wrong instrument. Better: match against the
module's PORT LIST split on `_`, so `ts` matches `monbus_timestamp` only if it is
a whole underscore-delimited segment or a documented protocol alias.

**Must not regress:** the `PRESETn`/`ARESETN`/`TDATA` class stays absolved, and
the anti-vacuity controls keep working -- blinding `RE_TBL_HDR` must still exit 1
("read no port-table rows at all"), and a planted `zz_fabricated_port_xyz` must
still be caught.

**Second, smaller defect in the same file.** Attribution takes the FIRST module
named in a `**Module:**` line, so a page declaring two
(`pumice 09_bank_machine.md`: `` `bank_timer.sv` (per-bank) / `pumice_bank_timers.sv`
(aggregator) ``) resolves neither and reports its 10 correct rows as bad. Either
support multi-module declarations or skip the page loudly rather than compare
against nothing.

## Fix

**Multi-module attribution, and coverage with it.** `check_doc_examples.py` gained
`declared_sources()`, which takes EVERY backticked name on a `**Module:**` line and
unions their sources, plus a declaration-attributed table walk for pages whose
filename is not a module name.

Measured before adopting it, because extending attribution makes the gate inspect
pages it has been skipping and that can go red on contact:

- 46 previously-unchecked pages brought into scope
- exactly 2 have bad rows, and BOTH were already filed:
  [[rapids TASK-008]] (`ch01_overview/02_port_list.md`) and
  [[rapids TASK-009]] (`ch02_fub_blocks/07_beats_latency_bridge.md`)
- the 3 pumice multi-module pages come out CLEAN -- which is the proof that their
  10 "bad" rows were the first-token blame, not doc defects

`BASELINE` therefore went 0 -> 2, with the two tracked pages named in the comment
and an instruction to drop it back to 0 as they close. Choosing to leave 46 pages
unchecked in order to keep a 0 would be preferring a prettier number to coverage.

**Threshold.** No change, deliberately. `>= 3` is correct and load-bearing; see the
corrected table above. The `TID` case was the real threshold bug and was already
fixed by `>= 3`, and `monbus_ts` was a doc abbreviation no threshold resolves --
fixed in the doc instead (`monbus_ts` -> `monbus_timestamp`, verified against
`monbus_axil4_axil4_group.sv`).
