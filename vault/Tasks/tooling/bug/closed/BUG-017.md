# BUG-017: test_rs_loop_uart_windows fails Verilator compile on UNOPTFLAT w_epoch — blocked on the amba lane's uncommitted monbus_group_core.sv rework

**Priority:** P3
**Status:** closed 2026-10-09 — resolved without a code change on this side:
targeted re-run **1 passed in 2:37** against the then-current working tree.
The amba lane fixed the circular `w_epoch` path in-place in its uncommitted
rework (diff grew 369 -> 385 insertions between the two runs). Original
failure was concurrent-edit contamination, exactly as filed.
**Owner:** TBD (handed to the amba lane by convention — the fix is in their working tree)

## What happened

The BUG-015 re-run (2026-10-09) of the RS loop UART suite under cocotb 2.1.0
scored 17 passed / 1 failed: `test_rs_loop_uart_windows` dies in the Verilator
compile with

    %Warning-UNOPTFLAT: rtl/amba/monitor/monbus_group_core.sv:847:34:
    Signal unoptimizable: Circular combinational logic:
    'rs_loop_uart_tb_top.u_harness.u_obs.g_egress_axi4.u_group.u_core.w_epoch'
    %Error: Exiting due to 1 warning(s)

The suite's waiver list does not carry `-Wno-UNOPTFLAT` (the stream build-mon
suite does, which is why only this configuration trips).

## Cause (measured, not guessed)

`rtl/amba/monitor/monbus_group_core.sv` is **modified in the shared worktree**
(369 insertions / 462 deletions uncommitted on top of a101397fd, the amba
lane's BUG-039 "pipeline the monbus record path" commit, board-verified
2026-10-09). The circular combinational path on `w_epoch` exists in that
uncommitted state. The other 17 RS tests — including the observer-grid cells —
compiled the same dirty file with configurations that do not elaborate the
egress-AXI4 group path; `uart_windows` is the one that does.

This is concurrent-edit contamination, the exact class
`vault/handbook/dv/running-regressions.md` documents ("RTL can move underneath
a long run too"). It is NOT a cocotb 2.1.0 regression: the failure is a
Verilator lint exit, cocotb-version independent.
