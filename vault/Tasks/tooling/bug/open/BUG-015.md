# BUG-015: the cocotb 2.x flip matrix did not cover the UART-equivalence suites

**Priority:** P3
**Status:** open
**Owner:** TBD

## What happened

The 2026-10-08 cocotb 2.x flip (tooling TASK-025, closed owner-confirmed the
same day) removed `cocotb.external` / `cocotb.function`. Sixteen files still
used them — every silicon/sim-equivalence UART suite (rapids byte/char, stream
mon, RS and BCH loop UART, pumice ddr2 char, cdc demo). All of them failed at
startup (rapids byte sink: 190 ns in, `module 'cocotb' has no attribute
'function'`). The flip matrix that gated TASK-025 exercised val/ suites but
not these; the breakage surfaced the same day only because a utility-ip
TASK-003 board-matrix build runs verify-sim as a gate.

Fixed in 61ea5dc13 (mechanical rename to `cocotb._bridge.bridge`/`resume`;
rapids byte sink re-passed 31 s). The RS/BCH UART suites' full grids should be
re-run under 2.1.0 to confirm the rename did not perturb the suites
themselves.

## Scope

- Re-run at FUNC from clean, under cocotb 2.1.0: RS loop UART suite, BCH loop
  UART suite, stream build-mon, rapids char harness, pumice ddr2 char — the
  suites touched by 61ea5dc13 that are not re-run by the routine campaign.
- Extend the flip-matrix suite list (or the pre-release check) to include at
  least one suite per `cocotb._bridge` consumer, so the next cocotb minor
  cannot take these down silently again.
