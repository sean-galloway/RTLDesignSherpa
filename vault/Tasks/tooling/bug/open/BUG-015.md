# BUG-015: the cocotb 2.x flip matrix did not cover the UART-equivalence suites

**Priority:** P3
**Status:** open
**Owner:** TBD

## What happened

The 2026-10-08 cocotb 2.x flip (tooling TASK-025, closed owner-confirmed the
same day) removed `cocotb.external` / `cocotb.function`. Sixteen files still
used them — every silicon/sim-equivalence UART suite (rapids byte/char, stream
mon, RS and BCH loop UART, pumice ddr2 char, cdc demo). All of them failed at
startup (rapids byte sink: 190 ns in, `module 'cocotb' has no attribute
'function'`). The flip matrix that gated TASK-025 exercised val/ suites but
not these; the breakage surfaced the same day only because a utility-ip
TASK-003 board-matrix build runs verify-sim as a gate.

Fixed in 61ea5dc13 (mechanical rename to `cocotb._bridge.bridge`/`resume`;
rapids byte sink re-passed 31 s). The RS/BCH UART suites' full grids should be
re-run under 2.1.0 to confirm the rename did not perturb the suites
themselves.

## Scope

- Re-run at FUNC from clean, under cocotb 2.1.0: RS loop UART suite, BCH loop
  UART suite, stream build-mon, rapids char harness, pumice ddr2 char — the
  suites touched by 61ea5dc13 that are not re-run by the routine campaign.
- Extend the flip-matrix suite list (or the pre-release check) to include at
  least one suite per `cocotb._bridge` consumer, so the next cocotb minor
  cannot take these down silently again.

## More 2.x residue found 2026-10-08 (amba BUG-039 verification)

Two more pre-existing 2.x breaks surfaced while validating the monitor-lite
fix — both confirmed pre-existing by stash baseline (fail identically without
the fix):

1. **TB-class handle truthiness** — `self.aclk_name = aclk._name if aclk else
   'aclk'` in the `bin/TBClasses/**/*_tb.py` constructors raises
   "cannot be cast to bool" under 2.1.0, killing every monitor-lite wrapper
   grid cell. FIXED for the four `bin/TBClasses/axi4/*_tb.py` constructors
   (`aclk is not None`) as part of the BUG-039 commit; the same idiom is still
   present in axis4/axil4/axis5/apb5/etc. constructors (~20 files, grep
   `_name if .* else 'aclk'`) and will take those suites down the same way.
2. **`TESTCASE` selection ignored** — `test_axi_monitor_soak.py`'s pktgen
   runner (`testcase='monitor_soak'`) executes the module's OTHER cocotb test
   (`monitor_soak_monlite`) too, against the pktgen DUT, which fails on
   `dut.cmd_valid` (the lite-only pin). The monlite runner itself passes.
   Likely cocotb 2.x ignoring the TESTCASE env that cocotb_test sets; check
   whether cocotb_test's testcase kwarg needs a different mechanism under 2.x.
   Until then every multi-test module runs ALL its tests in EVERY build.
3. **Cached-handle conditionals in `bin/TBClasses/amba/amba_cg_ctrl.py`** —
   the walrus `if signal := self._get_signal(...)` (2 sites) plus cached-signal
   checks `if self.<clk/gating/idle/enable/idle_count>_signal:` (11 sites)
   raise "cannot be cast to bool" under 2.1.0; killed
   `val/amba/test_amba_clock_gate_ctrl.py` at 0 ns. Surface route: tooling
   BUG-016's SIM guard sent a bare-pytest run down the verilator leg, where
   the residue became visible instead of dying on the icarus env first.
   FIXED 2026-10-09 (all 13 sites to `is not None`; test re-passed).
