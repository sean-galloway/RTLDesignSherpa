# BUG-002: the HPET test report's self-assessment fields can never be true

**Priority:** P2. Every HPET run, in every configuration, reports
`timer_functionality_verified: False` and `total_tests_run: 0` while passing.
A green run that says it verified nothing is worse than a red one.

**Where.** `projects/components/retro_legacy_blocks/dv/tbclasses/hpet/hpet_tb.py`

```python
# line 614 -- 'tests_run' is never a key in stats
'total_tests_run': stats.get('tests_run', 0),

# line 642 -- timer_events is never appended to
'timer_functionality_verified': stats['timer_events'] > 0,
```

**Two dead fields, both structural rather than intermittent.**

1. `tests_run` is set **nowhere**. Grepping the whole DV tree finds one
   occurrence: the `stats.get('tests_run', 0)` that reads it. `get_statistics()`
   (line 310) does not define it. So `total_tests_run` is permanently 0.

2. `timer_events` has exactly one writer, `add_timer_event()` at line 220, and
   that method is **never called**. Grepping
   `projects/components/retro_legacy_blocks/dv/` for `add_timer_event` returns a
   single hit: its own `def`. So `len(self.timer_events)` is always 0, and
   `timer_functionality_verified` -- defined as `timer_events > 0` -- is always
   False.

**Measured 2026-09-27**, 8-timer FULL, both clock configurations:

| Config | timer_events | interrupt_events | errors | verdict printed |
|---|---|---|---|---|
| non-CDC | 0 | 164 | 0 | `timer_functionality_verified: False`, `total_tests_run: 0` |
| CDC | 0 | 184 | 0 | same |

Both runs passed 4/4. Interrupt events ARE recorded, which is what makes this a
wiring gap rather than a dead timer: the interrupt path feeds the scoreboard and
the timer-event path does not.

**Expected behaviour.** Either the fields report something true, or they do not
exist. A report field whose value is fixed by construction is a false negative
waiting to be believed -- and the repo has been bitten twice by checkers that
reported a verdict without a count.

**Repro:**

```bash
source env_python
cd projects/components/retro_legacy_blocks/dv/tests && make clean-all
REG_LEVEL=FULL pytest "test_apb4_hpet.py::test_hpet[8-43981-16-0-full-8-timer custom full]" -v
# grep the log: timer_events': 0, timer_functionality_verified': False, on a 4/4 PASS
```

**Fix is a DV design decision, not a one-liner**, which is why this is filed
rather than patched in passing. `add_timer_event(timer_id, event_type,
counter_value)` expects `'match'`/`'reload'`/`'disable'` events and a counter
value, which implies a timer monitor that samples comparator matches -- that
does not exist yet. Options: wire a monitor and call it; or derive timer events
from the interrupt stream already being captured; or delete both fields and stop
claiming them. Whoever owns HPET DV should pick.

**Must not regress:** `interrupt_events`, `errors_detected` and the APB
statistics are all correctly wired and should keep working.

**Found while closing RLB/hpet BUG-001**, whose stale timeout claim masked it:
the runs that disproved that bug are the ones that exposed these two fields.
