# BUG-002: the HPET test report's self-assessment fields can never be true

**Priority:** P2.
**Status:** CLOSED 2026-09-27. Fixed and verified across three cells; evidence
below.

**Where.** `projects/components/retro_legacy_blocks/dv/tbclasses/hpet/hpet_tb.py`

```python
# line 614 -- 'tests_run' was never a key in stats
'total_tests_run': stats.get('tests_run', 0),

# line 642 -- timer_events was never appended to
'timer_functionality_verified': stats['timer_events'] > 0,
```

**Two dead fields, both structural rather than intermittent.**

1. `tests_run` was set **nowhere**. One occurrence in the whole DV tree: the
   `stats.get('tests_run', 0)` that read it. `get_statistics()` did not define
   it, so `total_tests_run` was permanently 0.
2. `timer_events` had exactly one writer, `add_timer_event()`, and that method
   was **never called** -- a single grep hit, its own `def`. So
   `len(self.timer_events)` was always 0 and `timer_functionality_verified`,
   defined as `timer_events > 0`, was always False.

Every HPET run in every configuration reported `total_tests_run: 0` and
`timer_functionality_verified: False` while passing. A green run that says it
verified nothing is worse than a red one.

**Fix.**

- `HPETScoreboard.reset()` gains `self.test_results = []` (the single init path,
  since `__init__` calls `reset()`).
- New `HPETScoreboard.record_test(name, passed)`.
- `get_statistics()` exposes `tests_run` and `tests_passed` from that list.
- `monitor_interrupts()` calls `add_timer_event(i, 'match')` on a **rising**
  `timer_irq[i]`. A rising IRQ is the comparator match becoming observable, and
  the monitor already samples that signal on every `RisingEdge(hpet_clk)`, so
  nothing intrusive was added.
- `add_timer_event()`'s `counter_value` is now optional and documented as None
  when unsampled. The monitor deliberately does not read the counter: the main
  counter is internal to `hpet_core` and not a port, and an APB read from a
  monitor would perturb the very transactions the scoreboard counts. Faking a
  value would have been worse than omitting it.
- `generate_test_report()` now reads `stats['tests_run']` / `stats['tests_passed']`
  explicitly instead of `.get(..., 0)`, so a future wiring break raises KeyError
  instead of silently reporting 0 again -- the exact failure this bug was.
- `record_test()` is called from all three runner loops
  (`hpet_tests_basic.py`, `_medium.py`, `_full.py`) in both the pass and the
  exception path, so a test that throws is counted as run and not passed.

**Verified 2026-09-27**, after `clean-all`, three cells:

| Cell | suites | total_tests_run | tests_passed | timer_events | timer_functionality_verified |
|---|---|---|---|---|---|
| 8-timer non-CDC FULL | 4/4, 17/17, 4/4 | **25** | 25 | 80 | **True** |
| 8-timer CDC FULL | 4/4, 17/17, 4/4 | **25** | 25 | 89 | **True** |
| 8-timer non-CDC GATE | 4/4 | **4** | 4 | 2 | **True** |

All three `1 passed`, `errors_detected: 0`. Nothing regressed.

**Anti-vacuity -- why these are counts and not new constants.**

- `total_tests_run` is 25 at FULL and 4 at GATE. 25 is exactly the tests lists'
  4 + 17 + 4, and 4 is basic alone. The number tracks the depth actually run.
- `timer_events` equals the number of DISTINCT observed IRQ assert edges, 1:1.
  Deduplicating the log on timer id and sim time: GATE 2 distinct asserts vs
  `timer_events: 2`; non-CDC 80 vs 80; CDC 89 vs 89. (A raw `grep -c` shows
  exactly 2x these, because pytest's capture emits every cocotb log line twice
  -- once timestamped, once with sim time. That 2x is capture duplication, not
  double counting, which is why the dedup check matters.)
- `timer_functionality_verified` still reads `timer_events > 0`, so a run in
  which no timer fires still reports False. The predicate was never the problem;
  its input was.

**Must not regress:** `interrupt_events`, `errors_detected` and the APB
statistics were already correctly wired and still are (interrupt_events 164/184
before the fix, 160/178 asserts observed after -- same mechanism, untouched).
`verify_register_access()` and `verify_interrupt_behavior()` are called from
`test_apb4_hpet.py:143-144` and their inputs are unchanged.

**Change surface is self-contained.** Repo-wide, nothing outside the hpet TB
consumes `add_timer_event`, `tests_run`, `total_tests_run` or
`timer_functionality_verified`; no test asserts on the report's values; and the
~30 other `generate_test_report` definitions are separate methods on separate
classes. Only `test_apb4_hpet.py:137` calls this one.

**Left alone deliberately.** `verify_timer_functionality()` is now *usable* --
it filters `timer_events` for `'match'` -- but is still called from nowhere.
Calling it needs per-timer expected fire counts, which is a DV design decision
beyond this bug. Noted rather than half-wired.
