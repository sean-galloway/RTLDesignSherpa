# BUG-019: pumice's DV wrappers have no depth axis -- REG_LEVEL changes how many cells run, never how deep

**Status:** open 2026-09-27  **Priority:** P2. Filed from tooling BUG-004 when
that global item closed: the mechanism (shared `reg_level_grid()` /
`level_env()` helpers, `bin/review/check_test_levels.py`, the per-area profile
recipe) exists and every other component area is converted (bridge, converters,
misc, apbx-xbar, retro_legacy_blocks, stream, rapids). pumice is the last.

## The defect

`bin/review/check_test_levels.py` on `dv/tests/{fub,macro,phy,top}` reports
10/22, 0/5, 0/4, 3/5 compliant. The 23 non-compliant wrappers either have no
REG_LEVEL grid at all or never export TEST_LEVEL to the simulator, so a FULL
run of those tests does exactly what a GATE run does. Depth is a fiction for
two thirds of the area. (The conftests no longer stamp TEST_LEVEL -- that half
was done earlier -- which is precisely the half-state tooling BUG-004 warns
about: the stamp gone, nothing put in its place.)

## The fix (ready-made, NOT simulated)

Branch `tooling-pumice-halves`, commits `01052d460` + `b50495fde`: 23 wrappers
plus a new `dv/tbclasses/pumice_levels.py` (PROFILE gate/func/full, 24 knobs,
func == the literal each file used before, gate smaller, full larger; eight
single-scenario knobs are gate=func=1 and only grow at full). Every wrapper
gains a stacked `parametrize("test_level", reg_level_grid())`,
`**level_env(test_level)` in extra_env, a `_{test_level}` build/log suffix, and
its repetition counts routed through the profile. Protocol and geometry
constants (BL, DFI_RATE, widths, NUM_BANKS, timings, exact-shape expectations)
were deliberately left alone; the per-file knob and leave-alone table is in
the `01052d460` commit message.

Two departures from the rapids shape, both forced by this area and documented
in the files: each wrapper reads TEST_LEVEL itself beside its knob (the checker
cannot follow `tbclasses.*` imports through a hyphenated component path), and
the five pure-python tests (phy x4, the command-stream checker) monkeypatch
`level_env()` into the process environment since there is no simulator.

Checker after: 22/22, 5/5, 4/4, 5/5. Cells collected GATE 301 -> 301,
FUNC 340 -> 435, FULL 361 -> 569.

## What closes it

A green checker is not a passing suite. Rebase the branch, then
`make clean-all && make run-all-full-parallel` per area from clean, read
failures from the JUnit XML, and retune any knob that breaks or costs too much
-- the least-slack ones are `arbiter_issue_window` gate=100,
`wr_serializer_paced_writes` full=6 and `dfi_cdc_items` full=72. macro's
12-config scheduler matrix is unchanged (it only gained the depth cell);
`sched_mixed_pairs` and `sched_timeout_reps` are the two macro knobs that grow
work. Closes when FULL is green on main with the checker at 36/36.
