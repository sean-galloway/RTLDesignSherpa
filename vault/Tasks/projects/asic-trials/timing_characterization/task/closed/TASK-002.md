## CLOSED 2026-09-29 -- two FPGA technologies measured, three parameter sweeps run, tables generated

`docs/baseline_results.md` is GENERATED by `fpga/tools/baseline_report.py`
from the sweep CSVs under `fpga/reports/`; no number on it is typed. Against
the acceptance criteria:

| Criterion | What was run |
|---|---|
| Two FPGA targets compared | Artix-7 xc7a100t (Vivado `bitstream-sweep`, 100/200/300 MHz, board wrapper, full P&R) and Cyclone V GX 5CGXFC5C6F27C7 (Quartus `quartus-sweep`, 100..300 MHz, bare `char_top`). UltraScale+ is not available to this repo; Cyclone V is the second 28 nm fabric and the more useful contrast (a different vendor's ALM vs a LUT6 slice). |
| Carry chain width sweep | `CARRY_WIDTH` 8..256 on Cyclone V at 150 MHz: delay 2.15 -> 5.09 ns at one LUT level throughout (the ALM carry chain is the path). |
| NAND depth sweep | `NAND_LEVELS` 4..12: delay 2.36 -> 5.27 ns, 2 -> 5 LUT levels. The first run folded the 8/10/12 points into one netlist because char_top clamps leaves to `NUM_FLOPS` (256); rerun with `NUM_FLOPS 4096`, and the clamp is now in the config comment and on the page. |
| DSP vs LUT multiplier | `MULT_TYPE` 0..4 at 16 bits: the inferred multiplier is one DSP block, 2.73 ns, 0 LUT levels, 139 ALMs; the dadda / wallace LUT trees are 8.4-9.5 ns, 8-10 levels, ~470 ALMs. Type 4 has no 16-bit implementation and falls back to inferred (stated in the RTL header and on the page); types 1 and 3 synthesized identically from different sources, recorded as an observation. |
| Markdown tables | Sections 1-3 of the page; section 4 says how to read across vendors (compare slopes, not absolute slack; an ALM is not a LUT). |

Mechanism, so the page can be regenerated: `syn_sweep_quartus.tcl` gained
`SWEEP_PARAM` / `SWEEP_VALUES` (one point per (frequency, value), directories
`sweep_<F>MHz_<PARAM>=<v>`), the parser gained a `variant` column parsed from
that suffix (test added, 8/8), `make quartus-sweep` gained
`QUARTUS_REPORTS_SUB` and only overrides the config's frequency list when
`FREQS_MHZ` is given on the command line, and `fpga/quartus/sweeps/*.tcl` are
the three sweep configs. Sizes: 5 + 6 + 5 + 5 Quartus points at ~60-90 s each,
3 Vivado points at ~5-10 min each.

Not done: the spreadsheet builder still does not ingest either CSV (README_FPGA
5.7 lists that gap); the Artix-7 parameter sweeps would need the Vivado flow to
take generics, which it does not today.
