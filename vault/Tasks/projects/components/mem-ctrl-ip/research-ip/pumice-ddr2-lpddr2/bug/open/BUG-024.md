# BUG-024: pumice_zq_ctrl random_soak loses exactly one grant at some SEED draws — `total() == grants` off by one

**Priority:** P3
**Status:** open
**Filed:** 2026-10-10 (surfaced during mem-ctrl-ip Phase 2 Task 1; proven PRE-EXISTING; filed as BUG-024 after collision with closed BUG-023)
**Owner:** TBD
**Repro:** `cd projects/components/mem-ctrl-ip/research-ip/pumice-ddr2-lpddr2/dv/tests/fub && SEED=58170 python -m pytest "test_pumice_zq_ctrl.py::test_pumice_zq_ctrl[random_soak]"`

## Symptom

The soak (defer enabled, randomized demand/overdue) ends with the DUT's
lifetime grant counter one BELOW the TB's granted count:
`AssertionError: assert 36 == 37` (grant issued by the TB never lands in
`total_o`). Deterministic at `SEED=58170` (the TB seeds its own
`random.Random(int(os.environ.get('SEED', '12345')))` — NOT cocotb's
random seed; unset SEED always runs the 12345 scenario, which passes).

## Pre-existing — proven, not a Phase-2 regression

2026-10-10: reproduced on the pristine pre-Task-1 tree
(`git worktree add /tmp/pumice-pre 0a0a216c6`, same command, same seed —
FAIL). Phase 2's mc_common_pkg extraction (Task 1) was exonerated by the
same A/B. Surfaced now only because the full-suite harness drew 58170; no
prior recorded run drew it.

## Likely shape (for whoever picks it up)

One grant is issued in a cycle where the DUT is not in a state that counts
it — candidates: grant while `req` deasserts same-cycle (TB grants on
`req() && rng < 0.8` after 1 clock of demand), a defer/overdue window that
swallows a re-request, or `total_o` increment gated on a condition the
granted command didn't meet. The TB's model counts every `grant_one()`;
the DUT counts accepted ZQ commands. A one-cycle skew between the TB's
grant pulse and the DUT's accept would produce exactly this off-by-one at
demand-dependent seeds.

## Suggested first discriminator

Log `req`, `grant`, `total_o`, and the FSM state at the failing seed;
find the cycle where `grant_one()` pulses but `total_o` does not advance.
Do NOT "fix" by relaxing the assertion — the accounting identity is the
test's point.
