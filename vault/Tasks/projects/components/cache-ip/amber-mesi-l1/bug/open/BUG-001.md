# BUG-001: miss_fill FULL soak txn 6040 — DUT serves hit where oracle expects miss + dirty-victim drain + fill

**Priority:** P2
**Status:** open
**Owner:** TBD

Found 2026-10-12 by FULL grid v2 (leg amber_unit_macros). Deterministic:
same seed fails identically at HEAD (post l1_ rename), at 93ce944a2
(pre-rename, post deadlock-fix B), and at 255d8d9f5 (pre-Issue-A, pre-B,
pre-rename) — identical transaction index and check failures every time.
Pre-existing corner, exposed by seed luck; NOT caused by the 2026-10-11/12
TB fixes, the deadlock fix, or the l1_ rename.

## Reproduction

```
cd projects/components/cache-ip/amber-mesi-l1/dv/tests
SEED=81795 REG_LEVEL=FULL python3 -m pytest -q \
  test_amber_miss_fill_macro.py::test_amber_miss_fill_macro_s016w2_full
```

Fails at `full[6040]` (~3 min). Failing checks (all on one transaction):

- `MISS_VICTIM entered: got False expected True`
- `FILL_WRITE entered: got False expected True`
- `REPLAY entered: got False expected True`
- `rsp data: got 1710588546579113756 expected 17601867675199592480`
- `exactly one fill_start: got 0 expected 1`
- `fill beat count: got 0 expected 8`
- `dirty-victim drain: got 0 expected 1`
- `dirty-victim victim_load: got 0 expected 1`

Shape: the oracle expected a read miss that selects a dirty victim, drains
it, fills 8 beats, and replays; the DUT instead returned data with no
victim/fill activity at all (reads as a DUT-side hit, or a request the DUT
resolved without the miss path the oracle predicted).
