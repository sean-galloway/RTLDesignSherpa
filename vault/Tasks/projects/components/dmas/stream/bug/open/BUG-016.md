# BUG-016: the monitor PKT_MASK registers are described as "1 = enable"; the hardware masks on 1

**Priority:** Low -- documentation only. The board tooling already programs
the mask correctly (`projects/fpga-systems/Genesys2/stream/bin/mon_configs.py`:
"1 = drop that packet type at monbus entry"), and the all-masked reset (0xFFFF)
is the intended behaviour (Sean, 2026-09-28, on the rapids copy).
**Status:** OPEN 2026-09-27. Found from rapids BUG-008, the same description in
the RAPIDS copy of the register file, corrected there.

## Mechanism

`rtl/macro/stream_mon_regs.rdl` describes `DAXMON_PKT_MASK`, `RDMON_PKT_MASK`
and `WRMON_PKT_MASK` as "Packet type mask [15:0] - 1=enable, 0=disable".
`stream_top_ch8` feeds them to `monbus_axil4_axil4_group` and to the monitors
(`axi_monitor_filtered`, `axi_monitor_lite`), all of which implement
`pkt_drop = cfg_*_pkt_mask[pkt_type]`. A host that follows the description
writes 0xFFFF to "enable" and silences the monitors.

## Fix (not applied here)

Mirror rapids BUG-008: reword the three descriptions to "bit[type] = 1 masks
(drops) that packet type, at the monitor and again at the monbus group; reset =
all masked", keep the 0xFFFF reset, regenerate through
`bin/peakrdl_generate.py`, and reword the HAS register map. No RTL change.
