# BUG-001: STREAM formal proofs read a hand-copied gaxi_fifo_sync, not the RTL
> **Was `TASK-080` until 2026-09-24.** Renamed when this area adopted per-lane ID sequences. Older references, commit messages and handbook notes use the old ID.

**Priority:** Medium. Nothing fails, which is the problem: a proof about a
copy says nothing about the module that ships.

**Status:** CLOSED 2026-09-24. Opened 2026-09-11, found while retiring the same defect class from
the repo-root `formal/` areas (amba/cdc/common), where thirty tasks proved
hand-copied forks. This area was out of that job's scope.

- `formal/stream/stream_latency_bridge/gaxi_fifo_sync_formal.sv` is a
  hand-copied `gaxi_fifo_sync`: 155 lines against the real module's
  250, with 133 lines differing. It is read by:
  `stream_latency_bridge`.
- `formal/stream/_includes/monitor_pkg_formal.sv` is a package stub that
  no task reads -- an orphan.

Why forks exist, and why they are unnecessary: yosys's own SystemVerilog
frontend cannot read these modules (package-typed ports, casts, unpacked
array ports), so someone copied and simplified them. sv2v can read the real
RTL, and every one of the thirty repo-root forks turned out to be
convertible. See `vault/handbook/dv/formal.md` ("PROVING A FORK IS WORSE THAN
NO PROOF") for the method and the traps: judge a `[files]` entry by its
SOURCE, not its local name, and expect stale properties to surface once the
real module is read -- two of the repo-root conversions exposed properties
written for the fork, and one exposed a real AXI protocol bug (amba
TASK-094).

**Done when:** no `formal/stream` task reads a `*_formal.sv` copy of an rtl/
module, each converted task proves against the real RTL, and the two fork
files are deleted. **All three satisfied.**

## Done 2026-09-24

`stream_latency_bridge` now flattens the real `rtl/amba/gaxi/gaxi_fifo_sync.sv`
with sv2v and proves against it. Both fork files are deleted:
`gaxi_fifo_sync_formal.sv` and the orphan `_includes/monitor_pkg_formal.sv`
(0 references, and no `.sby` or Makefile under `formal/stream` puts
`_includes` on an include path, so it was unreachable even implicitly).

**Why the fork existed, measured rather than assumed.** yosys fails at
`gaxi_fifo_sync.sv:27` -- `parameter fifo_mem_t MEM_STYLE = FIFO_AUTO` -- with
"Non-constant width range on parameter decl", but ONLY in derive mode, once
`stream_latency_bridge` instantiates it as `.MEM_STYLE(FIFO_AUTO)`. Reading the
module standalone returns RC=0.

**That nearly cost a bad fix.** My first experiment read the module alone, got
RC=0, and I concluded the fork was unnecessary and a `[files]` repoint would be
the whole fix. Wrong: a standalone read never elaborates a parameterised
instance, so it cannot see the thing the fork exists to dodge. An out-of-tree
rehearsal caught it before any tracked file changed. Test in the configuration
the thing actually runs in, not the one that is convenient to test.

sv2v resolves the package-typed parameter, so the handbook's prescription holds
exactly: flatten the real module ([[formal]], "PROVING A FORK IS WORSE THAN NO
PROOF").

**Verified against a pre-conversion baseline**, so the result is attributable:

| | status | steps | process time |
|---|---|---|---|
| baseline (fork) | `PASS 0 454` | 20/20 | 7:34 |
| converted (real RTL) | `PASS 0 304` | 20/20 | 5:04 |

Same verdict at the same depth, 150s faster. No fork-specific property surfaced
-- the harness's `occupancy`, `f_count`, `F_MAX`, `dbg_r_out_valid` are all
harness-local, and only `occupancy`/`dbg_r_out_valid` cross into the DUT as
ports that exist in the real module. (The handbook notes two of thirty
repo-root conversions did expose stale properties, and one a real AXI bug.)

**Provenance proven, not inferred.** The flattened `gaxi_fifo_sync` body is 146
lines -- fewer than the fork's 155 -- which looks alarming until you flatten the
fork the same way: the two flats differ by 67 lines, and only the real one
carries the `MEM_STYLE` generate branches. sv2v drops comments and unselected
branches, so flattened line counts are not comparable to source ones.

**This unit had no Makefile at all**; it was driven entirely by its `.sby`
staging sources with `../../../` paths. It now has one on the
`formal/stream/scheduler` pattern, and the `.sby` reduces to flat + harness with
`prove: depth 20` / `cover: depth 40` preserved.

**Noted, deliberately NOT done:** `_includes/dummy_pkgs.sv` and
`_includes/stream_imports.svh` also have zero references -- the same orphan
class as the stub removed here, but outside this bug's stated scope. Left for a
decision rather than deleted unasked.
