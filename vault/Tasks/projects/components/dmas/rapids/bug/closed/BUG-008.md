# BUG-008: the monitor PKT_MASK registers default to "drop everything", documented as "1 = enable"

**Priority:** High -- with the register defaults no packet from any monitor-lite
ever reached the monbus group, and the register description told the host the
opposite of what the hardware does.
**Status:** CLOSED 2026-09-27 (closing note at the end); was OPEN 2026-09-27.
Found while wiring the AXIS monitor-lites (rapids TASK-015): the first top-level
test that looked for a monitor packet at the group's capture master found none.

## Mechanism

`rapids_mon_regs.rdl` declared `DAXMON_PKT_MASK`, `RDMON_PKT_MASK` and
`WRMON_PKT_MASK` as "Packet type mask [15:0] - 1=enable, 0=disable" with a
default of `16'hFFFF`. Both consumers treat a set bit as DROP:

- `axi_monitor_lite` / `axis_monitor_lite`: `type_allowed(t) = !cfg_*_pkt_mask[t]`
- `monbus_group_core`: `pkt_drop = cfg_*_pkt_mask[pkt_type]`

So at reset the descriptor-read monitor-lite dropped every event class at the
source, and the group dropped again whatever the SRC `RDMON`/`WRMON`/`DAXMON`
masks covered. A host following the register description ("1 = enable") would
write 0xFFFF and silence the monitors while believing it had enabled them.

The per-event `*_MASK1/2/3` fields were already documented and defaulted as
suppress masks (error/timeout/thresh/addr 0xFF, completion/perf/debug 0x00) and
match the group; only the packet-type mask had the inverted description.

## Fix

`rapids_mon_regs.rdl`: the three fields now read "Packet type DROP mask -
bit[type] = 1 drops that packet type, at the monitor-lite and again at the
monbus group" and default to `16'h0000`. Regenerated through
`bin/peakrdl_generate.py` (`rapids_regs.rdl` for the RTL and docs,
`rapids_regmap.rdl --regmap` for `rtl/rapids_regmap.py`); the only RTL change is
the six reset values (`SRC`/`SNK` x three masks). The HAS register map and the
MAS config-block page state the polarity. `rapids_core_beats_tb` drives the
descriptor mask as 0 instead of 0xFFFF.

## Verification

`test_rapids_beats_top_axis_mon` (rapids TASK-015) enables the two AXIS
monitor-lites over APB, writes `PKT_MASK = 0`, and decodes one Completion record
per monitor from the capture master's trace; it also passes with the mask left
at its new default. STREAM's register file was not checked here -- it uses the
same group and should be audited for the same inversion.
