# TASK-003: Author the BCH MAS v0.1 and signal-contract kmaps

**Status:** open 2026-10-03
**Priority:** P3 — the next planning artifact after the HAS, the same posture
reed-solomon TASK-003 will have
**Owner:** TBD

The BCH HAS v0.1 describes the target architecture; the MAS carries it one
level down to per-block signal tables, cycle behavior, FSM policy, and
signal-contract references. This task authors the MAS tree and the generator
for the pre-RTL signal-contract workbook.

## Scope

- `projects/components/ecc-ip/bch/docs/bch_mas/` tree mirroring the HAS
  structure: index, styles, front matter, overview (methodology + block
  inventory), FUB pages for encoder core, syndrome unit, key-equation solver,
  Chien search, and decoder core integration, core-signals interface page, and
  signal-contracts methodology page.
- `projects/components/ecc-ip/bch/docs/gen_bch_signal_contracts_kmaps.py`
  modeled on the stream component's generator, importing the shared
  `bin/kmaps/` machinery.
- `projects/components/ecc-ip/bch/docs/bch_signal_contracts.xlsx` generated by
  the script above.

## Definition of done

- Every MAS block page carries a signal-level interface table and an explicit
  FSM-policy statement.
- Every open item is marked **TBD** and tied to a PRD decision ID; no
  invented numbers or gate counts.
- The kmap workbook contains 5-8 contracts for the key control/qualifier
  signals, with term lists, invariants, decision tables, `depends_only_on`
  arguments, and pre-RTL `NOT CHECKED` verdicts.
- `python3 projects/components/ecc-ip/bch/docs/gen_bch_signal_contracts_kmaps.py`
  exits zero and produces the `.xlsx`.
- `python3 bin/check_task_ids.py --area projects/components/ecc-ip/bch/task` passes.
