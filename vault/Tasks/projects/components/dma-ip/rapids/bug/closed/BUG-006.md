# BUG-006: the descriptor engine fetches any APB-kicked address, in range or not

**Priority:** High -- the HAS lists "address outside configured range" as error
0x10 and the MAS FSM has a CHECK_RANGE state between the kick and the fetch;
software relies on the two ranges to fence descriptor fetches.
**Status:** CLOSED 2026-09-27 (closing note at the end); was OPEN 2026-09-27.
Found by the TASK-003 scrub: `test_address_range_validation` in
`dv/tbclasses/descriptor_engine_tb.py` used to submit only in-range addresses,
so the reject path had never been exercised. Its new out-of-range step failed
on every profile of the 2026-09-27 full regression.

## Symptom

`test_descriptor_engine_beats_address_range_validation[*]` at FULL, every
profile:

```
Out-of-range address 0x30100 did not raise descriptor_error
```

with ranges configured 0x10000-0x1FFFF and 0x20000-0x2FFFF. The engine issued
the AR for 0x30100, took the response, and delivered the descriptor.

## Mechanism

`w_addr_range_valid` was computed from `r_axi_read_addr` and never consumed.
The only range check that reached logic was `w_next_addr_valid`, applied to a
chained `next_descriptor_ptr` (`w_chain_eligible`). A commented-out
`w_validation_passed = w_addr_range_valid && w_axi_response_ok` shows the
initial-address check was designed and then left unwired; the `RD_ISSUE_ADDR`
transition went straight to `RD_WAIT_DATA` on `ar_ready`.

## Fix

`rtl/fub_beats/descriptor_engine_beats.sv`:

- `RD_ISSUE_ADDR`: `!w_addr_range_valid` now steps to `RD_ERROR` before the
  `ar_valid && ar_ready` transition; `RD_ERROR` already sets `descriptor_error`,
  drops the active flags and returns to `RD_IDLE` with nothing pushed.
- `ar_valid` is gated by `w_addr_range_valid` in `RD_ISSUE_ADDR`, so no AR goes
  out for a refused address; `r_axi_read_active` is set on the real handshake
  (`ar_valid && ar_ready`) rather than on `ar_ready` alone.

Formal flat regenerated (`formal/rapids/descriptor_engine_beats`). Chaining
behaviour is unchanged: the next-pointer check was already in place.

## STREAM

`projects/components/dma-ip/stream/rtl/fub/descriptor_engine.sv` carries the same
dead wire (`w_addr_range_valid` computed at line 619, `w_validation_passed`
commented out) and the STREAM MAS makes the same "Address Range Validation"
claim. Filed and fixed the same day as stream BUG-014.

## Closing note (2026-09-27)

`test_descriptor_engine_beats` at FULL passes with the reject step in place;
the full rapids regression is rerun after the fix (see TASK-003 / TASK-010
records for the run).
