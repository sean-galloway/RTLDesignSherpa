# BUG-013: axi_write_engine runs two AWs per channel at PIPELINE=0

**Priority:** High -- same defect as rapids BUG-005; `axi_write_engine.sv` and
`axi_write_engine_beats.sv` are one file modulo the header.
**Status:** CLOSED 2026-09-27 (closing note at the end); was OPEN 2026-09-27. Found through the rapids copy's first direct test.

A stale round-robin grant (`r_arb_request` is a cycle behind) loaded the next
AW keyed on `sched_wr_valid` alone, so a lone channel issued its second AW the
cycle after the first at PIPELINE=0, and the single-bit `r_outstanding_limit`
then cleared on the first B while the second burst was open. Fix identical to
rapids BUG-005: AW load and stale-grant release keyed on the live
`w_arb_request[grant]`. Write-up and evidence: rapids BUG-005.
