# BUG-011: sram_controller_unit's drain accounting refuses to count a write the FIFO accepted

**Priority:** Medium for STREAM (latent -- needs a consumer draining slower than the fill
so a channel fills to the last slot), High where it surfaced (rapids BUG-003).
**Status:** CLOSED 2026-09-27 -- fixed in the shared unit, both areas' suites green.

`stream_drain_ctrl` inside `sram_controller_unit.sv` is an ACCOUNTING counter -- FIFO
writes minus drain reservations -- but it is built as a virtual FIFO of depth `SD` whose
own `wr_ready` gates `w_write`. The unit feeds it the real FIFO's write handshake
(`axi_rd_sram_valid && axi_rd_sram_ready`). `stream_alloc_ctrl` bounds written minus
DRAINED to `SD`, and `stream_latency_bridge` holds up to 5 beats outside the FIFO, so
written minus RESERVED legitimately reaches `SD` while the FIFO still has room. At that
boundary the FIFO takes the write, the counter is "full" and does not count it, and the
beat can never be reserved: it sits in the channel until reset.

Found on rapids' source path after it adopted this unit (`bdf4e0dff`): 1024 beats written,
`wr_ptr` at 1020, `data_available == 0` with one beat in the FIFO and three in the bridge.
STREAM's own datapath drains at line rate and rarely fills a channel, which is why its
suites never saw it; the isolation suites (`test_sram_controller*`) cannot see it either,
because the trigger is the alloc/bridge interplay at exactly `SD` occupancy.

**Fix:** the drain accounting is instantiated with `DEPTH(2 * SD)` -- `stream_drain_ctrl`'s
read pointer relies on power-of-2 wrap, so a margin, not `SD + 5` -- and the wider
`data_available` is truncated back to the unit's `[ADDR_WIDTH:0]` port (the value is
bounded by `SD` + bridge occupancy). `run-sram_controller*-full-parallel`: 38/38; STREAM full `run-all-full-parallel`: 856/859 (3 pre-existing skips).

The formal harnesses that flatten this unit (`formal/stream/sram_controller_unit`,
`formal/stream/sram_controller`, `formal/rapids/{src,snk}_sram_controller_beats`) are
regenerated and re-proved alongside; see the rapids record for the numbers.
