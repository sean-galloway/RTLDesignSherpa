# BUG-015: a kick that ends in RD_ERROR wedges the channel's APB path through channel reset

**Priority:** High -- channel reset is the documented recovery from a
descriptor error and it did not recover the APB path.
**Status:** CLOSED 2026-09-27 (closing note at the end); was OPEN 2026-09-27.
Found by the recovery half of the BUG-014 reject test: after the refused kick
and a channel reset, an in-range kick timed out waiting for `apb_ready`.

## Mechanism

`r_apb_ip` is set when the APB skid accepts a kick and cleared only on the
falling edge of `channel_idle` (STREAM's engine keys on the falling edge where
the rapids port keys on the rising one; both depend on the scheduler leaving
idle). A kick that ends in `RD_ERROR` never delivers a descriptor, the
scheduler never moves, the edge never comes, and `apb_ready` -- which needs
`!r_apb_ip` -- stays low. Channel reset did not clear the flag. Same defect as
rapids BUG-007.

## Fix

`rtl/fub/descriptor_engine.sv`: `r_channel_reset_active` clears `r_apb_ip`.
The `address_range_reject` test type recovers through a channel reset and
requires the next in-range kick to deliver. Formal flat regenerated.
