# BUG-003: stream_core's formal dependency list has rotted behind the monitor rework

> **Was `TASK-091` until 2026-09-24.** Renamed when this area adopted per-lane ID sequences. Older references, commit messages and handbook notes use the old ID.

**Status:** CLOSED 2026-09-24. `stream_core` proves at depth 15.

## The verdict

```
PASS 0 20399        15 of 15 steps (0..14)
DONE (PASS, rc=0)   elapsed 5:43:36 clock / 5:39:59 process
engine_0 (smtbmc z3) returned pass -- did not produce any traces
```

**What that PASS actually covers, because "PASS" alone would be misread.**
`formal_stream_core.sv` asserts **10** properties, and they are shallow:
eight `ap_reset_*` (system_idle, scheduler_idle, descriptor_engine_idle,
desc/rd arvalid, wr awvalid, wr wvalid, sched_error, mon_valid) plus
`ap_system_idle_implies_sched`. They hold under **6 assumes**, which pin
`cfg_axi_rd_xfer_beats` and `cfg_axi_wr_xfer_beats` to 1..4.

The 5 `cover` properties belong to the `cover` task (depth 25) and were **NOT
run**. So this closes "stream_core cannot be proved at all"; it does not mean
stream_core is verified. Deepening the property set is separate work.

## What was wrong, and what fixed it

The entry's original diagnosis was right: the `axi_monitor_reporter_*` split and
the monitor rework never propagated into this Makefile, so the DEPS chain was
missing modules one at a time. The fix was the one this entry asked for --
generate the closure from the filelist instead of hand-listing it. Done in
`271143b55`: the Makefile now runs `bin/flatten_filelist.py` over
`rtl/filelists/macro/stream_core.f`, and the seven hand-written monitor `sed`
rules are gone (verified in HEAD: 1 `flatten_filelist` reference, 0 `MON_PREP`).

## The second "blocker" -- and a correction to my own reasoning

`formal/FORMAL_TODO.md` recorded a second blocker as a *"Yosys flatten name
collision (2x axi4_master_rd)"*. I disproved that phrasing early -- the flat has
**1** `module axi4_master_rd` definition and **0** duplicate module names among
45 modules -- and concluded it had been a misdiagnosis.

**That conclusion was itself half wrong.** `formal/stream/stream_core/DEFERRED.md`
records the actual error, and it is not about duplicate module names:

```
ERROR: Found multiple drivers for \fub_rd_axi_aruser.
```

Two `axi4_master_rd` instances flattened into one wire with two drivers -- the
desc monitor tying `.fub_axi_aruser(1'b0)` while the data path tied
`fub_rd_axi_aruser`. FORMAL_TODO's wording was a loose paraphrase of a real
defect, and I refuted the paraphrase rather than the claim. Worth recording
because the neat version ("it was never real") is the one that would have been
remembered.

**What removed it, established from the artifacts rather than assumed:**
`stream_core.sv:1514` records the upgrade from a bare `axi4_master_rd` to
`axi4_master_rd_mon`, `:1507` carries a scar comment naming the real
multi-driver on `fub_axi_ruser`, and `:1511` gives the wire a single explicit
driver, `assign fub_rd_axi_aruser = UW'(fub_rd_axi_arid)`. The flat that proved
confirms it: `fub_rd_axi_aruser` is declared once (`:10881`), assigned exactly
once (`:11531`), consumed once (`:11605`). So an RTL restructure fixed it, and
the deferral outlived its cause.

## Tractability

`FORMAL_TODO` filed stream_core under **"Deferred (not tractable for BMC)"**.
It is tractable: 5h40m of process time to depth 15 on smtbmc/z3. The cost is
wildly uneven per step -- step 9 took 100 minutes, step 11 about a second, and
steps 12-14 roughly three hours between them -- so a short timeout reads as
"intractable" when it is only "slow". Both FORMAL_TODO rows corrected.

## A side finding, corroborated by a second tool

The prove's base log emits four `Resizing cell port` warnings:
`cfg_{wreng,rdeng,desc}_mon_timeout_mask` 8 -> 16 bits and
`cfg_sched_timeout_cycles` 16 -> 32. These are the same width mismatches
Verilator reports as 52 `WIDTHEXPAND` warnings on the monitor config path, noted
while closing [[TASK-002]]. Two independent tools now agree; still unfixed, and
still outside this bug's scope.
