# BUG-008: dwidth converter split-fold assumes in-order B across IDs -- CLOSED (fixed + DV regression, 2026-10-04)

> Migrated 2026-09-27 from `vault/Tasks/projects/components/utility-ip/converters/open.md` as **CONV-010** (tooling TOOL-001). The flat page did not record a lane; this item was placed by hand. Body preserved as written -- only the H1 and this line are new.

*Renumbered from CONV-001 on 2026-09-14. It was filed in `vault/Tasks/amba/`,
where CONV-001 was free; moving it to the area it belongs to put it against the
converters' own CONV-001 (a resolved dnsize LAST fault). The area is the ID
namespace, so the clash only appeared once the task was in the right place.*

**Priority:** P3 — latent, needs an interleaving downstream AND a master using
multiple write IDs through the converter at once. No shipped integration in
this repo does both today.
**Status:** closed 2026-10-04. Fixed in `axi4_dwidth_converter_wr.sv` and
`axi4_dwidth_converter_rd.sv`; regression tests added; Verilator lint clean for
touched files.

**What the RTL did.** `axi4_dwidth_converter_wr.sv` split one oversized slave
burst into several master bursts and recorded each in a single FIFO:

    logic [9:0]         splitq_mem [SPLITQ_DEPTH];
    logic [SPLITQ_AW:0] splitq_wptr, splitq_rptr_w, splitq_rptr_b;
    assign split_b_final = splitq_mem[splitq_rptr_b[SPLITQ_AW-1:0]][9];

The B fold popped one entry per downstream response and forwarded a B to the slave
only on the record marked final.

**Why it was only sometimes correct.** All pieces of one split burst carry the
AWID of the burst they came from, and AXI4 guarantees same-ID B responses come
back in order — so within one ID the FIFO fold was exact. Across IDs AXI4 places
no such ordering requirement. If two slave bursts with different IDs were both
split and the downstream interleaved their responses, the FIFO could not tell them
apart and decremented the wrong record: one burst's B was released early, the
other's never completed.

**Fix applied.**
- Write converter (`axi4_dwidth_converter_wr.sv`): removed the B read pointer from
the split queue and replaced the single B-fold register with a per-burst CAM.
Each outstanding slave burst gets a CAM entry keyed by AWID, holding the number
of master bursts it was split into and the worst BRESP seen so far. Every master
B response searches the CAM for the oldest matching AWID, decrements that burst's
counter, folds the response, and forwards only when the counter reaches zero.
Same-ID bursts stay in order; cross-ID bursts can complete in any order.
- Read converter (`axi4_dwidth_converter_rd.sv`): removed the global
`r_rid_held`/`r_ruser_held` registers that were updated on every master R
handshake. RID/RUSER are now packed into the R sideband and carried through
`axi_data_upsize` (downsize path) and `axi_data_dnsize` (upsize path), so each
slave R beat reports its own originating ID even when responses overtake each
other through the data-width primitive.
- Shared primitive (`axi_data_upsize.sv`): added `SB_BROADCAST_WIDTH` so the
low-order sideband bits (RID+RUSER) can be held/broadcast while the high bits
(RRESP) are still folded by severity.

**Verification.**
- `test_axi4_dwidth_converter_wr_ooo_b`: dedicated cocotb/pytest regression that
issues concurrent split write bursts on distinct AWIDs and returns their B
responses cross-ID out of order.
- `test_axi4_dwidth_converter_rd_ooo_r`: dedicated cocotb/pytest regression that
stalls the slave R channel, piles ID1's converted wide beats in the skid buffer,
then sends an ID0 narrow beat before releasing ready, checking that every slave
R beat carries the correct RID. Isolated in its own cocotb module
(`test_axi4_dwidth_converter_rd_ooo_r.py`) to avoid BFM callback state pollution
when cocotb runs multiple tests in one module.
- Full `test_axi4_dwidth_converter_wr.py` + `test_axi4_dwidth_converter_rd.py` +
`test_axi4_dwidth_converter_rd_ooo_r.py` suite: 26/26 configurations passed at
gate/func/full levels.
- Verilator lint: clean for the three touched RTL files. Verible lint: no new
findings in touched files (pre-existing findings remain in unrelated files).
- Formal: `sby prove` and `sby cover` pass for both
`axi4_dwidth_converter_wr` and `axi4_dwidth_converter_rd` (BMC depth 25, z3).
The read formal wrapper was missing shadow-model registers and a master-R-valid
protocol constraint; both were added so the proof is now sound.
