# BUG-009: dwidth read converter does not support beat-level R interleaving across IDs — CLOSED (fixed + DV regressions, 2026-10-04)

**Priority:** P2 (bumped from P3 2026-10-04 on Sean's ruling: the house BFM
environment MUST be capable of interleaving responses). Latent against every
shipped integration (pumice's return ring is AR-ordered; bridge slave adapters
return R per-ID in order, burst-atomic; APB/AXI-Lite downstreams are in-order
across IDs) — but any bench that places this converter in front of an
interleave-capable BFM drove it into silent data corruption.
**Status:** closed 2026-10-04. Fixed in `axi4_dwidth_converter_rd.sv` with a
per-ID R reassembly layer; regression tests added; lint clean; formal proof
regenerated.

**Contract that IS supported (verified 2026-10-04).** The read converter
(`axi4_dwidth_converter_rd.sv`) regenerates the slave-side RID/RUSER from the
most recent master R beat (`r_rid_held`/`r_ruser_held`). Under AXI4's per-ID
ordering, this is EXACT whenever each master R burst returns burst-atomic
(all its beats contiguous): the held value at any group-complete or skid
capture is that burst's own ID, and the data primitives back-pressure the
master R stream while a converted beat is stalled, so a later burst's beats
cannot slip in mid-group. Whole R bursts completing out of order ACROSS IDs
is fine under this contract.

**What breaks it.** If a downstream slave interleaves R beats at BEAT level
across ARIDs (permitted by AXI4), the `axi_data_*` primitives merge beats of
different IDs into one wide word — corrupted data, and `r_rid_held` reports
the most recent beat's ID. No warning; silent misattribution.

**Candidate fix shape.** Per-ID R assembly before the data primitives: demux
master R beats by RID into per-ID buffers, reframe per slave AR split record,
and emit slave R in AR order per ID. This is a redesign of the R path, not a
fold tweak — fund it only if a real integration needs beat-level interleave.

**Test that would catch it.** Two ARIDs whose downstream R beats interleave
one-beat-per-ID round-robin; assert slave-side data and RID attribution per
beat.

## CLOSED 2026-10-04

**Fix.** `axi4_dwidth_converter_rd.sv` gains a per-ID R reassembly layer
between `m_axi` R and the data primitives (which are UNCHANGED and still see
one contiguous burst at a time):

- AR-side records extended with per-master-burst beat counts (the arsplit
  queue previously carried only a final flag); upsize records carry the
  wide-beat count, narrow length, and start lane (replacing the burst-length
  FIFO).
- Master R beats are demuxed by RID into per-ID queues backed by a shared
  beat pool (`RASM_MAX_OUTSTANDING * RASM_DEPTH` entries, default 16*272,
  singly-linked free list). A burst is assembled when its record's beat
  count is met with RLAST on the last beat.
- Deadlock-freedom by reservation: at most one unassembled master burst per
  ID — master AR issue for an ID is throttled until its previous burst is
  fully fed to the primitive, so a burst's buffer space is always reserved.
  Throughput tradeoff (documented in the MAS): same-ID read chains serialize
  through reassembly; cross-ID traffic stays concurrent. If the reservation
  is ever relaxed, `bridge_cam` mode 2 (ALLOW_DUPLICATES=1) is the
  designated tracking-structure upgrade.
- A round-robin scheduler feeds assembled bursts contiguously into
  `axi_data_upsize`/`axi_data_dnsize`; for downsize the scheduler holds an ID
  until its slave burst's converted output drains, so wide-word accumulation
  never mixes splits. `int_rid`/`int_ruser` come from the tracked feed/output
  IDs plus a first-beat RUSER capture (exact per beat).
- Protocol violations (R with no AR record, more beats than promised,
  premature RLAST) are flagged by `SIMULATION`-guarded `$error` checks and
  consumed without deadlock. No SVA (house rule).

**Review fixes applied during integration (parent review, 2026-10-04):**
- RUSER capture condition off-by-one (captured beat #2; single-beat bursts
  kept the previous burst's value) — now first-beat (`count == 0`).
- rd formal Makefile DEPS were missing the axi_data primitives (the flat
  never contained them; `prep` failed) — DEPS fixed, flat regenerated.
- `rasm_rec_valid` had two always-block drivers (AR generate blocks + the
  reassembly scheduler); simulation tolerated it, yosys/smt2 rejects it
  ("multiple drivers") — ownership consolidated into the reassembly block,
  which now sets valid on the AR push strobe while the AR blocks keep the
  payload fields.
- Formal proof practicality: the full-size pool (16*272 beats) explodes yosys
  prep into register arrays; the 256-beat sizing `$error` is waived under
  `FORMAL` and the wrapper bounds the pool to RASM_DEPTH=8 /
  RASM_MAX_OUTSTANDING=2 (safe under its arlen<=3 assumption). The proof
  covers the reassembly logic; sizing is a configuration invariant.
