# BUG-001: every integration example in rtl/amba/CLAUDE.md named ports the modules do not have

**Priority:** P2
**Status:** closed 2026-09-25 -- all 10 examples and 6 quick-reference rows corrected against the RTL
**Owner:** --

An agent following any integration example in `rtl/amba/CLAUDE.md` wrote RTL
that cannot elaborate. This is the same defect DOCREV found and fixed in
`rtl/common/CLAUDE.md` ("its whole Common Integration Patterns section
documented modules that do not exist as described"); `rtl/amba` never got the
same pass.

## Reproduction

Copy Pattern 4 into a design and run `verilator --lint-only`. Every pin is
rejected: the example connects `.i_clk/.i_rst_n/.i_valid/.i_data/.o_ready`,
while `rtl/amba/gaxi/gaxi_fifo_sync.sv` declares `axi_aclk, axi_aresetn,
wr_valid, wr_ready, wr_data, rd_ready, count, rd_valid, rd_data`. Zero overlap.

## What was wrong

| site | defect |
|---|---|
| 5 x `gaxi_fifo_sync` | `.i_clk/.i_rst_n/.i_valid/.i_data/.o_ready/.o_data/.o_valid/.i_ready` -- none exist |
| `arbiter_rr_monbus` | **module does not exist**, 7 invented ports. The real aggregator is `monbus_arbiter`, which takes UNPACKED arrays per client and `monitor_packet_t`, not a packed `[127:0]` bus |
| Pattern 1 `axi4_master_rd_mon` | bare `.axi_ar*`/`.axi_r*`; the module is INLINE with `fub_axi_*` upstream and `m_axi_*` downstream, not a passive snooper |
| Pattern 2 `apb4_monitor` | wired raw APB (`pclk/presetn/paddr/psel/...`); it watches the CONVERTED `cmd_*`/`rsp_*` interface in the aclk domain. Also passed `cfg_compl_enable`, an AXI4 port this module does not have |
| Pattern 3 `axis4_master` | **wrong premise.** Not a monitor -- 0 monbus ports. No module under `rtl/amba/axis4/` emits monbus at all |
| Pattern 5 `axi4_master_rd_mon_cg` | `.cg_enable`; real is `cfg_cg_enable` + `cfg_cg_idle_count`, outputs `cg_gating`/`cg_idle` |
| table rows | `axi4_master_rd_mon` claimed ID_WIDTH/ADDR_WIDTH/DATA_WIDTH (real: `AXI_*`); `axil4_master_rd_mon` ADDR_WIDTH/DATA_WIDTH (real: `AXIL_*`); both `*_cg` rows claimed a `CG_ENABLE` parameter that does not exist |
| AXIS table | `axis4_master.sv` and `axis4_slave.sv` listed as "AXIS transmit/receive monitoring" with 0 monbus ports between them |

Pattern 3 was built faithfully on that false table row, which is why the table
had to be fixed with it -- correcting only the example would have left the
source of the error in place.

## The fix

Examples rewritten from known-good instantiations in the tree rather than
hand-assembled from port lists: the `gaxi_fifo_sync` shape is copied from
`apb4_monitor.sv`'s own `monitor_fifo`, including the `REGISTERED(0)` mux-read
trap (flop mode re-emits the popped entry -- amba TASK-086,
[[valid-ready-contracts]]). The AXIS section now says plainly that there is no
AXIS monbus monitor and points at `axis_bus_meter`, which is real and consumed
(instantiated in `rapids_char_harness.sv`, filelist
`rtl/amba/filelists/axis_bus_meter.f`, test `val/amba/test_axis_bus_meter.py`).

## What made this findable, and what nearly hid it

A checker that compares every `.port(...)` in the file against the module's
real port list. It only became trustworthy after three rounds of fixing the
CHECKER, and each failure mode would have produced a false report:

1. it resolved modules to `formal/` harnesses, so "real ports" were a proof
   wrapper's;
2. it missed continued declarations (`input wire clk,` / `rst_n,`) and so
   called `rtl/common`'s correct `.rst_n(...)` bogus -- 3 false defects;
3. it missed unpacked-array ports (`monbus_valid_in [CLIENTS],`), taking
   `CLIENTS` as the port name -- 8 more false defects.

So the checker now carries four assertion gates (plain, continued, unpacked,
and a known port-count) and refuses to report unless they pass. Validate the
checker against ports you have read with your own eyes before believing a
verdict from it -- a passing run of a blind checker is indistinguishable from a
clean file.
