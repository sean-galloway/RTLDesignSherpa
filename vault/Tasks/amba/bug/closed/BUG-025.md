# BUG-025: axi_split_combi's next-boundary arithmetic overflows in the top alignment window

> Migrated 2026-09-27 from `vault/Tasks/amba/closed.md` as **TASK-095** (tooling TOOL-001). The flat page did not record a lane; this item was placed by hand. Body preserved as written -- only the H1 and this line are new.

**Priority:** P3. A latent hazard the design DOCUMENTS as out of scope, found
while proving TASK-094. Not a regression, and no in-tree RTL instantiates the
splitter today.

**Status:** CLOSED 2026-09-16 -- fixed, and verified red-before-green on seven
independent gates.

`axi_split_combi` computes the next boundary in AW bits:

```systemverilog
assign next_boundary_addr = (current_addr | AW'(alignment_mask)) + AW'(1);
assign crosses_boundary   = (transaction_end_addr >= next_boundary_addr);
```

For any transaction in the FINAL alignment window of the address space that
`+1` overflows to zero, and `crosses_boundary` then compares against 0 and
reads TRUE. A transaction that crosses nothing is split anyway.

**Counterexample** (from the rd splitter proof, AW=16, mask 0xFFF): a
ONE-BEAT read at `0xFFFC`. `next_boundary_addr` = `(0xFFFC | 0xFFF) + 1` =
`0x10000` -> `0x0000`; `0xFFFF >= 0x0000` is true; `split_required` asserts;
`split_len` = 0 and `remaining_len_after_split` = 0, so the FSM issues a
first split of one beat AND a second of one beat. Two downstream beats for a
one-beat original -- the extra beat arrives upstream with nothing owed, which
is how the rd splitter proof first surfaced it.

Note the transaction itself does NOT wrap here: `0xFFFC + 4` ends exactly at
the top of the space. The BOUNDARY arithmetic overflows before the
transaction does, so "the transaction does not wrap" is not a sufficient
guard -- the first constraint tried in the harness was exactly that, and the
solver walked straight back in.

**Why it is filed rather than fixed.** The module header states it as a
design assumption: "Assumption 4: No Address Wraparound ... No wraparound
handling in boundary crossing logic ... Real systems never allow this
condition due to memory layout and software design." Changing boundary math
the design explicitly excludes is a separate decision from TASK-094, which
was about acceptance timing. `formal/amba/axi_master_rd_splitter` now assumes
the next boundary exists inside the address space, which holds the proof to
the design's stated operating range and is commented as such.

**Fixed exactly that way 2026-09-16** (b29d5290e). The boundary is carried in
`AW+1` bits, so the comparison is against the real value instead of a wrapped
zero. `bytes_to_boundary` is untouched and still correct -- the modular
subtraction yields the true byte count either way -- and the `AW`-wide port
still truncates a `2**AW` boundary to 0, which is harmless because both
splitters read it only on the split path and `split_required` is false in that
window. The two in-RTL boundary assertions were restated against the widened
signal. The TRANSACTION-wraparound assumption is unchanged and still asserted;
only the BOUNDARY arithmetic moved.

**Evidence, red before green in every case.**

| gate | before | after |
|---|---|---|
| `axi_split_combi` formal | FAIL `ap_no_cross_no_split` + `ap_beats_conserved` | prove **PASS**, cover **PASS** |
| `axi_master_rd_splitter` formal | FAIL `ap_rvalid_after_ar` | prove **PASS**, cover **PASS** |
| `axi_master_wr_splitter` formal | **PASS -- blind to it**, see [[TASK-097]] | prove **PASS**, cover **PASS** |
| `val/amba/test_axi_split_combi` | aborted at `0xFFFFFFFC` | **16 passed**, 3 directed top-window cases |
| four sibling splitter suites | -- | **8 passed** |
| verilator lint | 2 warnings | 2 warnings, unchanged |
| flat files | -- | all three regenerated from the fixed RTL |

The three directed simulation cases assert `split_required` stays FALSE in the
top window and are new; the TB's Python reference model was already correct
there (Python ints do not wrap), so the suite passed only because
`generate_safe_random_address` never reached the top half. `is_address_safe` was
relaxed to its documented meaning -- no transaction wraparound -- rather than
"lower half of the space".

**The containment assume is gone, and it cost runtime.** The rd splitter proof
had carried `assume ((fub_araddr | AW'(alignment_mask)) != {AW{1'b1}})` since
the TASK-094 fix, which is what made the overflow invisible to it. Removing it
puts the top window back in scope. Measured: prove **PASS in 7930 s** to full
depth 25 (steps 0..24, no traces), against the 6175 s recorded in
`formal/FORMAL_TODO.md` -- about **29% slower**, and that delta IS the assume.
That file is generated by `bin/formal_status.py` over all 297 tasks, so its
number refreshes on the next sweep rather than by hand here.

**Follow-on:** [[TASK-097]], closed the same day -- the write splitter's proof
passed against the BROKEN RTL, so `axi_split_combi`'s arithmetic was guarded on
the read side only. It now carries `ap_split_beats_conserved` plus a reachability
cover, verified in both directions.
