# BUG-009: math_bf16_exp2 returns 0 for every x >= 256 (overflow read as underflow)

**Priority:** P2
**Status:** FIXED 2026-10-20 (fix-RTL; library regression + formal re-proof)
**Owner:** TBD

## Defect

`rtl/math/math_bf16_exp2.sv` saturates the integer part of a large input
with `w_int_part = w_sign ? -9'sd256 : 9'sd256;` (two sites: the
`w_exp >= 135` branch and the `default` arm of the exponent case).
`w_int_part` is `logic signed [8:0]`, range -256..255, so `9'sd256` wraps
to -256. Every positive x with |x| >= 256 -- 2^256, 2^1000, max-finite
0x7F7F -- took the UNDERFLOW path and returned +0 with `ow_is_zero` set,
where the correct result is +inf. 2^128 (exp 134) took the other branch and
was right, which is the only overflow the library test exercised.

Found by the alu-infer exp2 row's library cross-check (alu-infer act test:
`x=0x7F7F: got 0x0000, expected 0x7F80`).

## Fix

`+9'sd255` at both sites: 127 + 255 still clears the overflow threshold.
After the fix every x >= 256 (0x4380, 0x4400, 0x4700, 0x5000, 0x7F00,
0x7F7F) returns 0x7F80 with `ow_is_inf`; negative large x still returns 0.

## Regression

`BF16Exp2TB.run_comprehensive_tests` gains 2^256, 2^1000, 2^-256, 2^-1000,
2^max-finite and 2^-max-finite. Against the pre-fix RTL the three positive
cases FAIL (`got=0x0000, exp=0x7F80`); with the fix
`make run-math_bf16_exp2-func` passes. `formal/common/math_bf16_exp2`
prove + cover PASS on the regenerated canonical flat, whose diff is exactly
the two constants.
