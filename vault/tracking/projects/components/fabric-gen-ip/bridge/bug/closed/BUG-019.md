# BUG-019: unaligned INCR bursts keep their start misalignment past the first beat in several bridge converters

**Date:** 2026-10-19
**Priority:** P1
**Severity:** HIGH
**Status:** CLOSED 2026-10-22 (fixed; verified in sim and on the board)
**Owner:** unassigned
**Found by:** the Genesys 2 bridge stress model (`projects/fpga-systems/Genesys2/bridge-stress/`), then a sweep of every converter the bridge generator instantiates
**Affects:** every bridge path that passes an AXI4 INCR burst with an unaligned start through a width, protocol or burst-length converter

## Summary

AXI A3.4.1: only the first beat of an INCR burst may be unaligned. Every
later beat starts on the size grid, so beat N > 0 is at
`aligned(start) + N * bytes`, and a split piece N > 0 is at
`aligned(start) + N * piece_bytes`. Several converters instead step from the
unaligned start (`addr + bytes`), so every beat or piece after the first
carries the misalignment. The slave sees a partial-looking beat where the
master sent a full one: strobes outside the beat on writes, missing lanes on
reads, and, at the end of a burst, a last access that runs past the master's
last byte (and can cross 4 KB).

This is the bridge-level umbrella: one rule, broken in several converter
blocks in different ways. bridge BUG-018 (width-converted FIXED / WRAP /
narrow bursts) overlaps it on the downsize path only and stays open for its
non-alignment cases.

## Where

| Block | Bridge path | Defect | Status |
|---|---|---|---|
| `axi4_to_axi3_{wr,rd}` | AXI4 master -> AXI3 slave, bursts > 16 beats | chunk N started at `prev + 16 beats` | FIXED, converters BUG-011 (`404a7dd1c`), board-verified |
| `axi4_dwidth_converter_{rd,wr}`, downsize | wide master -> narrow slave | no start-lane accounting: issues `RATIO * (len+1)` narrow beats from the unaligned start, so a start in an upper narrow lane runs one narrow beat late (the upsize side has this accounting, converters TASK-001); the > 256-beat split also steps `r_split_addr + 256 * M_STRB_WIDTH` from the unaligned start | first part MEASURED (BUG-018 table, 128 -> 64, sim + board); split step by inspection |
| `axi4_to_axil4_{rd,wr}` (so `axi4_to_axil5_*` and `axi4_to_wb4`, which wrap them) | AXI4 master -> AXI-Lite / AXI5-Lite / WB4 slave | INCR next address = `r_ax_addr + (1 << size)`, not aligned first | by inspection |
| `axi_gen_addr` (`rtl/amba/shared`) via `axi4_to_apb4_convert` (so `axi4_to_apb4_shim`, `axi4_to_apb5_shim`) | AXI4 master -> APB / APB5 slave | INCR `next_addr = curr_addr + increment`; only WRAP aligns | by inspection; `axi_gen_addr` is also used by the `sdpram_slave_*` blocks outside the bridge |

## Correct

Every converter steps INCR from the aligned start:
`(addr & ~(bytes - 1)) + bytes` per beat, `aligned(start) + n * piece` per
split piece (the BUG-011 fix). The downsize converter also subtracts the
start's narrow lane from the narrow-beat count, as the upsize side does.

## Reproduction

The stress model has the stimulus: the `narrow` and `chaos` profiles set `unaligned = 1`, so INCR
bursts start off the size grid, and the slave checks `S_WSTRB` / `S_ADDR` against
the beat grid.

```
cd projects/fpga-systems/Genesys2/bridge-stress/dv/tests
BS_PROFILES=narrow BS_FULL_AXI=1 python3 -m pytest test_bs_harness.py -q
```

`bridge_bs_axi4` covers the downsize row; the AXI-Lite and APB rows need a
DUT with those slave ports (bridge TASK-019 phase 3). Without
`--full-axi` the host keeps converted paths aligned (`bstress.path_caps`),
which hides all of these.

## Fix plan

1. One regression per block, red first: an unaligned INCR whose second beat
   (or second piece) address is checked, as BUG-011 added for
   `axi4_to_axi3`.
2. `axi_gen_addr`: align INCR as WRAP already does. It is shared, so run
   the `rtl/amba` sdpram tests too.
3. `axi4_to_axil4_{rd,wr}`: same one-line step.
4. Downsize: start-lane accounting plus the aligned split step.
5. Board: `narrow` and `chaos` (the profiles with unaligned starts) with `--full-axi` on a DUT that has every
   converter on a path.

Handbook: `vault/handbook/design/axi-burst-splitting.md` states the rule.

## Resolution

Every converter in the table now steps INCR from the aligned start
(`(addr & ~(bytes-1)) + bytes`):
- `axi_gen_addr` aligns INCR the way it already aligned WRAP. Its TB gained
  `test_incr_unaligned_start_realigns`.
- `axi4_to_axil4_{rd,wr}` take the same aligned step.
- The dwidth downsize does start-lane accounting: it issues
  `wide_beats*RATIO - start_lane` narrow beats, and the >256-beat split
  steps from the aligned start. This landed in the BUG-018 rewrite.
- `axi4_to_axi3` was already fixed as converters BUG-011.

The stress builds carry APB (17), AXI-Lite (5), AXI3 and AXI5 slave ports,
so the `narrow` and `chaos` profiles (unaligned starts) reached every row on
the board.

Board, 2026-10-22, every stress build on bitstreams with the BUG-018/019/023/024 RTL (timing met on all five), every profile x seeds 1-3, 4000 bursts per master direction, no path limits (`bstress.path_caps` returns `{}`): axi4 30/30, axi3 30/30, axi5 30/30, xil 30/30, xmix 30/30 = 150/150 (`projects/fpga-systems/Genesys2/bridge-stress/reports/board/bridge_bs_*_20261022_*.csv`).
