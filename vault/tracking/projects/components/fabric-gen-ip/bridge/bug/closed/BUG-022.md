# BUG-022: AXI5 sideband on a rate-buffered width-converted path has two drivers

**Date:** 2026-10-20
**Priority:** P2
**Severity:** MEDIUM
**Status:** CLOSED 2026-10-20 (fixed; verified in sim, synthesis and on the board)
**Owner:** unassigned
**Found by:** Vivado synthesis of the Genesys 2 bridge stress model's mixed build (`projects/fpga-systems/Genesys2/bridge-stress/build-xmix`, `bridge_bs_xmix`): `CRITICAL WARNING [Synth 8-6859] multi-driven net` on every master adapter
**Affects:** a master adapter of a fabric that carries AXI5 sideband (any port with nsaid / trace / mpam / mecid / unique), on a width-converted path that has a write rate buffer (`bridge_wr_rate_buf`, an upsized path into a shared slave)

## Summary

Sideband never crosses the dwidth converter, so the generator ties every
sideband field of the path's output structs to '0 (`_sb_conv_tie_lines`).
With a write rate buffer on the path, the buffer drives that output AW / W
struct WHOLE (`.m_aw`, `.m_w`), so each sideband field had two drivers: the
buffer and the tie. Synthesis keeps one; which one is not defined.

## Also in build-axi5

`bridge_bs_axi5` has the same shape (AXI5 masters upsized into shared slaves):
its board-green bitstream's synthesis log carries 103 of these warnings, and it
passed 27/27 and three soaks regardless -- Vivado happened to keep the tie
('0), which is the intended value. Its regenerated adapters carry the fix;
the rebuild is to be re-run on the board.

## Why nothing caught it

No bridge fixture has AXI5 sideband on a rate-buffered converted path (the
regenerated suite was byte-identical after the fix). The FPGA lint flow waives
MULTIDRIVEN (`make/fpga_lint.mk`).

## Fix

On a rate-buffered path the AW / W ties go on the buffer's INPUT structs
(`<path>_rb_aw`, `<path>_rb_w`), which the buffer carries through; AR keeps its
tie on the output (no buffer on reads). Generator test
`test_rate_buffer_sideband_ties_have_one_driver` (fails on the old generator,
lints the generated bridge with MULTIDRIVEN live); bridge_bs_xmix: 60
MULTIDRIVEN before, 0 after; synthesis 0 multi-driven nets; build-xmix board
30/30.
