# BUG-025: bridge_2x2_lite_req concurrent AXI4-Lite write times out at SEED=65563

**Date:** 2026-10-21
**Priority:** P2
**Severity:** MEDIUM
**Status:** OPEN (reproduction only; not root-caused)
**Owner:** unassigned
**Found by:** the bridge component func regression (2026-10-21), on the BUG-018/023/024 tree
**Affects:** `bridge_2x2_lite_req` (AXI4-Lite request-sideband fixture), two masters writing at once

## Summary

`test_bridge_2x2_lite_req_concurrent[gate]` fails deterministically at
`SEED=65563`: `write m1 0x0000901C: AXIL4 write timeout after 1001 cycles`.
Other seeds pass (two random reruns did). It is not a regression of the
2026-10-21 work: the same seed fails on a `git archive HEAD` tree (before
the converter, BUG-023 and BUG-024 changes) with both RDS-DV 1.2.8 and
1.2.9.

Not yet known: whether the write is lost (a hang) or only slower than the
TB's 1001-cycle limit. Correct is either the write completing, or a limit
derived from the fixture's worst-case latency with the reason written down.

## Reproduction

```
cd projects/components/fabric-gen-ip/bridge/dv/tests
SEED=65563 python3 -m pytest -q -p no:rerunfailures \
  "test_bridge_2x2_lite_req_sideband.py::test_bridge_2x2_lite_req_concurrent[gate]"
```
