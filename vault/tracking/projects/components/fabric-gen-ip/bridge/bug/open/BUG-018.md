# BUG-018: width-converted paths emit illegal AXI for FIXED, WRAP, narrow and unaligned bursts

**Date:** 2026-10-19
**Priority:** P1
**Severity:** HIGH
**Status:** OPEN
**Owner:** unassigned
**Found by:** the Genesys 2 bridge stress model (`projects/fpga-systems/Genesys2/bridge-stress/`), in simulation, before any board run
**Affects:** every master-to-slave path whose data widths differ: `axi4_dwidth_converter_{rd,wr}` inside the generated adapters

## Summary

A bridge master port accepts any legal AXI4 burst, and on a path with no
width conversion the bridge carries all of them: the stress model's `bursts`
profile (FIXED / INCR / WRAP, every length) passes clean on the same-width
paths of `bridge_bs_axi4`. On a width-converted path it does not. The
converters' documented contract is full-width INCR (converters MAS 2.6:
"size is the master's own full width, not a shift of ARSIZE"; FIXED/WRAP
"keep the wide-aligned requirement (asserted in simulation)"), but nothing at
the bridge's master port restricts traffic to that contract, so a legal
master burst becomes an illegal one at the slave.

Correct: either the bridge converts these bursts legally, or the generator
refuses / documents a master port that may issue them onto a converted path.
Silently emitting illegal AXI is the defect.

## Measured (`bridge_bs_axi4`, gate budget, slave-side ERR_S_PROTO / data checks)

| Master burst | Path | What the slave received |
|---|---|---|
| WRAP, 2 beats x 8 B | 64 -> 128 (upsize) | WRAP, AxLEN 0 (1 beat: not a legal WRAP length) |
| WRAP, 16 beats x 16 B | 128 -> 64 (downsize) | WRAP, 32 beats (> 16) |
| FIXED, 12 beats x 16 B | 128 -> 64 | FIXED, AxLEN 23 (> 16), one narrow address repeated |
| INCR, AxSIZE below the bus | 128 -> 64, 32 -> 64 | rewritten to full width: wrong beat count, RLAST / data errors at the master |
| INCR, unaligned start | 128 -> 64 | issued one narrow lane late: crosses 4 KB; first lane wrong |

Write paths show the same shapes plus `ERR_S_WSTRB` (strobes on bytes outside
the beat) and `ERR_S_WDATA`.

## Reproduction

```
cd projects/fpga-systems/Genesys2/bridge-stress/dv/tests
BS_PROFILES=narrow BS_FULL_AXI=1 python3 -m pytest test_bs_harness.py -q
```

or on the board: `python3 bin/run_stress.py --profiles bursts narrow --full-axi`.
Without `--full-axi` the host restricts converted paths to aligned full-width
INCR (`bstress.path_caps`) and every profile passes; that restriction is the
workaround, not the fix.

## Silicon

Reproduced on the Genesys 2 (`build-axi4`, 2026-10-19,
`reports/board/bridge_bs_axi4_20261019_102327.csv`): `--full-axi` `bursts` and
`narrow`, seed 1, 4000 bursts per master direction, fail with the same
signatures as the simulation -- S_PROTO at every slave fed by a converted
path, RD_DATA at every master, S_WSTRB / S_WDATA on writes. The fabric does
not hang: every burst retires. With the path limits on, all nine profiles x
three seeds pass on the same bitstream (27/27, `..._102024.csv`).

## Notes

- Same-width paths are clean under every profile, including FIXED, WRAP,
  narrow, unaligned and random strobes.
- The upsize side's mid-word INCR handling (converters MAS 2.6) does work for
  full-width bursts; it is the narrow-size and FIXED/WRAP cases that break.
