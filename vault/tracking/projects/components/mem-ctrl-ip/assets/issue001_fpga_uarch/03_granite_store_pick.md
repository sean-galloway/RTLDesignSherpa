## 2. Structure-by-structure detail

### 2.1 Bank queues (`gaxi_age_fifo_sync` x16) -- the dominant cost

What it is. Each (direction, bank) has a `gaxi_age_fifo_sync` with DATA_WIDTH=QDW=4 ({same-row-as-previous, slot[2:0]}), DEPTH=QDF=8, PEEK=2, AGE_WIDTH=4 (store `:1107-1157`). The entry memory is `logic [DW-1:0] mem [D]` with no reset, synchronous write and **asynchronous mux read** (FIFO `:277-285`) -> LUTRAM-inferrable (and it is: 12 LUTRAM per queue in the report). The two peek ports read `mem[w_addr]` at rd_addr+1, +2 with a non-power-of-two wrap compare (FIFO `:330-339`) -> 3 independent async read ports on an 8x4 array. Per-slot `r_valid[8]`, `r_age[8]`, `r_age_thresh[8]` are async-reset flops (FIFO `:290-320`); at HAS_AGE=0 `wr_data_age` is constant 0 (store `:1098-1104`) and the age/thresh columns fold to constants, leaving 8 valid flops + 2 x (3+1)-bit pointers + full + empty = **18 FF per queue, exactly what the report shows** (`utilization_hier.txt:122-147`).

Access pattern per cycle. 1 push per direction (store `:668-673,976-981`), at most 1 pop in the whole pool (one command per cycle, header `:60-62`), 3 reads per queue every cycle (head + 2 peeks feed the record build at `:1300-1340`). The pop is decoded by comparing the committed slot with each of the 8 live heads (`:670-671`), not by `r_wr_bank[slot]` -- a designer's timing choice that puts 8 x 3-bit compares on the fire cone, then into 8 `rd_ready`s, then `counter_bin_next`, then `fifo_control`'s full/empty/count (FIFO `:225-258`, `rtl/common/fifo_control.sv`, `counter_bin.sv:178-191`). The board's worst paths end exactly there (`timing_worst.txt:21-30`: CSR tRTP -> ... -> `g_q[4].u_wq/fifo_control_inst/wr_full_reg`). POP_REG=1 (store `:189-198`) was built to register this pop; it is OFF on the board (`granite_pkg.sv:94`).

Why ASIC-shaped. Sixteen complete FIFO controllers for queues that are, collectively, never more than 8 entries deep per direction and are popped once per cycle in total. Each `fifo_control` recomputes full/empty/almost-full/count from the NEXT pointers every cycle (REGISTERED=0) -- that is 16 copies of pointer-subtract logic, where the store already keeps a registered per-bank occupancy `r_wq_cnt`/`r_rq_cnt` (`:458,865,790-792,1005-1007`) **specifically because the FIFO's own count would close a loop** (comment `:454-457`). So the count is duplicated: once in flops the store trusts, once in each FIFO's control the store does not read. The attribution in the hierarchy report (`fifo_control_inst` of one 8-deep FIFO at 134 LUT, `:127`) is flatten=rebuilt drift from the parent, but the total (1,770 LUT across the 16 instances + drain queue) is real and is 80% of the store.

FPGA-native alternative (concrete).
- Per direction: one LUTRAM `q_mem[8 banks][8 entries]` of QDW bits (RAM64M: 64 deep x 4 bits, 1 write + up to 3 async reads, in 4 LUT6 of one SLICEM). With {sp, slot} = 4 bits that is **one RAM64M per direction**.
- Per bank: a 3-entry output shift register `{head, pk1, pk2}` (12 FF) + 3-bit RAM write pointer + 3-bit RAM read pointer + the existing count. Push: if count < 3 after this cycle's pop, land directly in the shift register at position count (bypass); else write RAM at wr_ptr. Pop: head <= pk1, pk1 <= pk2, pk2 <= RAM[rd_ptr] (if count > 3), rd_ptr++. One RAM read per cycle for the ONE bank that pops; one RAM write per direction per cycle.
- `has0/has1/has2` = count > 0/1/2 from the registered count (no valid flops); `rd_valid`, `wr_ready` = count != QD. The pop no longer touches any pointer arithmetic that the fire cone must settle: it ends in the shift register's load and a 3-bit increment.
- Estimate: 16 x (12 + 6) FF = 288 FF (same as now), ~16 x 25 LUT = 400 LUT of shift/bypass/ptr logic, 2-10 RAM64M. **Saves ~1,300 LUT** against the measured 1,770 and removes the FIFO controllers from the critical cone, making POP_REG unnecessary.
- The records (`:1300-1340`) read `s0/s1/s2, sp1/sp2, has0/has1/has2` -- exactly the three shift-register positions; no record logic changes.

What it gives up. The per-entry age column (#6). With HAS_AGE=0 on the board, nothing. If age is wanted, store a timestamp in the entry instead (section 2.6).

### 2.2 Merge CAM (MERGE_EN)

What it is. Write side: `w_awp_am[i]`/`w_awp_ie[i]` compare the incoming AW against all 8 slots' {bank,row,col} (26 bits) and id (8 bits) with forwarding for the slot being allocated this cycle (`:517-528`), registered into `r_awh_am/ie` (`:569-577`), then `w_mg_match` ANDs them with 6 per-slot state bits and last-match-wins (`:497-504`). Read side: `w_rdmg_match[i]` compares the LIVE `ar_push_*` inputs against all 8 read slots (34 bits each) plus the held AR, **combinationally into `ar_merge_o`/`ar_merge_ticket_o`** (`:919-937`), which the plane uses in the same handshake for the ring's shadow allocation and which `w_ar_direct` reads back (`:905`). Bookkeeping: `r_wr_cmt/mgv/mgfill/mgid/yng` (`:364-371`), the second-B queue (`:407-415,1443-1447`), FO_DEPTH doubled to 16 (`:311`), strobe RMW (`:852`), the merge-target mask in the record build (`:1328,1336`), and the candidate-coordinate decode `w_wr_is_cand`/`w_rd_is_cand` (`:1421-1427`: 8 x 3-bit bank compare x 2) that exists so the merge can skip the pick's candidate without a store->pick->store round trip.

Size. WR CAM: 8 x 34 XNOR-and = ~8 x 12 LUT6 ~ 100 LUT + 16 FF. RD CAM: ~100 LUT, zero registers between the AXI AR input and a store output. Plus ~150 FF / ~60 LUT for the B queue, ~40 FF for the FO doubling, 64 FF `r_wr_mgid`, 64 FF `r_rd_id`, 128 FF `r_strb` forced to flops. Owner's A/B: store wrapper 1,206 -> 635 LUT and 1,672 -> 1,226 FF (merge on -> off), ring 1,512 -> 665 LUT.

Is it load-bearing? From the owner's own measurement (memory note), merge-off lost only the open_page half-width cell (-20% at 4 threads) and was within 2% on 171/180 cells. Mechanically: on this board one AXI 64-bit beat is one DRAM BL4 x16 burst (DRAM_BEAT_WIDTH=64, BL_SHIFT=0, BURST_WORDS=2 -> a slot is 2 beats = one 128-bit DRAM access); the only merge opportunity is a host that splits one DRAM access into two narrower AXI writes to the same {bank,row,col} back to back (the lo/hi pair the header describes, `:484-489`). That is a host/bridge artifact, not a DDR2 bandwidth lever: at 100 MHz host / 300-400 MT/s DRAM the store is never the bottleneck for full-width writes. **Recommendation: STORE_MERGE_EN=0 for the FPGA SKU, and combine narrow pairs upstream (in the narrow->wide converter / generator) if the half-width cell matters.** If an in-store form is wanted, the 1-entry "last admitted write" compare: one {bank,row,col,id,slot} register per direction, loaded at admit, compared against the held AW (`r_awh_*` are already registers). It catches exactly the consecutive lo/hi case, `r_wr_yng` is unnecessary (the last write is the youngest of its id by construction), and the AR side needs no CAM at all if read merging is dropped (the ring's shadow machinery, ~850 LUT, goes with it).

### 2.3 Slot descriptor arrays

WR: `r_wr_valid/fdone/bank/row/col/id/last/bcnt` + merge bits (`:354-371`); RD: `r_rd_valid/bank/row/col/ticket/id` (`:859-864`). Written at admit via `w_wr_free_slot`/`w_rd_free_slot` (8-wide find-first, `:422-431,871-880`). Readers per cycle: (i) record `hit`: `r_wr_row[s0]` for each of 8 banks (`:1333`) and `r_rd_row[s0]` (`:1367`) = 16 x 8:1 x 13-bit muxes + 16 x 13-bit compares; (ii) drain: `r_wr_last/id/mgv/mgid[w_dq_rd_slot]` (`:697-700`); (iii) ticket: `r_rd_ticket[rd_issue_slot_i]` (`:952`); (iv) pick payload via the flat `wr_sch_row_o/..` (`:1286-1292`) -> `w_wr_slot_row[w_sel_slot]` in the pick (`:1153-1154`), 2 directions x 8:1 x 23 bits; (v) the CAM reads all 8 rows/cols/ids (merge only); (vi) `w_wr_is_cand`/`w_rd_is_cand` compare all 8 banks (`:1421-1427`).

All arrays live inside the async-reset `ALWAYS_FF_RST` block (`:686-841, 985-1011`); the payload fields are not themselves reset, but Vivado will not infer a RAM from an array written inside a process that also has an asynchronous reset branch. Result: ~620 FF of register file and ~300 LUT of 8:1 muxes.

FPGA alternative. Two routes, which can be combined:
- (A) Payload LUTRAM by slot: `{row,col}` and `{id|ticket}` in RAM32M-class distributed RAM in their own reset-free `always_ff`, written at admit. Read ports needed with merge gone: WR row x8 (hit) + 1 (payload) + 1 (drain id/last) = 10; split across 2-3 RAM copies (4 read ports each). ~60-80 LUTRAM replaces ~600 FF and the mux LUTs. Bank is still needed per slot only for `is_cand` (`:1421-1427`), which itself exists only for the merge.
- (B) Put `row` into the bank-queue entry ({sp, slot, row} = 17 bits, RAM64M x5 per direction). The head register of each bank then holds its row, so `hit` is `bank_row_active_i[b] && (head.row == orow)` with no slot indirection, and `r_wq_tail_row`/`r_rq_tail_row` (208 FF, `:459,866`) become the tail entry's own row. The pick's `cmd_row_o` can come from the record if the record carries row (13 x 32 = 416 FF; the struct already has a row field, `mc_common_pkg.sv:149`); col stays a by-slot lookup (10 x 8 x 2 in one RAM32M each).

Either removes the 16 x 8:1 x 13-bit hit muxes; (B) also removes the row half of the pick's payload mux.

### 2.4 Write-beat BRAM, strobes, skid

`r_mem` is a reset-free 16 x 64-bit array with `ram_style="block"`, byte-enable writes `if (!w_fill_mg || wd_strb_i[b])` (`:843-849`) and a synchronous read into `r_rd_q[63:0]` (`:848`) -> one RAMB36 (97% empty). `r_strb` (`:379,851-853`) is the byte-OR RMW described above -> **128 flops + a 16:1 read mux + 16-way write decode**, purely because of the merge's `|`. The entry store packs `{strb,data}` into one 72-bit word (`mc_xddr2_entry_store.sv:209-211,528-534`) and has no strobe flops. `r_rd_q` is driven by two different `always_ff` blocks for different bit ranges (`:848,853`) -- legal but a lint/tool-portability smell. The 2-deep skid + credits (`:381-392,655-660,803-810`) is the right pattern for a BRAM's 1-cycle read latency; keep it.

### 2.5 Head records and candidate flags

`w_wr_head/head2`, `w_rd_head/head2` are built from the three queue positions and registered (`:1293-1419`); `r_wr_h1/h2/r_rd_h1/h2` are per-slot one-hots registered at the same edge (`:1393-1419`) so the pick can name a commit as (bank, record 1|2) and the store resolves it (`:1421-1427`). This is a clean registered contract and the right FPGA shape. Two notes: (i) HEAD_BYPASS puts the AR push handshake (`w_ar_fire`, which includes `rt_alloc_ready_i`, the free-slot find-first, the cap check and `!ar_merge_o` -- `:900-906`) into the record register's D cone (`:1379-1386`); with the RD CAM gone that cone shortens by the 34-bit compares. (ii) `mc_head_rec_t` carries 32 constant-zero bits per record (`mc_common_pkg.sv:149-151`) plus a 5-bit-oversized slot; Vivado prunes them, but the struct width makes every consumer's elaboration misleading.

### 2.6 Pool age (HAS_AGE)

Off on the board. If turned on: every valid entry in all 16 queues decrements on every commit/issue (FIFO `:303-318`), the store tracks a tail age per queue (`:1053-1067`) and reduces 16 of them through a 4-level max tree (`:1068-1096`), and a per-head 8-bit wait counter gates the flag (`:1248-1270`). Estimate from structure: 16 x 8 x (4-bit decrement + thresh) ~ 16 x 40 LUT + 16 x 40 FF, tree ~60-90 LUT, tail ages 64 FF + 16 decrementers, wait counters 128 FF + 16 x 8-bit compares -> ~700-900 LUT / ~800 FF. The FPGA shape is the one `mc_xddr2_entry_store` already uses per slot (`:183,198,615-620`): a free-running stamp written with the entry, and `now - head.stamp >= thresh` computed only on the registered heads (16 subtract-compares). "Oldest in pool" is then min over 16 head stamps (~60 LUT) if the exact class is still wanted. The all-entries-decrement form is an ASIC register-file idiom.

### 2.7 Find-first / priority structures

`w_wr_free_slot`/`w_rd_free_slot` (8-wide lowest-free, `:422-431,871-880`), `w_mg_found/slot` (8-wide, `:497-504`), `w_rfsh_pre_found` (8-wide, pick `:861-869`) are small (~8 LUT each) -- keep. The pick's three 16-wide `rr_onehot` (`:357-365`) are the only ones worth attention (section 5).

## 4. ISSUE-001 (same-id B order): cheapest FPGA shape

The mechanism as read: a write's B is emitted at the drain of its slot's last beat (`:1437-1447`), the drain order is commit order (`u_wr_drain_q`, `:605-615`), and the pick commits across banks with no id term (`mc_bank_pick.sv:430-500,779-795`). The B then lands in `mc_wr_intake`'s 4-deep B FIFO (`fub/mc_wr_intake.sv:449-459`). ISSUE-001 (`vault/tracking/.../issue/open/ISSUE-001.md`) lists "hold the younger same-id write out of the commit set" as one fix -- that is the ASIC CAM answer again (an 8 x 8-bit id compare per direction, `r_awh_ie` already exists at `:473`) and, worse, it serializes all writes of one id across banks: a one-id master loses bank parallelism entirely.

Cheapest correct FPGA shape -- **release Bs in AW order, decoupled from slot lifetime**:
- At admit (`w_aw_fire`, `:541-543`): push `{id}` into an 8-entry B-order queue (8 x 8-bit, one RAM32M = 4 LUT, or reuse the fill-order FIFO's slot order which IS AW order, `:436-449`), and record `pos[slot] <= bq_wr_ptr` (8 x 3 FF).
- Carry `pos` (3 bits) instead of `id` (8 bits) through the fetch/skid tags (`:390,385`) -- saves 10 FF.
- At the drain's last beat (`w_done1`, `:1437`): `drained[pos] <= 1` (8 FF).
- Output: while `drained[bq_rd_ptr]`, emit `wr_done_valid_o` with `id = bq[bq_rd_ptr]`, clear the bit, advance. One B per cycle, strictly AW order (stronger than per-id, so no id compare anywhere).
- Cost: ~4 LUTRAM + ~40 FF + ~25 LUT. The slot is still freed at fetch-last as today (`:794-800`), so DRAM-side scheduling freedom is untouched. The only cost is B latency when an older write is starved behind page hits -- which the age class is meant to bound and which today is unbounded anyway (HAS_AGE=0).
- Note the merged second B (`:1443-1447`) would need a 2-B entry; with #2a it does not exist.

Also found in passing (not in this slice but where the store's B lands): `u_b_fifo`'s `wr_ready` is unconnected (`mc_wr_intake.sv:449-459`) and `wr_done_valid_i` has no ready, so a host holding `bready` low for more than 4 Bs drops Bs silently (`gaxi_fifo_sync` only writes on `wr_valid && wr_ready`, `rtl/amba/gaxi/gaxi_fifo_sync.sv:71`). Flagged; not evaluated further.

## 5. `mc_bank_pick`: what the 726 LUT are, and what could move

Stages (all from registers in, as the header says `:14-20`):
1. Candidate select: `w_cand[p] = r_shadow[p] ? rec2 : rec1` over 16 pairs x 7 live bits (`:331-345`) ~ 60-110 LUT.
2. Decode -> `r_req/r_cls` (`:430-500`): per pair ~9 terms incl. `w_hit[p^1]`, LA bits, DIR_OWNS term, refresh/tRFC block decodes (`:386-392,415-420`) ~ 150 LUT. Registered -- fine.
3. Request sets: `w_req_ok/col/col_dir/row/aged` with the 3:1 stale-mask mux at the root (`:656-676`) ~ 80 LUT; pending/any reductions (`:677-700`) ~ 30.
4. Arbiter: `w_below_mask` (16 x 4-bit compare vs `w_rotor_eff`, `:778`), **three** `rr_onehot` (each: and-masks + `f & (~f+1)` = a 16-bit carry chain, `:357-365,779-781`) ~ 150 LUT; 5-way 16-bit class select + source enum (`:782-795`) ~ 50; age tie-break ~ 30; two 16->4 priority encoders (`:813-817`) ~ 30; `w_pick_cls` 16:1 of `r_cls` (`:819`) ~ 10; `w_pick_onehot` 4-way 16-bit (`:821-827`) ~ 30; speculation (`:829-880`) ~ 30. **~330 LUT, about 45% of the module.**
5. Fire: `w_sel_cand = w_cand[w_win_pair]` 16:1 x 7 bits (`:1005`) ~ 40; class/timer checks (`:1033-1047`) ~ 25; hold/xdir (`:1078-1086`) ~ 15; override/refresh/maint (`:857-955`) ~ 90; payload `cmd_row/col` 2 x 8:1 x 23 bits (`:1153-1154`) ~ 115; op/AP encode ~ 20; direction next-state + idle (`:1206-1232`) ~ 30; hint ~ 15; counters (`tccd`, `rfc`) ~ 30.

Which reductions are over 8 banks x fields: `w_oth_req_any`, `w_rd/wr_col_any/_pend`, `w_cur_queued`, `w_row_pref_any` (`:677-700,752-756`) are all 8- or 16-wide OR trees over registered bits -- cheap. The expensive items are the one-hot ARITHMETIC (three carry chains), the four 16-bit stale-mask registers and their root mux, and the 16:1 struct mux in the fire cone.

What could be registered a cycle earlier. The decode already is. The fire stage must read live timers (JEDEC authority, `:43-52`), so `w_class_ok/w_timer_ok` cannot be pre-registered without losing a cycle of tCCD/turnaround accuracy. Two things CAN move without changing cycle behaviour:
- The payload mux (`:1153-1154`): `cmd_row_o/cmd_col_o` only need to be right in the fire cycle and they feed the DFI command FIFO's data input and `evt_row_o`; they are not on the fire-valid cone. With the row carried in the record (#3B) the 8:1 slot mux disappears for row.
- `w_pick_cls = r_cls[w_pick_pair]` (`:819`) is a 16:1 mux after the priority encoder; a one-hot AND-OR over `r_cls` with `w_pick_onehot` (already computed) is one level shorter.

Round-robin pointer with open-row preference, cheaper? The present scheme is already a rotor; the cost is that the pre-select (class alternation x direction x hint x xdir fall-through) is evaluated on three 16-wide candidate sets in parallel to keep the carry chain off the select (`:770-777` comment). A cheaper FPGA shape: register the (direction, class) decision one cycle earlier (both inputs -- `r_dir`, `r_last_was_row`, `r_batch_done`, `w_*_col_pend` -- are registers or near-registers), then run ONE 8-wide rotor over the banks of that (dir, class) set. 16->8 halves the rotor/encoder/mask widths and removes two of the three carry chains and the per-source one-hot muxing (~150-200 LUT), and the stale-mask vectors shrink to 8 bits. The risk is purely behavioural: the owner has a long measured history in this file (every term at `:560-676` cites a board cell), so this must be A/B'd on the proxy families, not argued. It is the lowest-priority item in this slice.

## 6. Correctness smells for an FPGA target

1. **Combinational input-to-output through the store** (`:919-937`): `ar_merge_o`/`ar_merge_ticket_o` are pure functions of `ar_push_*` and `ar_push_valid_i`; they go into the plane's ring allocation in the same handshake and `w_ar_direct` reads `!ar_merge_o` back (`:905`). `alloc_ready_o` in the ring is `!w_full && !w_tail_pinned` (`fub/mc_rd_return_ring.sv:152`) -- no loop found, but it is a 34-bit x 9 compare on an AXI-side path with zero registers; goes away with #2.
2. **Strobe RMW forces flops and a 16:1 mux** (`:851-853`) -- see 2.4; and `r_rd_q` driven from two `always_ff` blocks (`:848,853`).
3. **Slot payload arrays inside the async-reset process** (`:686-841,985-1011`) -- RAM inference impossible as written even though the payload is never reset. Reset style is async-assert via `ALWAYS_FF_RST_LO` (`rtl/common/includes/reset_defs.svh:55-64`); on 7-series, async-reset flops also cannot share a slice with the LUTRAM/SRL control set, which costs packing density around every such array.
4. **Duplicated occupancy state**: `r_wq_cnt`/`r_rq_cnt` (`:458,865`) and each FIFO's `count`/full/empty (`fifo_control`) describe the same queue; the store trusts only the former (`:454-457`). Two copies of state is a classic source of divergence under a missed corner (e.g. a push accepted by `w_aw_fire` while `w_wq_wr_ready[b]` is 0 is prevented only by `:542`). The shift-register form has one count.
5. **Fire cone ends in 16 FIFO controllers** (`:668-673` -> FIFO `rd_ready` -> `counter_bin_next` -> `fifo_control` full/empty), confirmed as the worst paths in `timing_worst.txt:21-30`. POP_REG=1 exists for this (`:189-198`) but trades a deeper FIFO and a logical-view mux (`:1171-1245`) for it; the shift-register form fixes it structurally.
6. **No backpressure on `wr_done`** into `mc_wr_intake`'s 4-deep B FIFO (`mc_wr_intake.sv:445-459`) -- potential silent B loss under a slow `bready` (outside this slice; flagged).
7. **HEAD_BYPASS cone** (`:1379-1386`): the AR handshake including `rt_alloc_ready_i` and `!ar_merge_o` sits in the record register's D input; it is registered (no loop) but it is the long AXI-side cone the admission hold was introduced to cut (`:92-106`).
8. Latch inference: none found -- every `always_comb` assigns defaults first (`:422-431,497-504,871-880,1013-1019,1099-1104,1295-1390,1395-1402,1421-1427,1449-1453`; pick `:331-345,857-869,…`). Same-cycle read-after-write on arrays: only the strobe RMW (`:852`) and the FO push-at-head+count (`:763-764`); the BRAM `r_mem` is written and read at provably different addresses (header `:22-27`, entry store `:22-27`).
9. `mc_head_rec_t` slot field is 8 bits for a 3-bit value and carries dead row/col (`mc_common_pkg.sv:149-151`) -- pruned by synthesis, but every `PTRW'(…slot)` truncation (`:1398-1401`, pick `:1003,1162-1165`) is a place a wider NUM_ENTRIES silently changes behaviour.

## 7. Keep as-is

- The registered per-bank record contract and the pick's "flops in, one command out" pipeline (store `:1404-1419`; pick header `:14-20`). This is the right boundary; nothing here should become combinational.
- The write-beat BRAM + 1-cycle read + 2-deep skid + credits (`:376-392,620-660,803-810,843-849`) -- the pumice-proven FPGA pattern. Only fold the strobes back into the word.
- The admission holds `r_awh_*`/`r_arh_*` (`:467-473,884-889`) and the registered `r_awh_am/ie` idea (compare at load, not per cycle) -- correct FPGA instinct; it just has nothing to compare against once the CAM is gone.
- The drain queue `u_wr_drain_q` (`:605-615`, 67 LUT / 10 FF, LUTRAM).
- `w_wq_pop` by head-compare instead of `r_wr_bank[slot]` (`:668-673`) -- stays valid in the shift-register form (the head is a register).
- The small find-firsts (`:422-431,871-880`).
- `mc_bank_pick`'s decode and fire stages; the arbiter restructure is optional and last.
- `mc_xddr2_entry_store` + `mc_bank_head_records` as the simulation reference backend only (STORE_BACKEND=0); never build it for the FPGA.

## 8. Suggested order of work

1. STORE_MERGE_EN=0 on the FPGA SKU (parameter only; owner already measured the perf delta) -> strobes into the 72-bit BRAM word, FO_DEPTH back to 8, RD CAM path gone. (~570 LUT store, ~850 LUT ring, ~450 FF.)
2. Replace the 16 `gaxi_age_fifo_sync` with per-direction RAM64M regions + 3-entry head shift registers; drop the duplicated FIFO control; POP_REG becomes moot. (~1,300 LUT; fixes the worst-path tail.)

4. AW-order B release queue for ISSUE-001 (~30 LUT, ~40 FF), with the `wr_done` backpressure gap closed at the same time.
5. If aged-first is ever wanted on FPGA: timestamp-at-head, not pool-age decrement.
6. Pick arbiter 16->8 restructure, A/B'd against the proxy families.
