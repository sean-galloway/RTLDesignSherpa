# BUG-004: mc_global_timers enforces a programmed window N as N+1 cycles -- tRRD 2 became 30 ns, one ACT per 3 cycles, and the row lane never fired

> Source: the owner asked why the granite SKU's `bank_interleave` preset sits at
> 238 MB/s on the board (memory-controllers MC-021, 2026-11-18). The DRAM trace
> of the proxy's bank_interleave run has 65,810 ACTs with a minimum ACT-to-ACT
> gap of 3 MC cycles (52k of the 65k gaps are exactly 3); the part's tRRD is
> 10 ns, one MC cycle at 100 MHz.

**Priority:** P2 -- every close-page stream whose column needs its own ACT ran
at one ACT per 3 cycles (30 ns) on both boards; the granite bank_interleave and
close_page interleaved cells sat at 238 MB/s where 400 is the two-cycle floor.

filed; the record is at the end.
**Owner:** TBD

**Related:** pumice TASK-034 (closed 2026-09-29: measured the N+1 on every

## What is wrong

A window programmed to N was enforced as N+1 MC cycles of command spacing: the
counter is loaded with N on the event and the registered gate is written as
`ok_nxt = event ? (t == 0) : (cnt <= 1)`, which opens the cycle AFTER the count
reaches zero. Two conservative steps then stack on tRRD:

| step | value at 100 MHz | why |
|---|---|---|
| JEDEC tRRD, MT47H64M16 x16 (2 KB page) | 10 ns = 2 CK = 1 MC cycle | JESD79-2F Table 42 |
| host `ddr2_timings_mc_cycles` | ceil((10 + 5) / 10) = **2** | the DFI phase margin: a lane ACT on phase 1 followed by a main ACT on the next cycle's phase 0 is 5 ns apart, so 2 is the floor while the row lane exists -- this step is right |
| `mc_global_timers` | **3** | N+1: one extra cycle on top of the distance the host already padded |

The host's docstring says "turnarounds are command-to-command distances, which
is what the RTL's global counters measure"; the RTL measured one more. TASK-034
saw exactly this, called the cost "much smaller than the tRTW cliff" and kept it;
the prize was never measured. Where it binds it is 3x on tRRD:

- In close page with the bank-interleave map every 8-byte column needs its own
  ACT, so the ACT rate is the throughput: 8 B / 30 ns = 267 MB/s ceiling, 238
  measured (the stale re-picks take the rest; MC-021 step 1).
- The DUAL_ISSUE row lane fires only beside a main-slot column, and in close
  page the column lands at ACT + tRCD = 2 cycles -- inside the 3-cycle tRRD
  exclusion. In the 64-cycle pick probe the lane held bank 3's ACT for all 64
  cycles with `w2_timer_ok` and `w_col_fire_now` perfectly anti-correlated;
  across the whole run ZERO of the 65,810 ACTs fired beside a column. The one
  feature built to make close-page interleave fast was structurally dead on
  every close-page preset.
- Open page never shows it (one ACT per row, and the pick does not consult the
  tCCD gate), which is why the SKU's 30 open-page cells were fine and the
  defect hid behind the model's `rank_ok_lag 1` knob, which MC-021 step 1
  introduced to match the RTL's 3-cycle spacing.

The same +1 sat on tFAW, tCCD, tWTR and tRTW. tCCD is not consulted by the
pick; tWTR and tRTW cost one cycle per direction turn (negligible at the SKU's
255-column turns); tFAW was not binding at a 3-cycle ACT spacing.

## The fix

**RTL** (`mc_global_timers.sv`): the readiness compares move one cycle earlier,
`ok_nxt = event ? (t <= 1) : (cnt <= 2)` for tRRD / tWTR / tRTW / tCCD, the tFAW
slot-free test `<= 1 -> <= 2` and its reload arm `t_faw == 0 -> t_faw <= 1`, and
the HAS_LS_PAIRS per-group outputs `== 0 -> <= 1`, and the `obs_*` debug flags
`!= 0 -> > 1` ("the window still blocks a command issued next cycle", so the
STALL_* attribution stays on the same cycle as the gate: the formal's Family 2
`a_obs_*` caught the first draft without it). N is now enforced as N, the
convention `mc_bank_timer` has had since MC-003. Fifteen compare constants; the
counters and the slot tournament are untouched. The golden copy under
`formal/mc_common/mc_global_timers/mc_global_timers_gold.sv` carries the same
ten so the MC-011 tournament-vs-serial equivalence stays meaningful.

**Formal** (`formal_global_timers.sv`): the four `a_*_bound_n1` asserts (which
pinned N+1 and failed, as written to) are gone; `c_trrd/tfaw/tccd/twtr/trtw_exact`
covers pin the gate opening at exactly N, so a revert to N+1 fails the cover
task while Family 1 still forbids opening before N. The tFAW-must-bind comment
is re-derived for the new 1-cycle minimum spacing. The Makefile's prove / cover
targets now depend on the gold flat the .sby names for every task (`make clean`
then `make prove` failed on the copy).

**Host** (`pumice_device.py`): `rtw_guard` 6 -> 7. tRTW is the one empirical
window (the PHY's read-return occupancy, measured clean at a programmed 20 under
N+1 = 21 cycles on DQ); the guard goes up by one so the enforced spacing the
board was measured at does not move. Every JEDEC-derived window keeps its count
and loses the extra cycle: at 100 MHz tRRD 2 cycles = 20 ns (15 ns across the
lane's phase) against 10; tFAW 5 cycles = 50 ns (45 across the phase) against
45; tCCD 1 cycle = 2 CK; tWTR 4 cycles = 8 CK against WL + BL/2 + tWTR = 6 CK.
Programmed 21, the tRTW CSR no longer reads as a JEDEC value -- it never did;
it is `t_rddata_en + BL/DFI_RATE + guard`.

**Model** (`granite_sku_controller.cpp`, `char_model.py`): `rank_ok_lag`
default 1 -> 0 (the lag WAS this N+1); `sku_rankok1` keeps the pre-fix RTL as a
variant; the `DDR2_GRANITE_SKU100` preset's nRTW 40 -> 42 CK for the host's 21.

**Docs**: pumice `pumice_csr.rdl` (ten field descriptions and the register
paragraph that stated the N+1 contract; regenerated through
`bin/peakrdl_generate.py`, docs only, regblock and regmaps byte-identical),
`pumice_mas/ch04_apb_config/03_runtime_overrides.md`, `pumice_has/ch06_integration/03_csr_map.md`;
the handbook note `global-windows-revalidate-at-issue.md`; TASK-034 annotated.
