# BUG-003: the board host's DDR2 ns table carries the 1 KB-page tRRD for a 2 KB-page part

> Source: found deriving the Ramulator 2 DDR2 device class constraint by
> constraint against JESD79-2F (memory-controllers MC-012, 2026-11-11).
> Verified against the spec text (`/mnt/data/github/dfi-specs/ddr2-lpddr2/jedec/DDR2_JESD79-2F.pdf`,
> Tables 42 and 43). No board or sim symptom: at both board clocks the wrong
> value and the right one round to the same cycle count.

**Priority:** P3 -- a spec-value error with no effect at the board clocks; one
MC cycle short at the DDR2-800 span configuration that only the pumice DV
matrix runs.
**Status:** open
**Owner:** TBD
**Where:** `projects/fpga-systems/NexysA7/mem-ctrl-ip-ddr2/build-perf/host/pumice_device.py:47-49`
(`DDR2_MT47H64M16_NS`), imported by
`projects/components/mem-ctrl-ip/research-ip/pumice-ddr2-lpddr2/dv/tbclasses/pumice_dram_configs.py`
as `PART_MT47H64M16` for every DDR2 config in the pumice / granite DV matrix,
and by `pumice_char.py` for the board.

## What is wrong

`DDR2_MT47H64M16_NS` has `tRRD=7.5`. JESD79-2F Tables 42/43 give tRRD by PAGE
SIZE: 7.5 ns for "1KB page size products", **10 ns for "2KB page size
products"**, at every speed grade. The Nexys A7 part is a x16 with 1K columns
(1024 x 16 bits = 2 KB page; `Geometry.page_bytes` in pumice_char.py says the
same), so its tRRD is 10 ns. Micron's MT47H64M16 datasheet says the same
(tRRD 10 ns for the x16). The table's other rows are right: tFAW 45 ns is the
2 KB-page value at DDR2-800 (Table 43), tWTR 7.5 ns is the part's rating-bin
value (Table 42 gives 10 ns only for the DDR2-400 bin, which is not this part).

## Effect

`ddr2_timings_mc_cycles` rounds ns up to CK, applies the JESD79-2 2 CK floor,
and converts to MC cycles with the phase margin:

| config | tCK | tRRD 7.5 ns | tRRD 10 ns |
|---|---|---|---|
| board_ddr2_300 (CK 150 MHz) | 6.667 ns | 2 CK | 2 CK -- same |
| ddr2_400_cl3_bl4 (CK 200 MHz) | 5.0 ns | 2 CK | 2 CK -- same |
| ddr2_800_cl6_bl4 (CK 400 MHz, span config) | 2.5 ns | 3 CK | 4 CK -- one MC cycle more |

So the board and every 75 / 100 MHz sim were never under-spaced; the
`ddr2_800_cl6_bl4` span configuration programs an ACT-to-ACT spacing one CK
below JEDEC.

## Expected

`tRRD=10.0` in `DDR2_MT47H64M16_NS`, with a comment naming the page-size rule,
and `test_pumice_device.py` pinning the three rows above. The Ramulator class
(`references/ramulator2/overlay/python/ramulator/dram/ddr2.py`) already carries
10 ns; `test_ddr2.py::test_board_part_presets_match_the_rtl_derivation_in_ck`
asserts both board points still resolve to 2 CK.

## Why it is filed, not fixed, here

The table is shared by the pumice DV matrix (`SPAN_CONFIGS` includes
`ddr2_800_cl6_bl4`) and the two board hosts; the change moves one span-config
timing, so it belongs to a pumice / granite regression pass, not to the
modelling task that found it.
