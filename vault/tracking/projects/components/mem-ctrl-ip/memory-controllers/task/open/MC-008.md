**Owner:** TBD

## Why

Both CAMs carry 16-bit free-running ages per entry with subtractors and age-exceed compares every cycle (row 10; 8-bit prescaled counters do the same job at ~380 LUT / ~290 FF less); the slot payload (row and the per-slot fields) is flops read by every comparator, where a reset-free LUTRAM indexed by slot with the row carried in the queue entry would do (row 5, ~300 LUT / ~600 FF); `mc_rd_return_ring` evaluates shadow readiness every cycle, resets `r_src` and keeps a dead `r_resp` (row 4, 150-250 LUT, 384 async-set flops).

## Plan

1. Row 4 first (smallest, ring-local): readiness evaluated at fetch, `r_src` reset dropped (the valid vector guards it, MC-005's rule), `r_resp` deleted.
2. Row 10: an 8-bit age per entry on a shared prescaler; `age_exceed` compares against the CSR threshold in the same units; the arbiter's age inputs keep their width through a zero-extend.
3. Row 5: slot payload into a reset-free LUTRAM written at insert, read by slot at issue; the row stays in the queue entry for the hit compares.
4. Routed A/B sys75 after each row; the rd_cam / wr_cam / rd_ring hotspots are the before/after census.

## Gate

## Progress (2026-11-07 late)

- Row 4 done: `mc_rd_return_ring` evaluates a shadow's readiness at the
  fetch pointer (`r_shadow[r_fptr] ? r_ready[r_src[r_fptr]] : r_ready[r_fptr]`)
  instead of marking every shadow of a returning ticket in the fill, the
  MERGE_MARK_REG ready special-case is gone with it, and `r_src` moved to a
  reset-free block (read only for allocated slots, always written at
  allocation). `r_resp` is NOT dead -- it feeds `r_if_resp` -- and stays.
  Unit test `test_mc_rd_return_ring` 24 / 24 (shadow and random model cells).
- Found while gating: the ring's formal proof was ALREADY RED on the
  committed tree (`a_ready_is_notfull` at step 4) -- the harness left the
  TASK-060 merge ports unconnected, which yosys treats as free inputs, so the
  solver allocated a shadow of the tail and pinned it. Ports tied to the
  no-merge contract with the reason written in; prove / data / cover pass.
- Rows 10 and 5: on the FPGA SKU the age logic is dead once
  `RUNTIME_PICK_MODES=0` (no ORDER_AGE_THR, so `sch_age_exceed` has no
  reader) and `HAS_SNARF=0` (no youngest-match), and synthesis prunes it;
  the batch-A build dropped 487 FF against the second cut. Whether an
  AGE_PRESCALE knob for the research configuration is worth its risk to the
  age-threshold ordering tests is an open question; row 5 (slot payload in
  LUTRAM) is area only and untouched so far.
