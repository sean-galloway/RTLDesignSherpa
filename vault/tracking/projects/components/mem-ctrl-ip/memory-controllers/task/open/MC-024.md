> Filed 2026-11-24 from the owner's "design a read-priority direction

## What it does

A second rule set for `mc_bank_pick`'s direction register, selected at run
time (`SCHED_POLICY.dir_mode`), reset to today's symmetric register:

| | symmetric (`dir_mode` 0, today) | read priority (`dir_mode` 1) |
|---|---|---|
| read hold cap | `dir_batch_max` (255) | none |
| write hold cap | `dir_batch_max` (255) | `wr_burst` (16) |
| reads -> writes | reads drained, or the read cap | reads drained, or **write starvation**: a write head queued `wr_starve` cycles (512) with no write column |
| writes -> reads | writes drained, or the write cap | the same (the cap is `wr_burst`) |
| leftover rule, cross-direction fire, hold-idle, ownership courtesy | as today | as today (with no read cap the reads keep the courtesy for the whole hold) |

## Model price (granite_sku100 = the board's `defaults`)

| cell | today | read priority |
|---|---|---|
| mixed_bl8 wr / rd (union) | 278 / 278 (555) | 307 / 597 (614) |
| read latency mean / max | 19.0 / 450 cyc | 9.8 / 80 cyc |
| worst write wait | 463 | 559 (bound 512 + the pick's latency) |
| mixed modes over 40 GO phases | race (board: one mode on `defaults`, two on `open_page`) | one mode on 40 / 40, both open-page presets |
| sustained reads (`mixed_rd4`) writes | 278 | **124** |
| sustained writes (`mixed_wr4`) wr / rd | 469 / 277 | 486 / 597 |
| close_page mixed reads | 121 | 114 (-6%) |
| every single-direction cell | | within 2% |

Priced and rejected (the record's section 3): a pool watermark drain (became
write priority: the writers refill the pool as fast as it drains), a read
quantum under write pressure (more turnarounds, a lower write share), longer
write bursts (the floor rises only at 128, and the board cell's reads fall to
382).

## RTL design (mc_bank_pick, behind `HAS_RD_PRIO`)

Structural parameter `HAS_RD_PRIO` (0 = tied off by generate, the logic
elided, bit-identical); granite builds it 1. New inputs, all static CSRs
(false paths in the board XDCs, the owner's 2026-11-08 rule):
`dir_mode_i`, `wr_starve_i[11:0]`, `wr_burst_i[7:0]`.

1. **Starvation counter.** `r_wr_wait[11:0]`: cleared on a write column
   fire (`w_col_fire_now && w_sel_is_wr`) or when no write head is valid
   (`|wr_head_i[*].vld`, the registered records); else +1, saturating.
   `r_wr_starved <= dir_mode_i && (wr_starve_i != 0) && (r_wr_wait >= wr_starve_i)`,
   registered: the compare sits in its own cycle, off the fire cone.
2. **The starvation flip.** In `w_dir_nxt`, after the two column-fire
   branches and before the drain flip:
   `else if (rp && !r_dir && r_wr_starved && w_wr_queued)` -> `w_dir_nxt = 1`,
   `w_dir_batch_nxt = 0`; `r_dir_cause` 3 (the 2-bit field's free code).
   `r_wr_starved` is a register, so the branch adds one AND of registered
   terms to the next-state mux.
3. **The cap.** `r_batch_done <= rp ? (w_dir_nxt ? (wr_burst_i != 0 &&
   w_dir_batch_nxt >= wr_burst_i) : 1'b0) : (today's compare)`. Both
   compares run in parallel on `w_dir_batch_nxt`; `w_dir_nxt` selects. This
   is the one change on a cone MC-022 measured with no margin (the D input
   of `r_batch_done`, not the fire path itself): build it, then read the
   path before calling timing.
4. Nothing else moves: `w_xdir_ok`, the row preference, the hint gate and
   the ownership courtesy all read `r_batch_done`, which now carries the
   mode's cap.

Cost estimate: one 12-bit counter, a 12-bit and an 8-bit compare, a 2:1 mux,
~14 FF and ~40 LUT.

**CSRs** (granite_csr.rdl): `SCHED_POLICY.dir_mode` at bit 24 (from
RSVD_31_24; reset 0); a new `SCHED_DIR_RP` @ 0x080 (0x078 / 0x07C stay
retired holes): `wr_starve[11:0]` reset 512, `wr_burst[23:16]` reset 16.
Regenerated through `bin/peakrdl_generate.py` with an explicit `-o`.
Host: a `read_priority` field on pumice_char's ControllerConfig and the
three SKU presets' variants; proxy knobs `TEST_DIR_MODE`, `TEST_WR_STARVE`,
`TEST_WR_BURST`. One bitstream runs both modes.

## Verification

- **Formal** (`formal/`, external, no RTL assertions): with `dir_mode_i = 0`
  an equivalence task against the golden pick core (bit-identical outputs).
  With `dir_mode_i = 1`: (a) `r_wr_starved && !r_dir` is followed by `r_dir`
  within a bound K unless a write column fires; (b) while a read column is
  pending a write hold fires at most `wr_burst` columns before the register
  flips; (c) a read hold never flips on the cap. Each mutation-checked with
  the flat rebuilt (the MC-020 lesson).
- **cocotb**: the pick-core suite at `dir_mode` 0 unchanged; new cases for
  the starvation flip and the write cap. The proxy, both modes: `mixed`
  under `defaults` and `open_page` at `TEST_TREFI` 778 .. 782 (one mode on
  all five under read priority), `mixed_rd4` / `mixed_wr4`-shaped runs, 0
  mismatched beats; clean-all first, the full granite regression.
- **Board**: the SKU bitstream with the field, windows x3 + every in both
  modes; the compare against `sku_rdprio` and the default presets.

## Decisions for the owner

1. **The write floor under sustained reads**: ~124 MB/s (17 percent of the
   bus) against 278 today, bounded latency (559 cycles). Nothing priced
   raised it without giving back the board cell's gain. Accept, or name a
   floor to design to.
2. **The reset default**: `dir_mode` 0 (today's register, the mode a
   board flow opts into) or 1 (read priority as the shipped behaviour).

## Done when

The RTL builds both modes with `dir_mode` 0 bit-identical (formal equiv);
the three read-priority properties prove and survive mutation; the proxy

into this task.
