# MC-024: the read-priority direction register -- a runtime mode of the pick core's direction register, no read cap, capped write holds, a write-starvation bound

> Filed 2026-11-24 from the owner's "design a read-priority direction
> register", the third option memory-controllers ISSUE-005 left open (the
> mixed cell's two modes are a one-slot race the refresh phase places; a
> knob closes it only into the time-share). Priced in the SKU model first:
> `char_results/model_mc024_read_priority_2026-11-24.md`. No RTL yet.

**Priority:** P2 -- the shipped preset's mixed cell (+10.6 percent union,
read latency halved, one mode on every refresh phase) and ISSUE-005's
resolution.
**Status:** OPEN 2026-11-24 -- designed and priced; both decisions taken

**Owner:** TBD

## What it does

A second rule set for `mc_bank_pick`'s direction register, selected at run
time (`SCHED_POLICY.dir_mode`), reset to today's symmetric register:

| | symmetric (`dir_mode` 0, today) | read priority (`dir_mode` 1) |
|---|---|---|
| read hold cap | `dir_batch_max` (255) | none |
| write hold cap | `dir_batch_max` (255) | `wr_burst` (reset 128) |
| reads -> writes | reads drained, or the read cap | reads drained, or **write starvation**: a write head queued `wr_starve` cycles (reset 512) with no write column |
| writes -> reads | writes drained, or the write cap | the same (the cap is `wr_burst`) |
| leftover rule, cross-direction fire, hold-idle, ownership courtesy | as today | as today (with no read cap the reads keep the courtesy for the whole hold) |

## Model price (granite_sku100 = the board's `defaults`)

The two CSRs are a dial: they set the write share while reads keep the bus
busy (the contended write rate, `wr_bw_rd_live_mb_s`), and the board cell's
union falls as that share rises. Record sections 4-5:

| `wr_starve` / `wr_burst` | contended write MB/s | mixed_bl8 wr / rd, union | read lat mean / max | worst write wait |
|---|---|---|---|---|
| 512 / 16 | 23 | 307 / 597, 614 | 9.8 / 80 | 559 |
| 512 / 128 | 140 | 299 / 454, 599 | 12.8 / 256 | 553 |
| 512 / 255 | 221 | 290 / 357, 580 | 17.0 / 454 | 558 |
| 256 / 255 | 305 | 305 / 283, 566 | 22.0 / 455 | 299 |
| today (symmetric) | 278 | 278 / 278, 555 | 19.0 / 450 | 463 |

- Every point is one mode on 40 / 40 GO phases under `defaults` and
  `open_page` (today: the refresh-placed race of ISSUE-005).
- 256 / 255 dominates today's register on every column but the mean read
  latency (22 vs 19).
- At equal write share a long burst beats a short one (fewer turns).
- Single-direction cells move by less than 2 percent; `close_page` mixed
  reads -6 percent at 512 / 16.

The first pricing quoted a 124 MB/s write floor at 512 / 16. That was the
write window, which under read priority includes a writes-only tail after
the reads end; the contended rate is 23 (record section 4). Priced and not
carried (section 3): a pool watermark drain (became write priority), a
read quantum under write pressure.

## RTL design (mc_bank_pick, behind `HAS_RD_PRIO`)

Structural parameter `HAS_RD_PRIO` (0 = tied off by generate, the logic
elided, bit-identical); granite builds it 1. New inputs, all static CSRs
(false paths in the board XDCs, the owner's 2026-11-08 rule):
`dir_mode_i`, `wr_starve_i[11:0]`, `wr_burst_i[7:0]`.

1. **Starvation counter.** `r_wr_wait[11:0]`: cleared on a write column
   fire (`w_col_fire_now && w_sel_is_wr`) or when no write head is valid
   (`|wr_head_i[*].vld`, the registered records); else +1, saturating.
   `r_wr_starved <= dir_mode_i && (wr_starve_i != 0) && (r_wr_wait >= wr_starve_i)`,
   registered: the compare sits in its own cycle, off the fire cone.
2. **The starvation flip.** In `w_dir_nxt`, after the two column-fire
   branches and before the drain flip:
   `else if (rp && !r_dir && r_wr_starved && w_wr_queued)` -> `w_dir_nxt = 1`,
   `w_dir_batch_nxt = 0`; `r_dir_cause` 3 (the 2-bit field's free code).
   `r_wr_starved` is a register, so the branch adds one AND of registered
   terms to the next-state mux.
3. **The cap.** `r_batch_done <= rp ? (w_dir_nxt ? (wr_burst_i != 0 &&
   w_dir_batch_nxt >= wr_burst_i) : 1'b0) : (today's compare)`. Both
   compares run in parallel on `w_dir_batch_nxt`; `w_dir_nxt` selects. This
   is the one change on a cone MC-022 measured with no margin (the D input
   of `r_batch_done`, not the fire path itself): build it, then read the
   path before calling timing.
4. Nothing else moves: `w_xdir_ok`, the row preference, the hint gate and
   the ownership courtesy all read `r_batch_done`, which now carries the
   mode's cap.

Cost estimate: one 12-bit counter, a 12-bit and an 8-bit compare, a 2:1 mux,
~14 FF and ~40 LUT. `wr_burst` stays 8 bits: 255 is the useful end of
the dial, not a limit on it.

**CSRs** (granite_csr.rdl): `SCHED_POLICY.dir_mode` at bit 24 (from
RSVD_31_24; reset 0); a new `SCHED_DIR_RP` @ 0x080 (0x078 / 0x07C stay
retired holes): `wr_starve[11:0]` reset 512, `wr_burst[23:16]` reset 128 (decision 1).
Regenerated through `bin/peakrdl_generate.py` with an explicit `-o`.
Host: a `read_priority` field on pumice_char's ControllerConfig and the
three SKU presets' variants; proxy knobs `TEST_DIR_MODE`, `TEST_WR_STARVE`,
`TEST_WR_BURST`. One bitstream runs both modes.

## Verification

- **Formal** (`formal/`, external, no RTL assertions): with `dir_mode_i = 0`
  an equivalence task against the golden pick core (bit-identical outputs).
  With `dir_mode_i = 1`: (a) `r_wr_starved && !r_dir` is followed by `r_dir`
  within a bound K unless a write column fires; (b) while a read column is
  pending a write hold fires at most `wr_burst` columns before the register
  flips; (c) a read hold never flips on the cap. Each mutation-checked with
  the flat rebuilt (the MC-020 lesson).
- **cocotb**: the pick-core suite at `dir_mode` 0 unchanged; new cases for
  the starvation flip and the write cap. The proxy, both modes: `mixed`
  under `defaults` and `open_page` at `TEST_TREFI` 778 .. 782 (one mode on
  all five under read priority), `mixed_rd4` / `mixed_wr4`-shaped runs, 0
  mismatched beats; clean-all first, the full granite regression.
- **Board**: the SKU bitstream with the field, windows x3 + every, each cell
  at the power-on defaults and at its optimized settings (decision 2's
  benchmark rule; `read_priority` among the optimized candidates); the
  compare against `sku_rdprio` and the default presets.

## Decisions for the owner

1. **The dial's reset point -- DECIDED 2026-11-24: 512 / 128.** The owner
   chose it over 512 / 16 (23 MB/s of writes under contention) and 256 / 255
   (305, today's register beaten on every column but the mean read latency).
   At 512 / 128 the `defaults` mixed cell is 299 / 454, union 599 (today
   555), read latency 12.8 mean / 256 max, worst write wait 553, writes 140
   MB/s while reads hold the bus; one mode on 40 / 40 GO phases under
   `defaults` and `open_page`. The model's `wr_burst` default (and so
   `sku_rdprio`) is 128.
2. **The reset default -- DECIDED 2026-11-24: `dir_mode` 0.** The owner:
   "power up should be the most generic setting" -- the symmetric register,
   which favours neither direction. Read priority is a CSR write.
   With it, the benchmark rule: **a benchmark across all cells runs each
   cell at the power-on defaults AND at that cell's optimized settings**
   (for the mixed cells, `dir_mode` 1 at 512 / 128; for every cell, the best
   of the matrix), and reports both.

## Done when

The RTL builds both modes with `dir_mode` 0 bit-identical (formal equiv);
the three read-priority properties prove and survive mutation; the proxy
shows one mode on five refresh phases under both open-page presets with 0
mismatched beats; the sys100 bitstream closes under the 0.2 ns budget; the
board's mixed cell lands within tolerance of `sku_rdprio`; ISSUE-005 closed
into this task.
