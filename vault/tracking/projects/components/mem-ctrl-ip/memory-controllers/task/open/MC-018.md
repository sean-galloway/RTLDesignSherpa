# MC-018: a Ramulator 2 configuration that IS the FPGA SKU, then pattern exploration on it for microarchitecture improvements

> Filed 2026-11-16 by the owner ("make a config in ramulator that matches the
> design; use this information to run patterns on ramulator to find uarch
> improvements"), the day the granite SKU default moved to the measured point
> (row lane built, 16-entry pool, the MC-017 direction rule; `GRANITE_SEAM_N`
> 16, `DUAL_ISSUE` 1). THE FPGA SKU IS THE CONFIGURATION (owner 2026-11-08):
> the model matches the SKU, not a research build.

**Priority:** P2 -- the model is the cheapest place to price a scheduling or
storage change before an RTL task is filed (MC-013 / MC-016 did exactly this
and one of three ideas survived); the SKU has moved three times since the
model was last tied to a board cell set (MC-012, 2026-11-11, pool 8, lane off).
**Status:** open 2026-11-16
**Owner:** TBD

## Why

The overlay (`projects/components/mem-ctrl-ip/references/ramulator2/`) has an
ideal controller (`open32` and friends), the strict per-bank FIFO with a rotor
(`BankFIFO-RR`, MC-013 item 4) and the peek variants (MC-016), each a
POLICY, none of them the SKU: no direction register with a 255-column batch
cap and the MC-017 hold rules, no `BANK_CAP_MIXED` 6 admission cap, no row
lane (one row command beside a column per MC cycle, ACT / PRE only, DDR2
only), no eight-entry-per-direction store shape at the measured pool, no
one-slot-per-MC-cycle command port with the 2 CK phase placement. The gaps the
model shows today are therefore a mixture of "the ideal does better" and "the
model is a different machine", and MC-012 / MC-013 read them by hand each
time. A configuration that reproduces the SKU's cells to a stated tolerance
turns the model into an instrument: a pattern that the SKU-model and a
variant disagree on is a candidate improvement with a number on it, before any
RTL is touched.

## What

1. **The SKU configuration.** A `granite_sku100` `ModelConfig` (char_model.py)
   plus whatever overlay scheduler / controller changes it needs, matching the
   shipped granite sys100 build:
   - DDR2 x16 BL4, DFI 1:2, MC 100 MHz / CK 200 MHz, `t_phy_wrlat` 1, the
     host's derived timings (`pumice_device.ddr2_timings_mc_cycles` at 100 MHz,
     tREFI 772, tRRD at the 2 KB-page value -- BUG-003), 2 CK command
     granularity (`mc_granular`), AllBank refresh at the host's placement.
   - the store: 16 entries per direction, per-bank FIFOs pool-deep
     (`BANK_FIFO_DEPTH` 0), `BANK_CAP_MIXED` 6 while the other direction holds
     entries, one entry = one BL4 beat (an AxLEN-8 burst is eight same-row
     entries), `HEAD2_EN` as it is (not a peek: MC-016).
   - the pick: `mc_bank_pick` as of 225094132 -- column-first with the rotor,
     the direction register (hold while the current direction has pending
     columns, `DIR_BATCH_MAX` 255, `DIR_OWNS_ROWS` 1, `DIR_HOLD_IDLE` 8, the
     four MC-017 terms), the row lane (one ACT / PRE to another bank beside
     the column, `row_phase` 1), the hint path (SRC_HINT).
   - the front end as the harness presents it: the `windows` / `every`
     streams the cocotb exporter already produces (MC-013 item 5), captured
     from the proxy at this SKU.
   Record every SKU term the model does NOT reproduce, with the reason
   (the model is cycle-approximate; the list is the instrument's error bars).
2. **Tie it to the board.** The 2026-11-16 SKU cells
   (`char_results/char_granite_sku100def_{windows,every}_2026-11-16.csv`, lane
   on, pool 16, defaults) are the reference. Report model vs board per cell;
   state a tolerance per family (the single-direction row-hit families should
   land within 2 percent as the ideal already does; `random`, `col_major` and
   `mixed` are where the SKU terms matter and where the match is the test).
   A family outside tolerance is a model term to add or an RTL effect to name,
   not a number to average away.
3. **Patterns.** With the SKU model trusted, run patterns the char profiles do
   not cover and the ones they do, on the SKU model and on variants that each
   change ONE term: pool 24 / 32; `BANK_CAP_MIXED` off / 4 / 8; batch cap 64 /
   128; the row lane carrying PRE only / ACT only / any row command; a
   two-head peek (MC-016's `peek_depth` 16 at pool 32 is the first depth that
   moves); write drain thresholds (MC-013 item 2); refresh placement (item 3);
   AxLEN 4 / 16 streams; bank-interleave strides that defeat the rotor;
   read-heavy and write-heavy mixes (70 / 30, 30 / 70) and the mixed window
   at 2 and 8 threads; row-locality sweeps (hit rate 10 .. 90 percent).
   One table: pattern x variant, MB/s and worst-wait, delta against the SKU
   column. The exporter / `char_model.py` sweep machinery is the tool; new
   pattern generators go beside the existing ones with a test each.
4. **The list.** Every variant that lifts a family by more than the model's
   own error bar without costing another becomes a filed task with the model
   number in its filing (as MC-014 / MC-015 were filed from MC-013 / the
   probe); every variant that does not is recorded with its number so it is
   not re-asked. The write-up lives in
   `ddr2-characterization/char_results/model_mc018_sku_config_2026-MM-DD.md`
   and the handbook note `vault/handbook/dv/dram-cycle-model.md` gains the SKU
   configuration section.

## Done when

`granite_sku100` exists in the overlay with its unmodelled-terms list, matches
the 2026-11-16 board cells within the stated per-family tolerance (the
comparison table committed), the pattern x variant table is committed, and
every candidate improvement is either a filed memory-controllers task carrying
its model delta or a recorded negative. No RTL in this task.

## Notes for whoever picks it up

- `make -j` in `vendor/ramulator2/build` is a 1 s incremental rebuild; the
  overlay's scheduler sources sit in
  `references/ramulator2/overlay/src/ramulator/controller/scheduler/impl/`, and
  codegen regenerates the Python mirrors (MC-016's `peek_depth` is the
  template for adding a scheduler knob end to end).
- `PERF_AXI_TRACE` on `test_granite_char_perf.py` exports the accepted AXI
  stream per pass as Ramulator traces; `PERF_DIR_FLIPS` / `PERF_PICK_PROBE`
  are the pick-core probes to check a model term against the RTL cycle by
  cycle.
- The 2 KB-page tRRD (BUG-003) makes tFAW unreachable at every legal point of
  this part after MC-cycle rounding (four rounded tRRDs cover the rounded
  tFAW); the model's CK-granular rounding differs and must be checked, not
  assumed, when the timing set is ported.
