## Why

Eight `mc_bank_timer` instances each redo the CSR arithmetic (`t_wr - 1`, `t_rtp <= 1`, the `f_ld` subtractions) every cycle (row 6, ~150-200 LUT, and the CSR -> timer fold is on granite's worst path); their counters could be SRL delay lines or 5->3 counters, and tFAW an SRL window (row 7, 250-400 LUT); the fast-release `S_MAX` is a two-stage 16-CSR max tree for a value that never changes during traffic (row 8, ~180 LUT / 98 FF -- a CSR or a serial scan); `mc_page_policy` drives `timeout_pre_req/bank` combinationally into the arbiter's pick (row 11, timing).

## Plan

1. Row 6: compute the per-timer load values once in the plane (or `mc_bank_timers`) from the CSRs and feed the 8 timers registered constants; `mc_bank_timers` already owns the EVT_REG/SET_LAG wrapper.
2. Row 11: register `timeout_pre_req/bank` in `mc_page_policy` (one cycle later is a background request; the arbiter's fire-stage re-check stays the authority).
3. Row 8: `S_MAX` from a CSR field written by the host from the same timing table (host already derives every timing), with the max tree kept behind a parameter for the proxy TBs.
4. Row 7: SRL delay lines for tRCD/tRP/tRAS/tRC/tWR/tRTP where the count fits; measure the LUT delta per timer out of context first.
5. Routed A/B sys75 (pumice) and sys100 (granite) after each row.
