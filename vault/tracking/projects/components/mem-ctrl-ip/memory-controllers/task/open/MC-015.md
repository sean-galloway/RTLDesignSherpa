# MC-015: the write stream pays one command slot per AXI burst at the intake (both controllers)

> Filed from MC-014's first sim (2026-11-12): with the row lane on, granite's
> reads on `col_major_interleaved` / `row_thrash` reach 773 / 775 MB/s, within
> 1 percent of the model's ideal, and the writes stay at 686 / 687 -- the same
> cells as without the lane. The write ceiling is not the command slot.

**Priority:** P2 -- the write-side twin of MC-014; ~+87 MB/s on every bank-parallel write cell once the lane ships.
**Status:** open 2026-11-12
**Owner:** TBD

## Why

The granite perf proxy's command trace (sku100 point, `TEST_DUAL=1`,
`char_results/sim_mc014_granite_row_lane_2026-11-12.md`) shows the write
column stream as a fixed pattern: seven WRs one cycle apart, then a gap of
two, repeating -- 8 beats in 9 cycles, 1 009 gaps of 2 in 1 024 bursts on
`col_major_interleaved_bl8`, 4 045 in 4 096 on `row_thrash`. The read stream
on the same families runs at gap 1 throughout (8 163 of 8 192). The pattern
is identical with the lane off (the control run, 1 010 gaps of 2), so the ACT
that used to take a slot per burst was hiding behind it; and pumice shows the
same one extra cycle per burst with its lane on (682 / 767 on the same
family, MC-013 item 1). Row commands are no longer in the write path, so the
bubble is upstream of the scheduler: per AXI burst, between the last beat of
one burst and the first of the next. `mc_wr_intake` captures one AW-meta FIFO
entry per burst and pushes the write data per beat; the store admits a write
column when its data has landed. The read side has no data to wait for and
streams.

8/9 of the refresh-limited peak is 695 MB/s, measured 686-687: the one slot
per burst is the whole write gap to the ideal (781).

## What

1. Trace the first beat of each write burst from `wvalid` at the AXI slave
   through the intake's data FIFO, the store's admission and the pick's
   decode to the WR fire: which hop adds the cycle (the proxy's
   `PERF_STORE_TRACE` and the pick probe exist). Candidates, in order: the
   injector's AW -> W ordering (the harness issues the first W beat after the
   AW handshake), the intake's AW-meta FIFO push gating the first beat's data
   push, the store's data-landed admission one cycle behind the data.
2. If it is the harness: a W-before-AW capable injector (AXI allows it) or a
   W skid that overlaps the next burst's first beat with this burst's last,
   and re-measure. The board host uses the same injector RTL, so the board
   cell moves with it.
3. If it is the controller: close the hop in the intake or the store
   (register-only, the same discipline as MC-011), re-run the common-ip
   contract bench and the granite / pumice func regressions, and re-measure.

## Done when

The write cells on `col_major_interleaved` and `row_thrash` sit within a few
percent of the read cells with the lane on, in sim and then on the board
(with MC-014's board step), or the task records which hop owns the cycle and
why it stays.
