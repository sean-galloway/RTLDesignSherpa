# MC-029: the row lane in the diagrams and the common MAS

> Filed 2026-11-27 out of pumice TASK-047 (owner's go). Docs only.

**Priority:** P2
**Status:** OPEN
**Owner:** TBD

The DUAL_ISSUE row lane is built by default on both DDR2 controllers (granite
since 2026-11-16, pumice since 2026-11-27), but none of the block diagrams
show it. Without that, a reader can't see that a DFI 1:2 word carries a column
on phase 0 and a row command to another bank on `DFI_PHASE.row_phase`.

## Items

1. **Scheduler plane diagram:**
   `common-ip/docs/common_mas/assets/graphviz/03_mc_scheduler_plane.dot`.
   - Show the two lanes out of the pick core: main (`cmd`) and row (`cmd2`).
   - Show the shared pieces each lane feeds: `mc_bank_timers` `evt2`,
     `mc_global_timers` (tRRD / tFAW across both lanes) and
     `mc_page_policy` `cmd2`.
   - Name both cores under `SCHED_CORE`.
2. **DFI 2.1 plane diagram:**
   `common-ip/docs/common_mas/assets/graphviz/06_mc_dfi_2p1_plane.dot`.
   - Show the `mc_dfi_cmd_path` `row_phase` formatter: the second command
     input, and the per-phase command slots it places it in.
   - The file is GENERATED by `gen_dfi_planes.py`; change the script, not the
     .dot.
3. **Slot waveform (new):** one 8-column row at the board geometry, lane off
   vs on.
   - Lane off: phase 1 always NOP, the next bank's ACT costs a slot, 9 slots
     per row.
   - Lane on: the ACT rides phase 1 beside a column, 8 slots per row.
   - Placement: common MAS ch04, next to the lane section.
4. **Common MAS ch04 text:**
   `common-ip/docs/common_mas/ch04_scheduler_plane/01_mc_scheduler_plane.md`.

     core".~~ Fixed 2026-11-28 with MC-028 step A, which also names
     `mc_row_lane` in the intro.
   - The lane section itself is MC-028's: it is written once, for
     `mc_row_lane`, when step B has settled the rules (the recommendation
     filed with MC-028; no interim granite section).
5. **pumice HAS module hierarchy:**
   `research-ip/pumice-ddr2-lpddr2/docs/pumice_has/assets/mermaid/02_module_hierarchy.png`.
   - The PNG is stale: the `.mmd` names `mc_cmd_arb_frfcfs`, the PNG still
