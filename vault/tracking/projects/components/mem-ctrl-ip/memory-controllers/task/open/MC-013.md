# MC-013: model-driven scheduling-policy exploration on the Ramulator 2 DDR2 model

> Follow-up to MC-012 (closed 2026-11-11), which put the board's char streams
> through an ideal FR-FCFS controller and found the scheduler's share of the
> gap on the bank-parallel miss patterns; this task tries the policies before
> any of them is RTL.

**Priority:** P3 -- exploration; the model runs in under a minute per configuration.
**Status:** open 2026-11-11
**Owner:** TBD

## Why

MC-012's first numbers (its results log, and
`ddr2-characterization/char_results/compare_model_ramulator2_vs_granite_sku100_2026-11-11.md`)
split granite's gap to the ideal: on `col_major` and `mixed` it is the RTL's
2 CK timer granularity and nothing else; on `col_major_interleaved`,
`row_thrash` and `random` it is ~1.1 MC cycle per burst that the 2 CK
rounding does not explain, with the single-command-per-MC-cycle issue slot
as the structural candidate. The model can price each candidate fix before
it is built.

## What

1. **Dual issue.** Confirm the slot hypothesis on granite itself: a
   `DUAL_ISSUE = 1` granite sim (the pumice TASK-047 row lane already exists
   in `mc_dfi_cmd_path` / `mc_scheduler_plane`) on `col_major_interleaved_bl8`
   should move from 688 toward the model's 780. If it does not, the ~1.1 MC
   cycle per burst is somewhere else (the bank-pick / seam path) and the model
   has told us where not to look.
2. **Write drain.** Ramulator's `wr_low_watermark` / `wr_high_watermark` on
   the `mixed` family against granite's read/write arbitration; the shape of
   the curve says whether a drain threshold is worth a CSR.
3. **Refresh placement.** `AllBank(scatter_interval=...)` and the no-refresh
   ceiling (800 vs 781) against granite's REF timing: how much of the 2.3 %
   refresh cost is recoverable by scheduling REF into idle.
4. **Per-bank vs pooled queues.** Granite's 16 bank FIFOs vs pumice's pooled
   CAM: a Ramulator scheduler plug-in (`scheduler/impl/frfcfs.cpp` is 40
   lines) that picks per bank in round robin, on the four-injector families.
5. **Trace from the cocotb side.** A `TimedLoadStoreTrace` exporter from a
   cocotb AXI monitor so a sim's exact request stream, not a rebuilt one,
   feeds the model (MC-012 rebuilt the streams from the host program's stride
   tables, cross-checked but not captured).

## Done when

Each item has a model number beside a measured or simulated granite number in
the char_results directory, and every policy the model says is worth more
than a few percent is filed as its own RTL task with that number in it.
