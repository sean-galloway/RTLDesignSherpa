# MC-013: model-driven scheduling-policy exploration on the Ramulator 2 DDR2 model

> Follow-up to MC-012 (closed 2026-11-11), which put the board's char streams
> through an ideal FR-FCFS controller and found the scheduler's share of the
> gap on the bank-parallel miss patterns; this task tries the policies before
> any of them is RTL.

**Priority:** P3 -- exploration; the model runs in under a minute per configuration.
**Status:** open 2026-11-11; item 1 done 2026-11-12 (MC-014 filed from it)
**Owner:** TBD

## Why

MC-012's first numbers (its results log, and
`ddr2-characterization/char_results/compare_model_ramulator2_vs_granite_sku100_2026-11-11.md`)
split granite's gap to the ideal: on `col_major` and `mixed` it is the RTL's
2 CK timer granularity and nothing else; on `col_major_interleaved`,
`row_thrash` and `random` it is ~1.1 MC cycle per burst that the 2 CK
rounding does not explain, with the single-command-per-MC-cycle issue slot
as the structural candidate. The model can price each candidate fix before
it is built.

## What

1. **Dual issue.** DONE 2026-11-12, see the results log below. The row lane
   cannot be built on granite (the bank-FIFO store forces the bank-pick core,
   which has no lane), so the slot was measured instead: the plane fires in
   97 % of MC cycles on `col_major_interleaved` / `row_thrash` with the ACT
   every 9 cycles exactly. Pumice, which has the lane on the same DFI command
   path, gains +13 % reads with it. The granite row lane is MC-014.
2. **Write drain.** Ramulator's `wr_low_watermark` / `wr_high_watermark` on
   the `mixed` family against granite's read/write arbitration; the shape of
   the curve says whether a drain threshold is worth a CSR.
3. **Refresh placement.** `AllBank(scatter_interval=...)` and the no-refresh
   ceiling (800 vs 781) against granite's REF timing: how much of the 2.3 %
   refresh cost is recoverable by scheduling REF into idle.
4. **Per-bank vs pooled queues.** Granite's 16 bank FIFOs vs pumice's pooled
   CAM: a Ramulator scheduler plug-in (`scheduler/impl/frfcfs.cpp` is 40
   lines) that picks per bank in round robin, on the four-injector families.
5. **Trace from the cocotb side.** A `TimedLoadStoreTrace` exporter from a
   cocotb AXI monitor so a sim's exact request stream, not a rebuilt one,
   feeds the model (MC-012 rebuilt the streams from the host program's stride
   tables, cross-checked but not captured).

## Done when

Each item has a model number beside a measured or simulated granite number in
the char_results directory, and every policy the model says is worth more
than a few percent is filed as its own RTL task with that number in it.

## Results log

### 2026-11-12: item 1, the command slot

Full table and recipe:
`ddr2-characterization/char_results/sim_mc013_command_slot_dual_issue_2026-11-12.md`.

- `granite_core` with `STORE_BACKEND=1` errors on any `SCHED_CORE` but
  BANK_PICK, and `mc_scheduler_plane` ties `a2_act / a2_pre` to 0 on that
  core: there is no dual-issue granite sim to run. The granite perf proxy's
  `PERF_CMD_TRACE` probe was also dead (it looked for the retired per-bank
  scheduler); it now reads the plane's `evt_*` strobes plus `cmd_accept_o`
  and reports the slot occupancy per 1024-cycle bin (`.gaps.json`, `slot`).
- Granite at the sku100 point (sim reproduces the board within 1 % on all
  four cells): `col_major_interleaved` 681 / 686 with occupancy 0.965 mean /
  0.981 max in the busy bins and the ACT period 9 cycles in 1950 of 2085
  ACTs; `row_thrash` 684 / 687, 0.970 / 0.981, ACT 9 in 7859 of 8355;
  `random` 626 / 656, 0.909 / 0.970, ACT gaps 9 / 15 / 6; `col_major` 413 /
  517 at 0.65-0.74 (timer-bound, the control). PREs are auto-precharge, so a
  burst is 8 columns + 1 ACT = 9 commands through one slot per cycle: 8/9 of
  peak less refresh = 695, measured 686. The slot IS the ceiling.
- Pumice (FR-FCFS core, same `mc_dfi_cmd_path`) `TEST_DUAL` 0 -> 1:
  `col_major_interleaved` 613 / 680 -> 682 / 767, `row_thrash` 615 / 682 ->
  683 / 769, `random` 578 / 642 -> 623 / 703, `col_major` 410 / 472 both
  (unchanged, as it should be). Dual-issue reads within 1.7 % of the model's
  ideal; pumice writes keep one extra cycle per burst that is not the lane.
- Filed MC-014: a row lane on `mc_bank_pick`, priced at +92..+100 MB/s on
  the two pure families and +110..+145 on `random` by the model, +68 / +87
  measured on pumice.
