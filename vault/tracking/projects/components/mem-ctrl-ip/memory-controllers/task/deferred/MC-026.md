## What is known

- With `ref_drain_pb` (the RTL's one-PREpb-per-two-slots refresh drain) the
  model reaches the RTL's ~518 write level on the bank_interleave row_major /
  incremental cells; without it the model has no levels (582 / 590 at every
  phase). The proportion is wrong: model `granite_sku100_bi row_major_bl8` at
  tREFI 780, both terms, 40 GO phases: writes ~518 on 26, ~570 on 14.
- The RTL proxy after the tREFI period fix (d36ee4882), 16 refresh offsets:
  writes ~518 on 6, partial dips on 4, ~570 .. 583 on 6; reads 565 on all.
  Those runs predate the pre-pass fix (9dc43c4ae) but row_major has no
  pre-pass, so they stand.
- `ref_drain_pb` and `behind_lag` 1 are the SKU defaults since 2026-11-26
  (MC-023 item 4, the hybrid). The SKU board compare is 53 in / 4 out, and
  these are the four: bank_interleave incremental_bl16 and row_major_bl4 /
  bl8 / bl16, writes at ~518 against the board's ~583
  (`compare_model_sku_mc023_defaults_vs_board_sku100rpap_2026-11-26.md`).
  `sku_norefdrain` (the model before) is 57 in / 0 out, but holds the
  hybrid's mode by compensation.
