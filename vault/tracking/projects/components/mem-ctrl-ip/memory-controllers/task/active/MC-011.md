## What closure means from here

1. Both board XDCs carry `set_clock_uncertainty -setup 0.200` on the system
   clock (the measured band). Closed = WNS >= 0 under it. Never "closes" alone.
2. The band is re-measured with the flow's `PLACE_DIRECTIVE` knob
   (AltSpreadLogic_high / ExtraTimingOpt / Explore) on the same netlist; the
   `reports_*_budget_*` directories hold the measurement.

## Plan

1. Measure under the budget: pumice sys75 (default = FPGA SKU), granite sys100
   (push profile) x 3 directives each; granite sys75 (board point) x 1.
2. Pumice sys75 SKU: expected at or just under zero with the budget. Binding
   cones from the latest builds: bank-timer `r_preblk` / `r_open_row` live
   readiness into the arbiter's fire stage (`r_bank`, `r_row`), and the
   CAM bank field into the 1b column pick (`wr_col_ap`). Candidates: the
   fire-stage readiness as a registered lookahead with the hold moved one
   cycle (the timers already export `*_la` twins for exactly this), and
   MC-009 step (b).
3. Granite sys100: the bank pick's `r_hold` / `r_pick_cls` / `r_held_pair`
   select loop fed by the store heads and the page policy's timeout request
   (MC-010 row 15). First cut: register the timeout request one more cycle
   into the pick (a background request), then the `w_self_stale` register the
   review's 02 report names, then the 16->8 rotor.
4. Every step: formal where a proof exists, the suites, and the three-directive
   sweep -- the number reported is the WORST of the three under the budget.
