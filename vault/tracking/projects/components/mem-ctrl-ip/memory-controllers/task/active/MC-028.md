## Why

The DUAL_ISSUE row lane is one duty: put a demand ACT / PRE to another bank on
`DFI_PHASE.row_phase` beside the main lane's column, one row command per DFI
word. Both pick cores carry it, each written separately inside its own core:

| | `mc_cmd_arb_frfcfs` (pumice) | `mc_cmd_arb_bank` (granite) |
|---|---|---|
| Source | lines ~313-345 (state), ~1579-1610 (candidates), ~1871-1925 (pick, fire) | lines ~636-656, ~1087-1160 (pick), ~1393-1466 (fire) |
| Candidates | the pre-pick's demand ACT / PRE, either direction's slot | every head record's row request |
| Direction | the riding column's direction only (be8d7cd76, 2026-11-27) | either direction |
| Bank exclusion | the banks of the two column candidates | any bank with a pending column in either direction |
| Fires beside | a column or an idle main lane | a column only (keeps the lane out of the command-valid cone) |
| Hold | while the bank is in the state the command needs | while the class applies and the lookahead timer opens within the pipe |

Some differences follow from the cores (the candidate source, the cone rule
that made granite's lane column-only at sys100). Others are the same rule
written two ways that drifted apart. Today's pumice bug, where the lane
precharged a write bank for the readers' row mid-batch, was fixed in one
core only. Granite was safe from it by a different rule, its any-column bank
exclusion, not by sharing the fix (see the check below). The next fix to one
lane will again have to be found and re-derived in the other.

## What

1. Pull the lane into one block, `mc_row_lane` (common-ip `rtl/fub`), that
   both cores feed with the same interface:
   - per bank: a demand ACT (with its row) and a demand PRE request, each with
     its direction;
   - per bank: "a column is pending here" (either direction);
   - the riding column this cycle: its bank and direction;
   - the main lane's row / REF / ZQ / maintenance fire;
   - the bank-state and timer images (`bank_row_active`, `bank_act_ready`,
     `bank_pre_ready`, their lookaheads, `tfaw_ok`, `trrd_ok`, `rfc_busy`);
   - outputs: `row2_act_o`, `row2_pre_o`, `row2_bank_o`, `row2_row_o`,
     plus the stale / hint side-band granite needs.
2. Settle each divergent rule once, on measurement: the direction rule, the
   bank exclusion, beside-idle vs column-only, and the hold rule. Each choice
   is A/B'd on both proxies (pumice `test_ddr2_char_perf.py`, granite
   `test_granite_char_perf.py`, the `mixed`, `col_ilv`, `col_major` families
   at BL8, lane on and off).
3. Both cores instantiate it under `DUAL_ISSUE`; lane off stays bit-identical.
4. Formal: the existing `formal/mc_common/mc_cmd_arb_frfcfs` dual tasks and
   `mc_cmd_arb_bank` dual / equiv tasks keep passing. Add lane properties on
   the new block (one row command per word, never the riding column's bank,
   no ACT beside a main ACT, tRRD / tFAW honoured).
5. Timing: the granite sys100 SKU and the pumice sys75 SKU still close, with
   the ~0.2 ns placement spread budgeted.
6. Board: both rigs rebuilt and run in one pass (`windows` + `every`),
   0 mismatched.

## 2026-11-28: step A done -- the lane is one block, behaviour unchanged

`common-ip/rtl/fub/mc_row_lane.sv` (+ `filelists/fub/mc_row_lane.f`, pulled in
by both cores' `.f`) holds the lane's three stages for both cores:
- **Candidates:** per (bank, direction) pair, with ONE bank-busy rule: no
  column pending on the bank in either direction. Each core feeds its own
  column-pending set: granite every live head, pumice its two column
  candidates.
- **Pick:** ACT before PRE, then one pair.
- **Register:** hold, load or drop.
- **Fire:** the bank state, timers, tRRD / tFAW and the refresh busy. The
  core adds its own terms (`core_ok_i`, `core_fire_i`).

Every rule the two copies disagreed on is a parameter, set per core. These are
step B's list:

| Parameter | pumice | granite |
|---|---|---|
| `PICK_MODE` | 1, per-direction priority | 0, age then rotor |
| `DIR_RULE` | 1, the riding column's direction only | 0, either |
| `HOLD_MODE` | 0, held on bank state | 1, held on the lookahead timer |
| `LATCH_ROW` | 1, the row rides in the lane | 0, slot lookup at fire |

Plus two core-side differences now visible as the core terms: pumice may fire
beside an idle main lane (`core_fire_i` = `cmd_ready`), granite only beside a
column (`w_col_fire_now`).

**Equivalence** (`formal/mc_common/mc_row_lane/{frfcfs,bank}`): each core
against its own copy from before the move (`*_pre028.sv`, 2ff688065), BMC from
reset, every output every cycle, all inputs free per cycle (CSR knobs and
`dual_issue_en_i` included). The lockstep wrapper and harness are generated
from the core's port list (`gen_pair.py`, `make pair`). Both copies start from
one state (`setundef -init -zero`): payload and storage registers are
reset-free by design and would otherwise power up differently.
