**Priority:** P2 -- the single largest chip-wide area lever the review found.
**Status:** active 2026-11-06 -- RTL done as the `DATA_RST` parameter (default 0 = the new form); skid suite FULL 61/61, formal prove + cover PASS, OOC synth measured (below); area regressions clean 2026-11-06; routed A/B builds (granite 75 MHz, pumice 75 MHz) running 2026-11-07.
**Owner:** TBD

## Why

The 10-29 routed pumice checkpoint has 49 `gaxi_skid_buffer` instances costing
6,366 LUT / 6,430 FF, 17% of the chip, about one LUT per flop. The cause is the
storage style (`gaxi_skid_buffer.sv:128-170`): every data bit is a 4-way mux
(load / shift / clear-to-zero / hold) on an async-reset flop, with the vacated
tail slot explicitly zeroed. The canonical two-register skid (an output
register and one skid register, no data reset, no shift, a 2:1 mux per bit) is
about half a LUT per flop. Estimated saving ~3k LUT chip-wide on either
controller; every board instance is DEPTH=2 (880 of the repo's instantiation
sites say `DEPTH(2)`; the rest are parameters that resolve to 2 on the board).

## Contract (what must NOT change)

- Port list and parameters identical. `DEPTH` 0 and 2..8 stay legal
  ([[feedback-skid-depth-contract]]: odd depths are legal, the `{2,4,6,8}`
  guard was an inference and is gone).
- Cycle-exact handshake behaviour on `wr_ready`, `rd_valid`, `count`,
  `rd_count`, and `rd_data` WHILE `rd_valid` is high. The existing
  `val/amba/test_gaxi_skid_buffer.py` levels and the formal properties under
  `formal/amba/gaxi/` are the gate; none of them may be loosened.
- What MAY change: `rd_data` while `rd_valid` is low. Today it reads zero after
  reset and after a vacated tail; a reset-free register holds stale data. The
  task must grep every consumer for a dependence on `rd_data` when
  `rd_valid=0` (a `&`/`|` reduction, a comparison, a monitor that samples
  without valid) before claiming zero functional change.

## Plan

1. Measure first: OOC synth of the current module at DATA_WIDTH 64/128/256,
   DEPTH 2, on the A7 part, LUT and FF -- the baseline the saving is claimed
   against. Keep the numbers in this file.
2. DEPTH=2 branch: two registers (`r_out`, `r_skid`) written in a reset-free
   `always_ff` gated only by their load conditions; `wr_ready` / `rd_valid` /
   the occupancy bits stay in the reset block. No shift, no clear.
3. DEPTH>2 branch: pointer-indexed ring in a reset-free array (read and write
   pointers reset, data not), so the odd-depth contract survives without a
   per-slot shift mux. If timing or the formal harness argue for keeping the
   shift for DEPTH>2, say so here and keep it; the board only builds DEPTH=2.
4. Gate: `val/amba` skid tests at every level against a clean build
   ([[feedback_always_make_clean_all_first]]), the gaxi formal proofs, then
   `make clean-all && make run-all-func-parallel` for the areas whose RTL
   instantiates it (amba, mem-ctrl-ip pumice + granite, dma-ip stream/rapids,
   utility-ip converters, ecc-ip reed-solomon, cdc), named per
   [[feedback_ci_green_name_the_repo]].
5. Re-measure OOC and one full pumice build-perf build; record LUT/FF before
   and after in this file and in ISSUE-001's anchor table.

## Risks

- Shared primitive: a behavioural slip here breaks every AMBA channel in the
  repo at once ([[feedback_confirm_scope_shared_rtl]] -- scope confirmed by the
  owner for this task). The contract section above is the whole defence.
- The 2026-04-23 refactor note in the header explains why the previous flat
  packed vector was abandoned (dynamic part-select -> 17 logic levels). The
  two-register form has no dynamic index; the DEPTH>2 ring must keep its index
  arithmetic to the pointer bits only.

## Done 2026-11-06: `DATA_RST` parameter on the existing module

Owner direction mid-task: "make the skid buffer and fifo updates parameters on
the existing modules." (The gaxi FIFO memories were already reset-free and
LUTRAM-inferred -- the review's own "good" list -- so only the skid buffer
changes.) `gaxi_skid_buffer` gained `parameter bit DATA_RST = 1'b0`:

- `DATA_RST=0` (default): the slots are written in a reset-free `always_ff`
  gated only by the same load / shift decisions as before, and a vacated slot
  is not cleared. The head slot is a 2:1 mux per bit (wr_data / next slot),
  every other slot a clock-enabled flop. At DEPTH=2 this IS the canonical
  two-register skid; the same generate serves 3..8 with no dynamic index.
- `DATA_RST=1`: the pre-MC-004 storage kept verbatim (async reset to zero,
  tail cleared to zero), for any consumer that reads `rd_data` without
  `rd_valid`.
- The handshake registers (`wr_ready`, `rd_valid`, `r_data_count`) are shared
  and untouched, so the two styles are cycle-identical on every port except
  `rd_data` while `rd_valid` is low. The formal harness never looks at
  `rd_data`; the sim suite's scoreboard samples it only on the handshake.

Default chosen as the NEW form because the 49 board instances sit behind
rtl/amba masters, slaves, the bridge and the harness -- plumbing an override to
each is the plumbing the review was trying to avoid. Flip `DATA_RST=1` at an
instance to get the old storage back.

### Measured (OOC synth, xc7a100tcsg324-1, 10 ns, `opt_design`; LUT / FF)

| DATA_WIDTH | DEPTH | before (= `DATA_RST=1`) | after (`DATA_RST=0`) | LUT saved |
|---|---|---|---|---|
| 64 | 2 | 142 / 134 | 77 / 134 | 46% |
| 128 | 2 | 272 / 262 | 141 / 262 | 48% |
| 256 | 2 | 532 / 518 | 272 / 518 | 49% |
| 64 | 4 | 278 / 262 | 211 / 262 | 24% |
| 128 | 4 | 538 / 518 | 407 / 518 | 24% |
| 256 | 4 | 1057 / 1030 | 796 / 1030 | 25% |

`DATA_RST=1` re-synthesised to exactly the baseline (142/134 at 64x2, 278/262
at 64x4), so the legacy branch is the old netlist. Flop count is unchanged by
design: the saving is the per-bit clear/zero logic, ~0.5 LUT per data flop at
DEPTH=2 as the review predicted. Whole-design synth A/B (same tree, MC-004 + MC-005 together, detached-worktree
baseline): pumice 46,131 -> 43,868 LUT (-2,263), granite 41,036 -> 38,877
(-2,159); numbers and method in MC-005. The skid share of that is most of the
logic-LUT drop; the ~3k estimate assumed the routed 6,366 figure, and the
synth-level skid total is smaller, so the saving is in proportion.
