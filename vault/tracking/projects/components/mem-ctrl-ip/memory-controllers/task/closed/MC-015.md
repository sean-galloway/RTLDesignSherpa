# MC-015: the write stream pays one command slot per AXI burst at the intake (both controllers) -- it was the store's 8-entry pool

> Filed from MC-014's first sim (2026-11-12): with the row lane on, granite's
> reads on `col_major_interleaved` / `row_thrash` reach 773 / 775 MB/s, within
> 1 percent of the model's ideal, and the writes stay at 686 / 687 -- the same
> cells as without the lane. The write ceiling is not the command slot.

**Priority:** P2 -- the write-side twin of MC-014; ~+87 MB/s on every bank-parallel write cell once the lane ships.
**Status:** CLOSED 2026-11-13 (active 2026-11-13; the mechanism found, sized in sim on both controllers, built and measured on the board the same day)
**Owner:** claude (mem-ctrl session)

## Why

The granite perf proxy's command trace (sku100 point, `TEST_DUAL=1`,
`char_results/sim_mc014_granite_row_lane_2026-11-12.md`) shows the write
column stream as a fixed pattern: seven WRs one cycle apart, then a gap of
two, repeating -- 8 beats in 9 cycles, 1 009 gaps of 2 in 1 024 bursts on
`col_major_interleaved_bl8`, 4 045 in 4 096 on `row_thrash`. The read stream
on the same families runs at gap 1 throughout (8 163 of 8 192). The pattern
is identical with the lane off (the control run, 1 010 gaps of 2), so the ACT
that used to take a slot per burst was hiding behind it; and pumice shows the
same one extra cycle per burst with its lane on (682 / 767 on the same
family, MC-013 item 1). Row commands are no longer in the write path, so the
bubble is upstream of the scheduler: per AXI burst, between the last beat of
one burst and the first of the next. `mc_wr_intake` captures one AW-meta FIFO
entry per burst and pushes the write data per beat; the store admits a write
column when its data has landed. The read side has no data to wait for and
streams.

8/9 of the refresh-limited peak is 695 MB/s, measured 686-687: the one slot
per burst is the whole write gap to the ideal (781).

## What

1. Trace the first beat of each write burst from `wvalid` at the AXI slave
   through the intake's data FIFO, the store's admission and the pick's
   decode to the WR fire: which hop adds the cycle (the proxy's
   `PERF_STORE_TRACE` and the pick probe exist). Candidates, in order: the
   injector's AW -> W ordering (the harness issues the first W beat after the
   AW handshake), the intake's AW-meta FIFO push gating the first beat's data
   push, the store's data-landed admission one cycle behind the data.
2. If it is the harness: a W-before-AW capable injector (AXI allows it) or a
   W skid that overlaps the next burst's first beat with this burst's last,
   and re-measure. The board host uses the same injector RTL, so the board
   cell moves with it.
3. If it is the controller: close the hop in the intake or the store
   (register-only, the same discipline as MC-011), re-run the common-ip
   contract bench and the granite / pumice func regressions, and re-measure.

## Done when

The write cells on `col_major_interleaved` and `row_thrash` sit within a few
percent of the read cells with the lane on, in sim and then on the board
(with MC-014's board step), or the task records which hop owns the cycle and
why it stays.

## Results log (2026-11-13)

**The framing was wrong and the probe said so in one run.** A per-cycle
valid/ready probe on every hop of the write path (`PERF_W_HOPS` in
`test_granite_char_perf.py`) shows the same 1 007 gaps of two at every hop,
all as "valid, no ready" above the FIFO store: the store refuses one AW head
in nine with `w_wr_have_free = 0`. The write pool holds eight entries and a
slot turns around in nine cycles (admit -> fire -> fill -> pick -> WR ->
commit -> fetch-last, every stage a register); eight over nine is 8/9 of a
command per cycle = 686 of 781. The 8-beat period was the pool, not the
burst. Item 1's three candidates (injector ordering, AW-meta FIFO gating,
store admission timing) were read statically first and are all bubble-free;
items 2 and 3 do not apply -- the fix is capacity, not a hop.

- **Sim, granite** (`char_results/sim_mc015_write_pool_2026-11-13.md`; sku100
  point, lane on, `TEST_NUM_ENTRIES`): `col_major_interleaved` 686 / 773 ->
  **766 / 768** (pool 12: 768 / 767), `row_thrash` 687 / 775 -> **769 / 769**,
  `random` 627 / 722 -> **719 / 717**, `col_major` 414 / 516 unchanged,
  `mixed` 475 / 300 -> 473 / 267 at bank cap 6 (the cap sweep at pool 16 is
  non-monotonic: 120 / 120, 277 / 513, 473 / 267, 221 / 219 at 3 / 4 / 6 / 8
  -> MC-016). 0 mismatched beats throughout.
- **Sim, pumice** (`TEST_WR_CAM_DEPTH` threaded through `ddr2_char_uart_tb_top`
  and `ddr2_char_harness`, default 8 unchanged): `col_major_interleaved`
  682 / 767 -> **768 / 767**, `col_major` 410 / 472 -> 411 / 472. Same pool,
  same eight, both controllers.
- **Board** (`char_results/board_mc015_write_pool_sku100_2026-11-13.md`):
  sys100 with `GRANITE_DUAL_ISSUE=1 GRANITE_NUM_ENTRIES=16`: **+0.034 ns
  under the 0.2 ns budget, 0 failing endpoints**, 37 258 LUT / 32 922 FF
  (+913 / +667 over the MC-014 design point), worst path still the main
  pick's class select. Smokes pass lane off and on. `col_major_interleaved`
  688 / 774 -> **768-770 / 768-770** (bl4 765-768, bl16 772), `row_thrash`
  688 / 774 -> **770 / 770**, `random` 629-635 / 723-729 -> **718-726 /
  740-746**; `incremental` 772 -> 775; `col_major` and every other `every`
  cell identical; `mixed` swaps shape between the presets (487 / 300 -> 318 /
  649 defaults, 334 / 649 -> 473 / 286 open_page), 0 mismatches. Reads on the
  two pure column streams give back 4-6 MB/s (774 -> 768-770) with the read
  pool doubled alongside; not chased here.
- **Regressions**: the char framework func suite after the pumice TB
  parameter (see the commit); the granite / pumice proxies ran as the
  measurements. No RTL changed.

**Done-when, met:** the write cells sit level with the read cells on
`col_major_interleaved` and `row_thrash` in sim and on the board, with the
pool at 16. **Open decision for the owner:** the SKU default is 8
(`granite_char_harness` `NUM_ENTRIES`, `GRANITE_SEAM_N`; pumice
`ddr2_char_macro` `WR_CAM_DEPTH`). Moving it to 16 costs +913 LUT and the
`mixed` balance question above, and buys +12 percent writes on every
bank-parallel family; this task leaves it as the build knob
`GRANITE_NUM_ENTRIES=16`, as MC-014 left `GRANITE_DUAL_ISSUE=1`, and
recommends the two move to the SKU together once MC-016 has looked at
`mixed`.
