> Source: owner direction, 2026-10-12 ("add a todo for mem-ctrl, please. For
> each ip fub/macro create GTKW files in the tests areas. For the top, create
> GTKW files for the write path to dfi and the rd path to/from dfi").
> Scope: `projects/components/mem-ctrl-ip` — the common-ip fub + macro
> inventory as exercised from each controller's tests area, and the four
> cores' tops (pumice, scoria, andesite research-ip; granite product-ip).

**Priority:** P3
**Status:** closed 2026-10-08 (per its own close record)
**Owner:** TBD

Wave-debug views for the whole MC family, following the stream/rapids
precedent (commit `f8e2197e7`: `.gtkw` per tested fub/macro plus top
engine-path views, each validated 0-missing-paths against a gate-level VCD).

Motivation, stated plainly: the 2026-10-12 granite bring-up wedge (WR
engine freezes, zero DFI commands, scheduler silent) took hours of UART
probe archaeology that a checked-in wr-path GTKW would have answered in one
waveform. These views are debug infrastructure for exactly that class of
failure.

## Deliverables

- [ ] **Fub views**: one GTKW per tested common-ip fub, filed in the tests
  area that exercises it — `research-ip/pumice-ddr2-lpddr2/dv/tests/fub/GTKW/
  <name>/<name>.gtkw` (the `tests/fub/GTKW/` dir already exists there;
  extend it). Inventory to cover (common-ip `rtl/fub/`):
  `mc_rd_cmd_cam`, `mc_rd_return_ring`, `mc_wr_data_cam`, `mc_wr_intake`,
  `mc_rd_intake`, `mc_wr_splitter`, `mc_axi_burst_chopper`,
  `mc_addr_mapper`, `mc_bank_timer(s)`, `mc_global_timers`,
  `mc_cmd_arbiter`, `mc_cmd_history_checker`, `mc_page_policy`,
  `mc_xddr2_init_sequencer`, `mc_xddr2_mode_register`,
  `mc_xddr2_refresh_ctrl`, `mc_xddr2_entry_store`,
  `mc_xddr2_cmd_formatter`, `mc_dfi_cmd_path`, `mc_dfi_wr_serializer`,
  `mc_dfi_rd_aligner`, `mc_dfi_cdc`, `mc_lpddr2_zq_ctrl`,
  `mc_lpddr2_dq_cal`. A fub without a test in any tests area gets its view
  with the test it lands with — do not create orphan views.
- [ ] **Macro views**: same treatment for the common-ip macros
  (`rtl/macro/`): `mc_axi4_plane`, `mc_storage_plane`, `mc_scheduler_plane`,
  `mc_training_plane`, `mc_training_shell`, `mc_dfi_2p1_plane`,
  `mc_dfi_3p1_plane`, `mc_dfi_4p0_plane`, `mc_ras_plane` — filed under the
  tests area of the core that exercises the macro.
- [ ] **Top views — write path to DFI**: per core top, a view tracing host
  AXI W (and AW) → axi plane intake → storage/entry seam → scheduler
  cmd stream → DFI plane → `dfi_wrdata_o` / `dfi_wrdata_en_o`, with the
  B-response return overlaid. Cores: pumice, scoria, andesite
  (`dv/tests/top/`), granite (`product-ip/granite-ddr2-lpddr2/dv/tests/top/`).
- [ ] **Top views — read path to/from DFI**: per core top, host AR → rd
  intake → CAM/entry → scheduler RD issue → DFI `dfi_rddata_en_o` → PHY
  `dfi_rddata_i` / `dfi_rddata_valid_i` → return ring → R channel, with the
  ring ticket signals (`rt_alloc_*`, `rd_iss_*`) grouped — the seam the
  granite bring-up hypothesis first pointed at.
- [ ] **Validated, not authored**: every `.gtkw` proven 0-missing-paths
  against a real wave dump — run its test with `WAVES=1`, load the VCD,
  check every saved path resolves (same mechanism the stream/rapids batch
  used). A view that references a signal the TB doesn't dump is a defect.
- [ ] Gates: `bin/filelist_registry.py --check` PASS; no new broken links;
  no test slowdown beyond the WAVES-gated dump itself.

## Notes

- Hierarchy paths in the views must match each TB's DUT instance names
  (`u_entry_store`, `u_axi_plane`, `u_sched_plane`, `u_dfi_plane` on the
  granite/pumice-family cores) — derive them from the TB RTL, not from
  memory.
- The granite `dv/tests/top/` area already carries the new cocotb smokes
  (`test_granite_core.py`, `test_granite_top_geared.py`); its top wr/rd
  views should key off those TBs' hierarchies.
- Keep views focused: a GTKW is a triage instrument, not documentation —
  group by contract (handshakes, credits/tickets, counters) per the house
  diagram flows (cmd top-down, wr data its own route, rd data back up).

Closes when every tested fub/macro has a validated view in its tests area
and all four cores carry top wr-path and rd-path views, with the gate
checks green.
