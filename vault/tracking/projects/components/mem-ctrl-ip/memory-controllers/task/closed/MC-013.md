# MC-013: model-driven scheduling-policy exploration on the Ramulator 2 DDR2 model

> Follow-up to MC-012 (closed 2026-11-11), which put the board's char streams
> through an ideal FR-FCFS controller and found the scheduler's share of the
> gap on the bank-parallel miss patterns; this task tries the policies before
> any of them is RTL.

**Priority:** P3 -- exploration; the model runs in under a minute per configuration.
**Status:** CLOSED 2026-11-12 -- all five items have their model number beside a measured / simulated granite number (`char_results/sim_mc013_command_slot_dual_issue_2026-11-12.md`, `sim_mc013_policies_2026-11-12.md`); two RTL tasks filed from it (MC-014, MC-016), the other three policies priced below "a few percent"
**Owner:** TBD

## Why

MC-012's first numbers (its results log, and
`ddr2-characterization/char_results/compare_model_ramulator2_vs_granite_sku100_2026-11-11.md`)
split granite's gap to the ideal: on `col_major` and `mixed` it is the RTL's
2 CK timer granularity and nothing else; on `col_major_interleaved`,
`row_thrash` and `random` it is ~1.1 MC cycle per burst that the 2 CK
rounding does not explain, with the single-command-per-MC-cycle issue slot
as the structural candidate. The model can price each candidate fix before
it is built.

## What

1. **Dual issue.** DONE 2026-11-12, see the results log below. The row lane
   cannot be built on granite (the bank-FIFO store forces the bank-pick core,
   which has no lane), so the slot was measured instead: the plane fires in
   97 % of MC cycles on `col_major_interleaved` / `row_thrash` with the ACT
   every 9 cycles exactly. Pumice, which has the lane on the same DFI command
   path, gains +13 % reads with it. The granite row lane is MC-014.
2. **Write drain.** DONE 2026-11-12. The hysteresis curve on `mixed` is
   monotonic in drain depth: +4 % (32-deep) / +8.5 % (8-deep) at the deepest
   setting over Ramulator's default, -7 / -20 % at a shallow one; granite's
   direction register (held while the owner has work, batch cap 255) is the
   deep end already. Not worth a CSR.
3. **Refresh placement.** DONE 2026-11-12. 1.67 % of the 2.4 % refresh cost is
   the tRFC floor; eight REFs as one burst (the postpone credit) recover the
   other 0.6 %, +5 MB/s; `scatter_interval` at one rank is a phase shift only.
   Below a few percent: no task; `REF_CTRL.refresh_burst` is the field if ever.
4. **Per-bank vs pooled queues.** DONE 2026-11-12. `BankFIFO-RR` written into
   the overlay. Single-direction families tie within 1 MB/s (with the column
   preference); `row_thrash` / `random` reads show upstream's plain FR-FCFS as
   the worst policy (743 / 760; row-hit-first or per-bank reach 782 / 780), so
   the ideal on those two is `open32_rowhit`; `mixed` pays 11 % for strict
   per-bank FIFOs against a pooled row-hit-first queue (320 vs 360). Filed as
   MC-016 (model the two-head store first).
5. **Trace from the cocotb side.** DONE 2026-11-12. `perf_axi_trace.py`
   exports the controller's accepted AXI stream per pass; `char_model.py
   run-trace` replays it. The three single-direction rebuilds are confirmed to
   the MB/s under every policy; `mixed`'s rebuilt beat-alternating stream is 8 %
   pessimistic against the port's burst-grained one, so the mixed ideal is
   363-370, not 337, and granite's `mixed` gap is 10 %, not 2.

## Done when

Each item has a model number beside a measured or simulated granite number in
the char_results directory, and every policy the model says is worth more
than a few percent is filed as its own RTL task with that number in it.

## Results log

### 2026-11-12: item 1, the command slot

Full table and recipe:
`ddr2-characterization/char_results/sim_mc013_command_slot_dual_issue_2026-11-12.md`.

- `granite_core` with `STORE_BACKEND=1` errors on any `SCHED_CORE` but
  BANK_PICK, and `mc_scheduler_plane` ties `a2_act / a2_pre` to 0 on that
  core: there is no dual-issue granite sim to run. The granite perf proxy's
  `PERF_CMD_TRACE` probe was also dead (it looked for the retired per-bank
  scheduler); it now reads the plane's `evt_*` strobes plus `cmd_accept_o`
  and reports the slot occupancy per 1024-cycle bin (`.gaps.json`, `slot`).
- Granite at the sku100 point (sim reproduces the board within 1 % on all
  four cells): `col_major_interleaved` 681 / 686 with occupancy 0.965 mean /
  0.981 max in the busy bins and the ACT period 9 cycles in 1950 of 2085
  ACTs; `row_thrash` 684 / 687, 0.970 / 0.981, ACT 9 in 7859 of 8355;
  `random` 626 / 656, 0.909 / 0.970, ACT gaps 9 / 15 / 6; `col_major` 413 /
  517 at 0.65-0.74 (timer-bound, the control). PREs are auto-precharge, so a
  burst is 8 columns + 1 ACT = 9 commands through one slot per cycle: 8/9 of
  peak less refresh = 695, measured 686. The slot IS the ceiling.
- Pumice (FR-FCFS core, same `mc_dfi_cmd_path`) `TEST_DUAL` 0 -> 1:
  `col_major_interleaved` 613 / 680 -> 682 / 767, `row_thrash` 615 / 682 ->
  683 / 769, `random` 578 / 642 -> 623 / 703, `col_major` 410 / 472 both
  (unchanged, as it should be). Dual-issue reads within 1.7 % of the model's
  ideal; pumice writes keep one extra cycle per burst that is not the lane.
- Filed MC-014: a row lane on `mc_bank_pick`, priced at +92..+100 MB/s on
  the two pure families and +110..+145 on `random` by the model, +68 / +87
  measured on pumice.

### 2026-11-12: items 2-5, the other four policies

Full tables and recipe:
`ddr2-characterization/char_results/sim_mc013_policies_2026-11-12.md`; CSVs
`model_ramulator2_ddr2_<config>_2026-11-12.csv` for the 16 new configurations
(`char_model.py` CONFIGS: `*_wm<lo>_<hi>`, `open32_scatter`, `open32_refburst8`,
`open32_rowhit`, `open{32,8}_bankrr[_col]`).

- Tooling: `ModelConfig` gained the write-drain watermarks, refresh scatter,
  the refresh burst (a DDR2 subclass with nRFC and nREFI x n) and the scheduler
  choice; the overlay gained `scheduler/impl/bank_fifo_rr.cpp` (per-bank
  FIFOs, rotor over the ready heads, `column_first`) and the registration
  patch its CMake hunk; `run --txn` sets a sim's count; `run-trace` replays
  captured files. The exporter `perf_axi_trace.py` sits with the perf proxies
  (`PERF_AXI_TRACE=<dir>`); `perf_mixed_family.measure` takes a `phase_hook`
  so the bracket skips the untimed pre-pass. Tests in
  `references/ramulator2/tests/test_char_model.py` cover the configs, the
  trace contract and the exporter's line format.
- Verdicts: write drain and refresh placement -- no CSR, no task (the first is
  the policy granite already has, the second is 0.6 %); queue shape -- MC-016;
  the trace exporter -- the rebuilt single-direction streams stand, `mixed`
  switches to the captured trace, and the model's own policy matters (plain
  FR-FCFS is not the ideal on `row_thrash`: use `open32_rowhit` as the
  ceiling there).
