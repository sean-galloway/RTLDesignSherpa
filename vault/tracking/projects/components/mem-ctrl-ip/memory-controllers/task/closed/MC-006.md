## Why

The pumice storage plane at N=8 with merge off closes 75 MHz (review, 01_pumice_cams "Bottom line"); what breaks it is the TASK-060 write/read combiners (+473 LUT and two cross-plane same-cycle cones) and the snarf read-your-write forward (the rd_cam failing endpoints). The narrow pack rewrites AW/AR through the host edge for a board that never issues narrow bursts (row 12), the address mapper barrel-shifts on a live `bank_lsb` CSR (row 13), and the CAM backend's N=16 default costs 20k LUT if anyone leaves it (row 16). None of these is an RTL change to the mechanisms; each is a build-time choice the board build should make explicitly.

## Plan

1. Expose through `pumice_core` -> `pumice_top` -> `pumice_top_geared` -> `ddr2_char_macro` -> `ddr2_char_top`: `WR_MERGE_EN`, `RD_MERGE_EN` (exist in core), `HAS_SNARF`, `NARROW_EN` (mc_axi4_plane parameters the core does not pass today), and a build-time `BANK_LSB_CONST` for the mapper (row 13: constant on the board, CSR elsewhere).
2. One define group in `ddr2_char_top`, `PUMICE_FPGA_SKU` (create_project env `PUMICE_FPGA_SKU=1`), setting merge off, snarf off, narrow off, bank_lsb constant; the default build unchanged so the research configuration still builds.
3. Host: `pumice_char` already tolerates missing merge counters (`has()`); the `bank_lsb` CSR write must be a no-op or an error the host reports when the mapper is constant.
4. Row 16: `N_SRAM_SLOTS` / `NUM_ENTRIES` macro default 8 in `mc_storage_plane` (today the board passes 8 explicitly; the default is the trap).
5. Routed A/B at sys75, every knob individually then together; failing-endpoint census by parent instance (`timing_failing_hotspots.txt`) before/after.

## Gate

pumice `run-all-func-both` at both SKUs; char harness func; the routed sys75 build with the SKU on: wr_cam / rd_cam / rd_ring failing endpoints gone or named; board smoke at **75 MHz** on the sys75 SKU bitstream (owner 2026-11-07 evening: "if pumice converges at 75mhz, why are we doing 50mhz at all anymore" -- 50 MHz stays only as the known-good anchor; the `windows` profile must pass at 75).

  switches schemes at runtime, so the CSR has to stay live. Instead the
  mapper's four 32-bit variable shifts and two variable masks on the live

  already constant shifts). The mapper has no clock, so the decode is
  combinational on the static CSR net rather than registered; it is one
  level. `formal/mc_common/mc_addr_mapper` gained family 4 (`a_ref_col`,
  `a_ref_bank`, and the clamped pair) with the old shift arithmetic as the
  reference; prove + cover pass on a clean flat, and a one-bit slice
  mutation at k=2 fails `a_ref_col` and `a_ref_col_clamped`. Handbook:
  [[variable-part-select-is-a-shifter]] second case.
- Row 16: `ddr2_char_macro` `WR_CAM_DEPTH` / `RD_CAM_DEPTH` default 16 -> 8
  (the mc_* module and plane defaults were already 8; the macro's 16 was the
  trap, and `ddr2_char_macro_tb_top` never passed a depth so the macro TB
  ran at 16). `test_ddr2_char_macro.py` comments updated; N=17 still
