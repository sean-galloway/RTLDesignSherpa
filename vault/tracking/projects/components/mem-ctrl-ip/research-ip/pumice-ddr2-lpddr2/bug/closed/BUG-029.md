# BUG-029: scheduler plane fed the refresh controller's REFpb rotor mirror from the command FIFO head, not from the granted command

**Priority:** P1
**Status:** closed (2026-10-22, fix verified: `test_pumice_top_refpb` and `run-all-func` at both geometries on the BANK_PICK core)
**Owner:** TBD
**Filed:** 2026-10-22 (mem-ctrl recovery plan Phase 2, first full pumice regression on `mc_bank_pick`)
**Repro (before the fix, `SCHED_CORE=1`):** `cd projects/components/mem-ctrl-ip/research-ip/pumice-ddr2-lpddr2/dv/tests/top && TEST_LEVEL=func python3 -m pytest test_pumice_top.py::test_pumice_top_refpb` (after `source env_python`). Arm B reads back zeros: `READ path: R @ 0x10010 = 0x0 != golden 0x1`.

## Symptom

LPDDR2 per-bank refresh (`REF_CTRL.mode=2`). The DFI slave's DRAM model logs
`refpb_with_open_row: REFpb issued but rotor bank 2 is ACTIVE`, then bank 3,
4, ... 0 at every tREFIpb tick, then `no_act_before_rd: RD bank=0 but
state=idle`, and the readback through the REFpb stream returns zeros. The
model closed banks the controller believed open.

## Mechanism

JESD209-2 6.6: a REFpb carries no bank address; the DEVICE's internal
counter picks the bank in strict rotor order and the controller can only
mirror it. `mc_xddr2_refresh_ctrl` advances its mirror on
`refresh_grant_i && grant_was_pb_i`. `mc_scheduler_plane` drove
`grant_was_pb_i` with `cmd_op_o == OP_REFPB` -- the op at the command FIFO's
READ side. Both pick cores pulse `refresh_grant` in the cycle they PUSH the
REF/REFpb into that FIFO, so at the grant cycle the FIFO head is an older
command (or the FIFO is empty): the mirror advanced only when the FIFO
contents happened to line up. On the FRFCFS core they did, by the accident
of its pipeline spacing; on `mc_bank_pick` they never did, the mirror stayed
at bank 0, the drain PRE closed bank 0 before every REFpb while the device
refreshed bank 1, 2, 3, ..., each with its row open. The device closes the
refreshed bank; the controller's row image still shows it open; the next
column to it fires into an idle bank (row-0 fallback data, zeros).

## Fix

`mc_scheduler_plane.sv`: `.grant_was_pb_i (a_cmd_op == OP_REFPB)` -- the
push-side (core output) op in the grant cycle, the same cycle for both cores.
The FIFO-head wiring is gone.

## Why it was invisible

The FRFCFS core has run the refpb cell green since the mode landed; the
mirror was advancing from a FIFO head that happened to hold the REFpb (its
drain PREs and the REFpb are spaced by its five-stage pipe, and CMD_DELAY
keeps the head in place long enough). A second core with a different
grant-to-head spacing exposed it in the first regression. The plane-level
contract was "the kind of the command being granted"; nothing in the plane
checked that the signal it wired meant that.

## Collateral

None. `r_rfc_cnt` in both cores keys its tRFC/tRFCpb load off the core's own
output op, which was already correct.
