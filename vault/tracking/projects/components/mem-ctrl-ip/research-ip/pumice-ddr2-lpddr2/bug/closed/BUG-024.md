## Symptom

The soak (defer enabled, randomized demand/overdue) ends with the DUT's
lifetime grant counter one BELOW the TB's granted count:
`AssertionError: assert 36 == 37` (grant issued by the TB never lands in
`total_o`). Deterministic at `SEED=58170` (the TB seeds its own
`random.Random(int(os.environ.get('SEED', '12345')))` — NOT cocotb's
random seed; unset SEED always runs the 12345 scenario, which passes).

## Pre-existing — proven, not a Phase-2 regression

2026-10-10: reproduced on the pristine pre-Task-1 tree
(`git worktree add /tmp/pumice-pre 0a0a216c6`, same command, same seed —
FAIL). Phase 2's mc_common_pkg extraction (Task 1) was exonerated by the
same A/B. Surfaced now only because the full-suite harness drew 58170; no
prior recorded run drew it.

## Likely shape (for whoever picks it up)

One grant is issued in a cycle where the DUT is not in a state that counts
it — candidates: grant while `req` deasserts same-cycle (TB grants on
`req() && rng < 0.8` after 1 clock of demand), a defer/overdue window that
swallows a re-request, or `total_o` increment gated on a condition the
granted command didn't meet. The TB's model counts every `grant_one()`;
the DUT counts accepted ZQ commands. A one-cycle skew between the TB's
grant pulse and the DUT's accept would produce exactly this off-by-one at
demand-dependent seeds.

## Suggested first discriminator

Log `req`, `grant`, `total_o`, and the FSM state at the failing seed;
find the cycle where `grant_one()` pulses but `total_o` does not advance.
Do NOT "fix" by relaxing the assertion — the accounting identity is the
test's point.

## Resolution (2026-11-02)

**The RTL is correct; the test read `obs_zqcs_total_o` one clock early.**
`obs_zqcs_total_o` is Q of `r_total`, so it trails a grant by one clock. The
soak granted inside its loop and compared `total() == grants` the moment the
loop ended, so any seed whose FINAL loop cycle issued a grant read the old
total.

Measured on the current `mc_lpddr2_zq_ctrl` with the original soak ported
verbatim (same stimulus, same edge-plus-100-ps read timing as
`TBBase.wait_clocks`), over 2 002 seeds:

| read | mismatching seeds | of which the final cycle granted |
|---|---|---|
| immediately after the loop (the old test) | 82 | 82 |
| after two settle clocks | 0 | -- |

SEED 58170 reads `36` immediately and `37` settled, against 37 TB grants --
the exact `assert 36 == 37` this item was filed on. Every mismatch is a
final-cycle grant and none survives the settle, so no grant is ever lost.

The other candidate the item named -- a grant the DUT does not count -- would
be real on silicon, because `zq_req_o` is also Q of the state and stays high
for one clock after a grant. Both arbiters already guard it:
`mc_cmd_arbiter` with `!r_zq_grant` (the comment at its ZQCS-safety block
names exactly this hazard), and `mc_bank_pick` by loading `r_zqcs_cnt` on the
grant edge so `w_zq_busy` blocks the next cycle.

**Where the test lives now.** The soak is back, in common-ip where the
module is: `common-ip/dv/tests/fub/test_mc_lpddr2_zq_ctrl.py`
`cocotb_test_random_soak` (gate 200 / func 1 000 / full 5 000 cycles), with
the settle before the accounting check, and a pinned cell
`cocotb_test_random_soak-seed58170`. The pin travels as `PIN_SEED`, because
the repo conftest stamps `SEED` per test node and overwrites one passed
through `extra_env` (the first pinned run silently drew 44120).

**Mutation check.** With the settle removed, the pinned cell fails
`SEED=58170: DUT total 36 != TB grants 37`; with it, 7 / 7 pass from a clean
build at FUNC and FULL (the FULL soak simulates ~51.9 us, i.e. 5 000 cycles).

Note: the block is LPDDR2-only, and LPDDR is deferred on every technology
until summer 2027 (TASK-042). This closes the accounting question so the
deferral does not carry an open defect.
