# BUG-001: same-id write B responses leave out of AXI order across banks

> Source: granite ISSUE-001 (filed 2026-11-03 from reading the store), REPRODUCED
> 2026-11-05 by a directed test and re-filed here as a defect. ISSUE-001 is closed
> naming this bug.

**Priority:** P2 -- an AXI ordering rule (A5.3: write responses with the same ID
return in issue order). Invisible to a master that only counts OKAY Bs; a
producer/consumer master that reads after its B can see stale data.
**Status:** closed 2026-11-07 -- fix 1 (AW-order B release queue) landed 2026-11-06, regression-clean (see Closed).
**Owner:** TBD
**Where:** `mc_bank_pick.sv:777-817` (the pick chooses across banks with no id
term), `mc_bank_fifo_store.sv:580-616` (slots drain in commit order),
`:1440-1446` (B fires on the drain's last beat).

| cell | trials | B out of AW order (same id) | different-id guard inverted |
|---|---|---|---|
| backtoback | 12 | 8 | 4 |
| constrained (AW paced) | 12 | 4 | 3 |

In every different-id trial the B order matched the DRAM drain order, which is
the mechanism: B order is commit order, and commit order is the pick's.

## Expected

Bs of one id in AW order. Bs of different ids may reorder freely.

## Fix shape (owner to choose)

1. **Release Bs in AW order, decoupled from slot lifetime (recommended, FPGA
   shape).** At AW admit push `{id}` into an 8-entry B-order queue and record
   `pos[slot]`; carry `pos` (3 bits) instead of `id` through the fetch and skid
   tags; at the drain's last beat set `drained[pos]`; emit a B whenever
   `drained[head]`, popping the queue. One B per cycle, strictly AW order
   (stronger than per-id), no id compare anywhere, the slot still frees at
   fetch-last so DRAM scheduling freedom is untouched. About 4 LUTRAM, 40 FF,
   25 LUT. The cost is B latency when an older write starves behind page hits,
   which the age class is meant to bound. This also closes memory-controllers
   BUG-001 (B FIFO without `wr_done` backpressure), since the queue is bounded
   by admission. The merged second B (`:1443-1447`) needs a two-B entry while
   STORE_MERGE_EN stays on.
2. Hold a write out of the commit set while an older same-id write is
   uncommitted (per-slot bit, the mirror of TASK-006's `r_wr_yng`). This is a
   per-direction 8 x 8-bit id compare (the CAM habit, ISSUE-001 in
   memory-controllers) and it serializes all writes of one id across banks,
   so a one-id master loses bank parallelism.
3. Mask same-id writes in the pick. Same cost and loss as 2, plus a store to
   pick to store round trip.

## Fix (2026-11-06): option 1, the AW-order B release queue

`mc_bank_fifo_store` keeps a 4 x NUM_ENTRIES release queue of ids. Every
admitted HOST burst (the last chunk of a chopped burst, or a merge into a
slot) takes an entry at AW admit; a slot records its entry (`r_wr_pos`) and
its merge's (`r_wr_mgpos`); the drain's host-burst-last beat marks the
entry (and the merge's) done; `wr_done` presents the head while it is done
and pops on the intake's ready (memory-controllers BUG-001). The drain no
longer waits for anything on the B side; the second-B queue, the drain-order
B logic and `r_wr_mgid` are gone; admission holds only when the release queue
is full. Bs leave in AW order for ALL ids, which is stronger than AXI asks and
needs no id compare; the pick is untouched.

First cut took an entry for every chunk, so a non-last chunk's entry blocked
the head forever: the store-arbiter contract test (chopped bursts) timed out
on both FIFO-store cells while the granite core test (one chunk per burst)
passed. Now only the B-owing chunk takes an entry.

Test: `test_granite_core_b_order` re-targeted. The different-id phase now only
proves the DRAIN still inverts (vacuity) and that Bs follow AW order anyway;
the same-id phase bounds the first id-3 B by the measured drain-to-DFI lead of
W1 (a B leaves at the drain, a fixed lead ahead of the write's DFI burst, so
"B after its data on the DFI" was the wrong proxy and failed 12/12).
