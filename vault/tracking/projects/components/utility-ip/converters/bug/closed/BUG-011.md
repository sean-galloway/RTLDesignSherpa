# BUG-011: axi4_to_axi3 chopped an unaligned INCR into chunks that stay unaligned — CLOSED (fixed + regressions, 2026-10-19)

**Date:** 2026-10-19
**Priority:** P1
**Severity:** HIGH
**Status:** CLOSED 2026-10-19
**Owner:** bridge stress model work
**Found by:** the Genesys 2 bridge stress model, AXI3 build (`projects/fpga-systems/Genesys2/bridge-stress`, DUT `bridge_bs_axi3`): in the harness sim, then reproduced on the board
**Affects:** `axi4_to_axi3_wr` and `axi4_to_axi3_rd`, and so every generated bridge with an AXI3 slave port that an AXI4 burst longer than 16 beats can reach

## Summary

When an AXI4 INCR burst longer than 16 beats is chopped into AXI3 bursts,
each later chunk's address was `previous chunk address + 16 beats`
(`active_addr + (chunk_beats << size)`). For an unaligned start that keeps the
misalignment: a 64-bit burst at `0x...c4` gave chunk 1 at `0x...c4 + 0x80`.
AXI says every beat after the first is size-aligned (A3.4.1), so chunk 1
must start at `aligned(0x...c4) + 0x80 = 0x...c0 + 0x80`.

Effect at the AXI3 slave: the first beat of every later chunk looks like a
partial beat (only the lanes above the false offset), while the master sent
a full beat.
- Write: a full strobe arrives on a beat the slave thinks is partial. The
  stress slave flags `S_WSTRB` (expected `0xf0`, got `0xff`); a real slave
  drops or misplaces the low lanes.
- Read: a slave may return only the upper lanes of that beat, and the
  converter forwards them unchanged into a beat the master takes as full.

Correct: chunk N > 0 starts at `aligned(start) + 16 * N` beats.

## Evidence

- Harness sim, `bridge_bs_axi3`, every profile: `S_WSTRB` on mem0/mem1/mem2
  writes, all from master acc (the AXI4 master, IDs `0x2x`), first error at
  an unaligned address.
- Board, the same DUT built from the pre-fix RTL: `clean` and `bursts`,
  seeds 1-2, 0/4 PASS, mem0 `S_WSTRB` x1324 / x1556, mem1 x858
  (`reports/board/bridge_bs_axi3_20261019_135031.csv`).
- The converters' own tests never chopped an unaligned burst.

## Fix

`axi4_to_axi3_wr.sv` and `axi4_to_axi3_rd.sv`: the chunk address step aligns
first, `(active_addr & ~(bytes - 1)) + (chunk_beats << size)`.

## Regressions

- `axi4_to_axi3_wr_tb.incr_write_len32_unaligned` and
  `axi4_to_axi3_rd_tb.incr_burst_len17_unaligned`, in the gate suite of each
  (so every level runs them). RED against the pre-fix RTL (chunk 1 at
  `0x6884`, expected `0x6880`; AW1 at `0xA842`, expected `0xA840`), GREEN
  after: the AXI3 converter tests at `REG_LEVEL=FULL` 48 passed, 1 strict
  xfail (the injected-WID assertion check).
- Bridge AXI3 tests (`test_bridge_1x2_axi3*`, `test_bridge_2x2_axi3*`),
  `TEST_LEVEL=full`: 26 passed.
