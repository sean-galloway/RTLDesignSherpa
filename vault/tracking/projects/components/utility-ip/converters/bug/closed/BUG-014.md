# BUG-014: axil_to_axi4_wide_align_wr deadlocks a slave that waits for WVALID before AWREADY

**Date:** 2026-10-24
**Priority:** P1
**Severity:** HIGH
**Status:** CLOSED 2026-10-24 (fixed; verified in sim and on the board)
**Owner:** unassigned
**Found by:** the Genesys 2 bridge stress model's `bridge_bs_mixed_b` build, `w_first` profile in the harness sim: the AXI4-Lite master's writes to a wider slave hung
**Affects:** `axil_to_axi4_wide_align_wr`, so every bridge port where an AXI4-Lite master writes a wider AXI4 slave

## Summary

The FSM ran S_AW then S_W: it raised AWVALID, waited for AWREADY, and only then
raised WVALID. A slave may wait for WVALID before it raises AWREADY (AXI
A3.3.1), so neither handshake ever happens. Bridge BUG-020 and converters
BUG-013 are the same class in other blocks.

## Reproduction

bridge-stress harness sim, `BS_PROFILES=w_first`, `bridge_bs_mixed_b`: the
write side hung before the fix.

## Fix

S_AW/S_W merged into S_REQ, which presents AW and W together; `r_aw_done` /
`r_w_done` record each handshake so either may land first, and the FSM moves
to S_B when both have. Unit test 4/4; the 16 bridge test files that build the
converter, REG_LEVEL=FULL, 123/123. The framework AXI4 slave BFM has no
W-before-AW mode, so the unit-level regression is the harness `w_first`
profile rather than a cocotb test.

## Verified on the board

`build-mixb` rebuilt with the fix (routed WNS +0.346 ns): every profile x seeds 1-3, 20000 bursts per master direction, 30/30 PASS (`projects/fpga-systems/Genesys2/bridge-stress/reports/board/bridge_bs_mixed_b_20261024_051300.csv`). The pre-fix bitstream, same host, same day: 21/27, `w_first` not run (the pre-fix harness sim had already shown the hang; the sim's pass with the fix is the regression) (`..._20261024_045157.csv`).
