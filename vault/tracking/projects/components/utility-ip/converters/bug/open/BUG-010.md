# BUG-010: peakrdl_to_cmdrsp presents every access to the regblock twice

**Date:** 2026-10-19
**Priority:** P2
**Severity:** MEDIUM
**Status:** OPEN
**Owner:** unassigned
**Found by:** the Genesys 2 bridge stress model's harness sim (`projects/fpga-systems/Genesys2/bridge-stress/dv/tbclasses/bs_harness_tb.py`, the GO-width watch)
**Affects:** `peakrdl_to_cmdrsp` and so `apb4_to_peakrdl`: every PeakRDL regblock behind them

## Summary

`regblk_req` is asserted in `CMD_IDLE` with `cmd_valid` AND held through
`CMD_WAIT_ACK` (peakrdl_to_cmdrsp.sv, the "HELD until ack" block). A
PeakRDL passthrough regblock takes `s_cpuif_req` as one transaction per cycle
it is high, so a single APB write is decoded twice. For a plain storage field
that is invisible -- the same value lands twice. For a `singlepulse` field it
is a two-cycle pulse; for a read-side-effect or W1C/counter field it would be
two side effects.

Measured: `bstress_ctl_regs.CTRL.GO` (singlepulse) is high for **2** aclk
cycles on every write, every time (`GO pulses: widths [2, 2, 2]`). Through a
toggle synchronizer (`sync_pulse`) that is two toggles: the far domain saw two
GOs, or none when both toggles fell in one of its periods -- which is how it
surfaced (the cclk stress blocks silently never restarted).

Correct: one regblock transaction per APB access.

## Notes

- The in-file comment records that shortening the strobe to one cycle
  (2026-08-17) broke every register READ through an integrated path; the
  response capture appears to depend on the held request. A fix has to keep
  reads working and be validated through an integrated build (the comment
  names stream build-mon's obs_apb window), not the converter's own suite,
  which hangs an idempotent register off the interface and cannot see this.
- Workaround in the bridge stress harness: GO / STOP are taken as the rising
  edge of their field (`bin/gen_bs_harness.py`).
