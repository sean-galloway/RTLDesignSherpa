# BUG-005: two yielding same-line write-backs can block each other forever at the write port

**Priority:** P1 -- deadlock of the memory write port (and every cache
behind it).
**Status:** open (filed 2026-11-27).
**Owner:** TBD
**Where:** `rtl/top/onyx_ccu.sv`, the write-back order (`w_aw_younger`,
`r_aw_yield`, `r_aw_pres`; BUG-003 / jet-prime BUG-002's order rule).

## What is wrong

`r_aw_yield[d]` re-arms from `w_aw_younger[d]` every cycle, and
`w_aw_younger[d]` holds while ANY other port presents the same line. Two
write-backs that each see the other as present can both yield, and an AXI
master cannot withdraw an AW, so neither is ever taken.

## Reproduction

Liveness harness `formal/onyx/onyx_ccu_live` (L4.yield, deadlock freedom
as safety: every yielding write-back has a non-yielding same-line one to
yield to): FAIL at step 5 at N = 2. N = 2 trace: cache 0's write-back to
line F accepted at step 3, cache 1's presented then (younger), cache 0
presents a second write-back to F at step 4 -- both blocked from step 4.
At N = 3 / 4 with one write per cache: cache 1 accepted at step 3, cache 2
presents F then, cache 0 at step 4 -- caches 0 and 2 yield to each other
forever. Needs three write-backs to one line presented together (N >= 3),
or a cache presenting its next same-line AW while its last one's W runs
(N = 2; jet-prime's one-drain-at-a-time engine does not, so the rig's N = 2
configuration is not exposed).

## Fix direction

Order the yield by presentation age (a total order: the older presented
write-back never yields to a younger one), so the yield relation is
acyclic. Re-run L4.yield without the one-write narrowing.
