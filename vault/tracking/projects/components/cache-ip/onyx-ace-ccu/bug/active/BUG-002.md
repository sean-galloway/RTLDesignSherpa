# BUG-002: a memory read issues while a write to the same line is in flight on the memory port

**Priority:** P1 -- a requester can be served bytes older than a completed
write-back / WriteClean.
**Status:** active (fixed and sim-verified 2026-11-26; closes when the
onyx `prove` / `prove_book` re-runs on the fixed flat PASS).
**Owner:** TBD
**Where:** `rtl/top/onyx_ccu.sv`, the memory AR candidate (`w_marc_*`).

## What was wrong

onyx held a write-back AW to a line while a slot on that line gathered
(the write may not land between the memory read and the snoop), but not
the reverse: a slot's memory read could issue while the single write port
had a burst to the same line in flight. AXI orders nothing between a read
and a write in flight, so the read could return the bytes from before the
write. The snooped cache, answering after its own write completed, reports
Invalid or Shared, so nothing replaces the stale beats.

Core-alone rig, gate cell (N 2, DW 64), seed 6, line 0x1100 (with BUG-001
fixed):

| ns | event |
|---|---|
| 2590 | port 0 launches WriteClean (line Modified, stores in it) |
| 2860 | the WriteClean's AW is accepted at memory (no slot holds the line) |
| 2880 | port 1's ReadNotSharedDirty is granted |
| 2890 | port 0 accepts the AC |
| 2900 | onyx issues the memory read (DEFER_AR=0) while the WriteClean's W beats are still in flight |
| 3060 | the WriteClean's BRESP; port 0 later drops the now-clean line |
| 3140 | port 0's answer: Invalid -- the stale memory beats are forwarded to port 1 |

## Expected

A memory read of a line does not issue while a write to that line is in
flight on the memory port.

## The fix

`r_wfly_line` captures the line of the burst the write port selects;
`w_wfly_vld = (r_wstate != W_IDLE)`. A slot's memory AR candidate waits
while `w_wfly_vld && r_wfly_line == r_line[s]` (selection to BRESP). An
already-presented AR is still held to its handshake (AXI). The write side
cannot wait on the read, so there is no cycle. A sim check names a memory
read of a line with a write to it in flight.

## Verification

- Core-alone rig: 12 of 12 gate seeds pass on the fixed RTL (exit codes
  captured); onyx full regression from clean twice, 75/75, 0 reruns.
  Mutation (the hold removed, the check kept): seed 6 stops at 2900 ns on "memory read of line 0000044 while a write to it is in
  flight"; without the check it fails the fill's data check.
- Formal: new property P24 `ap_mar_no_wr_race` (a memory AR is not first
  presented while a write to its line is in flight, AW to BRESP); cover
  `cp_mar_wr_wait` reached at step 6; mutation (the hold removed from the
  flat) fails P24 at depth 12.
- Proofs: `prove` and `prove_book` running on flat md5 34a9908c (with
  BUG-003's fix).
