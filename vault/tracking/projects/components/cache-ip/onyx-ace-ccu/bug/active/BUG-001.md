# BUG-001: a killed upgrade's CleanUnique snooped as MakeInvalid drops a peer's dirty line

**Priority:** P1 -- silent loss of completed stores between coherent caches.
**Status:** active (fixed and sim-verified 2026-11-26; closes when the
onyx `prove` re-run on the fixed flat PASSES; `prove_book` passed).
**Owner:** TBD
**Where:** `rtl/top/onyx_ccu.sv`, `map_snoop`.

## What was wrong

onyx snooped every `CleanUnique` with `MakeInvalid` (4'hC), the pair
fabric's mapping, on the argument that the requester holds the line Shared,
so no peer can hold it dirty. That holds when the request is issued, not
when it is granted. The caches' killed-upgrade rule (jet-prime Task 8): a
snoop that invalidates the Shared line before the `CleanUnique` is granted
kills the upgrade, which then completes to Invalid without its store. The
pulse and AR are already out, so onyx still grants it, possibly after a
peer took the line Modified and wrote it. `MakeInvalid` may not carry data
(IHI 0022), so the peer drops its stores.

Core-alone rig, gate cell (N 2, DW 64), seed 2, line 0x1040:

| ns | event |
|---|---|
| 1510 | port 1 launches CleanUnique (line Shared) |
| 2040 | port 0 launches CleanUnique (line Shared) |
| 2055 | port 1's upgrade granted first: port 0 snooped MakeInvalid, Shared -> Invalid (killed) |
| 2090 / 2260 | port 1 completes to Modified, stores beats 3 and 5 |
| 2350 | port 0's killed upgrade granted: port 1 snooped MakeInvalid at Modified, both stores dropped |
| 2860 | port 0 launches ReadUnique; its fill returns the line without them |

On the pre-fix RTL (HEAD 805fea022) 10 of 12 gate seeds fail this way (fill, load-hit
and final-memory data mismatches). The pair rig did not flag it: its golden
model encodes the same loss as "the fabric-contract M-kill corner".

## Expected

IHI 0022's mapping: `CleanUnique` -> `CleanInvalid` (4'h9). A Modified peer
passes the line dirty (DataTransfer + PassDirty), onyx absorbs it, and the
requester gets its single no-data beat. For the normal upgrade (peers
Shared or Invalid) the answers are the same as under MakeInvalid.

## The fix

`map_snoop`: `AMBER_ACE_CLEAN_UNIQUE` -> `ACSNOOP_CLEAN_INVALID`;
`MakeUnique` stays `MakeInvalid`. The no-data slot already handles a
DataTransfer CR (CD into the requester's buffer, PassDirty absorption, one
zero beat with RLAST on replay).
