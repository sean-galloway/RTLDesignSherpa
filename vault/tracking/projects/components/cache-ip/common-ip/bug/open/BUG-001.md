# BUG-001: the Genesys2 cache-ip rigs' "dual" sweeps never overlap the two injectors -- the host starts them 16 ms apart

**Priority:** P1 -- every board result labelled dual (both injectors) is
two single-injector runs back to back, not contention.
**Status:** open (found and reproduced 2026-11-26)
**Owner:** TBD
**Where:** the host's `start_all` (`jet/host/jet_board.py`, and its copy
`amber/host/amber_board.py`; the reference rig drives the jet host stack):
`start_ci("ci0")` then `start_ci("ci1")`, two separate UART register writes.
No harness CSR starts both injectors in one cycle.

## What is wrong

A register write over the UART bridge is a round trip: measured on the
Genesys2 2026-11-26 (`/dev/ttyUSB3`, 115200 baud), 15.9 ms at best, 216 ms
mean over 20 writes (one 4 s outlier, a marginal-channel retry); a read is
16.0 ms. At the 100 MHz harness clock that is >= 1.6M cycles between the
two starts. Every sweep cell finishes in fewer cycles than that (the
longest, the hot set at depth 1, runs 272k), so injector 0 completes before
injector 1 is started. The two caches never see each other's traffic in
flight; injector 1 finds injector 0's lines resident and takes them once.

## Reproduction

onyx TASK-001 bin 7 (2026-11-26), `ref_onyx_bringup.bit` sha256
3e1c87cdeb2e9e42, cell `hot16_we179` (mask 0xE07F, we_mix 179) at depth 1,
20,000 a side, against the reference-rig sim (`test_ref_harness_axil.py`
`onyx_hot_set_test`, `HOT_COUNT=20000 HOT_OUTSTANDING=1`):

| | transactions | lines supplied | write-backs |
|---|---|---|---|
| board | 22,874 | 8 | 16,528 |
| sim, both started together | 27,894 | 12,380 | 8,545 |
| sim, injector 1 started when injector 0 is done (`HOT_SEQUENTIAL=1`) | 22,874 | 7 | 16,522 |

The same holds for an ordinary cell: `smoke4k_we64` depth 1 gives 32
transactions on the board, 5,332 in sim started together, 128 in sim
sequential (the board's caches carried the preceding cells' lines in).

## Expected

Both injectors start in the same harness cycle (stage both, then one GO:
the rapids_char "stage-all-then-GO" precedent), so a dual cell measures
the two caches contending.

## What it invalidates

Every board number taken with both injectors active, on every rig that
uses this host: jet (pair rig), amber, the reference rig's SEL 3 (jet-prime
pair through `jet_prime_pair_fabric`) and SEL 4 / 5 (onyx), bins 1-7. The
single-injector (`--ci1-idle`) rows are unaffected, as are the like-for-like
cache comparisons built on them. What a "dual" row actually measured is
injector 0 alone, then injector 1 alone on a warm peer. That includes the
coherence claims drawn from board dual sweeps: onyx's supplied / wasted
counts on the board, "the sweep never snoops a victim in a write-back
buffer" (onyx TASK-001 bin 6), and the cycle identities between bins (still
true, but of the sequential runs). Sim results are unaffected; the sims
start both injectors together.

## Record

- 2026-11-26: found when the onyx bin 7 hot-set cell reached neither
  corner on the board while the sim of the same cell reached both;
  confirmed by the write-latency measurement and the sequential sim.
