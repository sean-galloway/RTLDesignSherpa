# BUG-006: the Genesys2 harness tally_latch_bank_test clears the tally while the MonBus path is still delivering

**Priority:** P3 (test defect; seed-dependent false failure).
**Status:** CLOSED 2026-11-26 -- the test drains the MonBus path before the
clear.
**Owner:** TBD
**Where:** `projects/fpga-systems/Genesys2/cache-ip/amber/dv/tests/test_amber_pair_harness_axil.py`,
`tally_latch_bank_test`.

## What was wrong

The test arms the first-event latch bank for every packet type, runs a
48-transaction burst, walks the 16 slots, then pulses tally_clear and,
256 cycles later, expects the bank empty. MonBus is low-bandwidth by
design: after that burst the path is still delivering when the slot walk
ends, so packets landing after the clear refill the re-armed bank. The
sibling `tally_clear_freeze_test` documents the protocol this one skipped
("the MonBus path must DRAIN before the clear pulse").

Seed-dependent: in the gate cell, seeds 2 and 68390 failed ("latch fill
not re-armed: 0x00000003") and 1 and 3 passed, identically at d36ee4882
(before the 2026-11-26 amber RTL changes) and at HEAD; func and full passed
on their seeds. A diagnostic read at seed 68390 found 7 events counted
after the clear, 3 latched.

## The fix

Before the clear, wait until the tally bins stop moving over a 256-cycle
window (bounded at 64 windows); after it, also assert that no events were
counted (`post == 0`), so a still-delivering path fails as such rather than
as a re-arm failure.

## Verification

Gate cell at seeds 68390, 2, 1, 3, 7, 11: all pass. Harness suite 6/6
from clean, 0 reruns.
