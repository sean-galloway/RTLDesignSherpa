# BUG-002: control FULL snoop soak 2126 — CRRESP IsShared set where oracle expects 0

**Priority:** P2
**Status:** closed 2026-10-27 — TB model bug (eviction accounting retired a
live line through a stale {tag, I} corpse slot); DUT was correct.

Found 2026-10-12 by FULL grid v2 (leg amber_unit_macros). Deterministic:
same seed fails identically at HEAD (post l1_ rename), at 93ce944a2
(pre-rename, post deadlock-fix B), and at 255d8d9f5 (pre-Issue-A, pre-B,
pre-rename) — identical snoop index `full_sn[2126]`, same got/expected.

## Root cause

Not an RTL defect — a testbench model bug in `AmberControlTB._score_slice`
(`dv/tbclasses/amber_control_tb.py`), present since before 255d8d9f5.

A snoop invalidate leaves the victim's tag in place with state I (a
"{tag, I} corpse" — `_hit_way`'s own comment documents that a duplicate
can exist elsewhere). When a later miss in the same set selected that dead
slot as its victim, the eviction accounting read `tags[(set, way)]` — the
stale tag — and unconditionally retired that line to 'I'. If the line had
meanwhile been re-filled into a DIFFERENT way (a live duplicate), the live
copy's `line_state` was clobbered to 'I' while the DUT correctly kept it.

The failing sequence for seed 41099 (line 0x740 = tag 0xe, set 64):

1. cyc 28292: read miss installs 0x740 S in way 0; cyc 28307 upgrade to M.
2. cyc 32416/32425: snoop READ_UNIQUE invalidates it — tag write way 0 → I
   (corpse left; model: line_state=I, slot_state[(64,0)]=I).
3. cyc 38452/38469: fresh read miss re-fills 0x740, installed S in **way 2**
   (model and DUT agree: line_state=S, slot(64,2)=S).
4. cyc 43419 (`full[1926]`): a miss in set 64 picks dead way 0 as victim.
   The accounting saw tags[(64,0)]==0x740 and retired 0x740 to I — the LIVE
   way-2 copy's state was destroyed in the model only.
5. cyc 48582 (`full_sn[2126]`): snoop READ_ONCE on 0x740. DUT answers the
   truthful S row (CRRESP 0b01000, IsShared); the corrupted model expected
   the I row (0b00000).

## Fix

Retire the victim's old line only when the victim slot was VALID
pre-install. The slot's PRE-WRITE state must be captured before
`slot_state` is updated to the install state (a first attempt read it after
the update and was a no-op — found by line_state write tracing). Same-class
guards applied to `_replay_models` (directed-path eviction) and
`AmberMonliteTB`'s eviction write. `amber_coh_macro_tb._reconcile_retired`
had already documented and worked around this exact class at tiny geometry;
it stays as a safety net with its comment updated.
