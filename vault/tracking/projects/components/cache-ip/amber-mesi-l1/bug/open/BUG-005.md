# BUG-005: amber_pair_fabric's write-port arbiter is not round-robin -- the last winner keeps top priority

**Priority:** P2 (fairness; no corruption or starvation observed).
**Status:** OPEN 2026-11-26 -- filed; not fixed.
**Owner:** TBD
**Where:** `rtl/top/amber_pair_fabric.sv`, the `w_sel` always_comb and the
`w_rr_q` update in W_IDLE.

## What is wrong

The same code as jet BUG-006 (jet's pair fabric inherited it from amber):
the scan from `w_rr_q = w_sel + 1` keeps the LAST candidate it sees, and
the last index scanned is the previous winner, so the previous winner has
top priority at every idle and the requester after it comes last. The
comment above the arbiter says "fair round-robin". The full analysis is in
[jet BUG-006](../../../jet-mesi-l1/bug/open/BUG-006.md).

## Expected

A first-match scan from `w_rr_q`: the previous winner lowest, every
candidate served within four grants.
