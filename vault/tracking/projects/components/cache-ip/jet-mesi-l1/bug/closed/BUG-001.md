# BUG-001: jet_mshr set_full_o compares claims against WAYS cast to MW+1 bits -- constant-true at MSHR_COUNT=2, WAYS=4

**Date:** 2026-11-09
**Priority:** P2
**Status:** closed 2026-11-09 -- fix committed with jet TASK-003 step 1; clean jet FULL 149/149 (first green FULL since v3), jet-g2 gate 2/2, Genesys2 bin 14 swept identical.
**Owner:** jet

## Symptom

Every jet FULL cell with `MSHR_COUNT=2` and `WAYS=4` (`test_jet_core_s128w4_m02v*_*_full`,
`test_jet_pair_rig_s128w4l64b64_m02v*_*_mon_full`) fails to build:

    %Warning-UNSIGNED: jet_mshr.sv:283:40: Comparison is constant due to unsigned arithmetic
    %Error: Exiting due to 1 warning(s)

Found by the first FULL-level run of the pushed review RTL (2026-11-09, HEAD
2bb8dd321 snapshot); the func grid never visits MSHR_COUNT=2 at WAYS=4.

## Cause

`jet_mshr.sv:283`:

    assign set_full_o = (w_set_claims >= (MW+1)'(WAYS));

`MW = $clog2(MSHR_COUNT)`; at `MSHR_COUNT=2`, `MW+1 = 2` bits and `(2)'(4)` is
0, so the compare reads `w_set_claims >= 0`: always true. Verilator reports the
constant compare and stops; a tool that did not would build a core where
`set_full_o` is stuck high, `alloc_gnt_o` never fires and every miss stalls on
`STALL_SET_OVERSUB` forever.

## Expected

`set_full_o` is "this set already has WAYS claims"; when `WAYS > MSHR_COUNT`
it can never be true. Compare in a width that holds WAYS (an `int` compare):

    assign set_full_o = (32'(w_set_claims) >= WAYS);

## Done when

- `test_jet_core.py` and `test_jet_pair_rig.py` FULL cells at `s128w4_m02v*`
  build and run; the func/gate grids unchanged.
- `formal/jet/jet_control` unaffected (jet_mshr is outside the flat).

## Fix (2026-11-09)

`jet_mshr.sv`: `assign set_full_o = (32'(w_set_claims) >= WAYS);` with the
explanation in a comment. Lint clean at `MSHR_COUNT=2, WAYS=4` and at the
defaults; identical logic at the formal geometry (`MSHR_COUNT=2, WAYS=2`).
Verification: the `s128w4_m02v4` FULL cells build and pass in `test_jet_core`
and `test_jet_pair_rig` (scratchpad `regr/corners_full.log`,
`regr/tbfix_jet_core_corners.log`); clean jet FULL 149/149 and Genesys2 bin 13
(unchanged LUT/BRAM, sweep identical to bin 12). jet_mshr IS in the
jet_control formal flat (the "Done when" above was wrong about that): the flat
was regenerated with the fix and re-proved, see the TASK-003 progress log.
