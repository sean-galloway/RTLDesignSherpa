# BUG-002: jet_wb_buffer indexes r_data with {slot, beat} -- one bit too wide at VICTIM_DEPTH=1, wrong at non-power-of-two depths

**Date:** 2026-11-09
**Priority:** P2
**Status:** closed 2026-11-09 -- fix committed with jet TASK-003 step 1; clean jet FULL 149/149 (first green FULL since v3), jet-g2 gate 2/2, Genesys2 bin 14 swept identical.
**Owner:** jet

## Symptom

Every jet FULL cell with `VICTIM_DEPTH=1` (`*_m??v1_*_full` in `test_jet_core.py`
and `test_jet_pair_rig.py`, both geometries) fails to build:

    %Warning-WIDTHTRUNC: jet_wb_buffer.sv:228: Bit extraction of array[7:0] requires 3 bit index, not 4 bits.
    %Warning-WIDTHTRUNC: jet_wb_buffer.sv:251: ...
    %Warning-WIDTHTRUNC: jet_wb_buffer.sv:337: ...
    %Error: Exiting due to 3 warning(s)

Found by the first FULL-level run of the pushed review RTL (2026-11-09).

## Cause

`r_data` is declared `[VICTIM_DEPTH * FILL_BEATS]` (8 words at depth 1) but
indexed by the concatenation `{slot, beat}` with `SLOT_W = (VICTIM_DEPTH <= 2) ?
1 : $clog2(VICTIM_DEPTH)`: 1 + 3 = 4 index bits into an 8-entry array. The
concatenation is only equal to `slot * FILL_BEATS + beat` when the array has
`2**SLOT_W * FILL_BEATS` entries, so a non-power-of-two depth (3, 5, 6, 7)
would also address the wrong word for the upper slots.

## Expected

Size the store to the index: `r_data [(2**SLOT_W) * FILL_BEATS]`. At the
default `VICTIM_DEPTH=2` this is the same 16 words as today (no FPGA-review
regression); at depth 1 it is 16 words with slot 1 unused; at depth 3 it is 32.
The three index sites keep their `{slot, beat}` form.

## Done when

- `*_v1_*_full` cells build and run in both FULL suites; default-depth cells
  bit-identical (same CRCs on the pair rig / cosim).
- The jet bin on the Genesys2 rebuilt and shown unchanged in LUT/BRAM.

## Fix (2026-11-09)

`jet_wb_buffer.sv`: `r_data [(2**SLOT_W) * FILL_BEATS]`, the three `{slot,
beat}` index sites unchanged. Lint clean at `VICTIM_DEPTH` 1, 2 and 3. At the
default depth 2 the store is the same 16 words. Verification: every `*_v1`
FULL cell builds and passes in both suites (scratchpad `regr/corners_full.log`,
`regr/tbfix_jet_core_corners.log`); clean jet FULL 149/149; Genesys2 bin 13
unchanged in LUT and BRAM and swept identical to bin 12. Found while trying to write the fix: a `//` comment that
begins with the lint tool's name is read by it as a directive and is a syntax
error.
