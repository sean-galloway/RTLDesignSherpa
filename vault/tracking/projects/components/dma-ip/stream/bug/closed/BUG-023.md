# BUG-023: the build-mon `err_window` cosim shared `test_stream_mon`'s sim_build under xdist and only passed through `--reruns`

**Status:** CLOSED 2026-11-10 -- fixed on filing in `projects/fpga-systems/Genesys2/dma-ip/stream/build-mon/dv/tests/test_stream_mon.py` (the testcase gets its own sim_build name); verified twice from `make clean-all`, 50 passed and 0 rerun each time -- once on the old comp_sram-carved window and once after stream TASK-024 moved the window to the `stream_err` SRAM (bridge respin included)
**Priority:** P3 -- a test-infrastructure defect, no hardware behind it; it hid as "2 rerun" in a green summary
**Filed from:** bridge TASK-024 (memory-controllers MC-005 phase 3), whose consumer-DV gate ran the build-mon suite clean and asked why `test_stream_mon_err_window` needed two reruns

## Reproduction

`make clean-all && make run-all-func` in `build-mon/dv/tests` (xdist, `--reruns 3`),
2026-11-10 07:57: `50 passed, 1 skipped, 2 rerun`, both reruns
`test_stream_mon.py::test_stream_mon_err_window`. The runner `_run_stream_mon`
maps each testcase to a `test_name` that is both its sim_build directory and
its log file, with the comment "every testcase gets its OWN sim_build: two
tests sharing one dir collide under xdist" -- and `_err_window` was not in the
list, so it fell through to `test_stream_mon`, the base test's name. Under
xdist the two started together and built the same tree in the same directory.
`local_sim_build/test_stream_mon/` afterwards held four results files: two of
0 bytes at 07:57:17 and 07:58:59 (the two attempts whose simulation never ran,
which is what cocotb-test reports as the failure; no log was written, so
`preserve_prior_log` had nothing to keep) and two complete ones at 08:08:43 and
08:09:04, the err_window and base tests passing 21 s apart in the shared
directory once their builds no longer overlapped. The seed is stable across
reruns ([[feedback_conftest_test_level_stamp]] / root `conftest.py`), so a
stimulus-dependent failure is ruled out by the third attempt passing unchanged.

Not a bridge or RTL defect: nothing in the sim differs between the attempts
but which worker finished linking first.

## Fix

`_run_stream_mon`: `"test_stream_mon_err_window" if testcase.endswith("_err_window")`
in the name mapping, with a comment at the site saying why. The log file
follows the name, so the err_window run now also keeps its own log instead of
overwriting the base test's.

## Why it stayed hidden

`make/tests.mk` runs every area with `--reruns 3 --reruns-delay 1`, and a
`-q` summary prints `N rerun` without the attempts' errors; the suite was green.
The rule that found it is [[feedback_no_flaky_dismissal]]: a rerun count is a
failure count until the mechanism is named.
