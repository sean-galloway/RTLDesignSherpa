# BUG-018: scheduler credit counter initialized to 0 instead of cfg_initial_credit (pre-beats)

> Migrated 2026-11-07 from `projects/components/dma-ip/rapids/TASKS.md` as **TASK-001** (that file's own numbering; vault TASK-001 is different work).

**Priority:** P0 (at the time)
**Status:** CLOSED -- fixed in the pre-beats scheduler (PRD.md: "fixed and verified (43/43)"); the module has since been retired. Verification steps 3-10 of the original are moot.
**Owner:** sean galloway

The pre-beats `rtl/rapids_fub/scheduler.sv` reset `r_descriptor_credit_counter`
to 0 rather than to the decoded `cfg_initial_credit`, so a channel blocked on
its first descriptor. The fix landed before the beats rearchitecture;
`r_descriptor_credit_counter` last appears in history at 3c308050b
(2026-01-11) and nowhere in today's `rtl/`.

The beats scheduler (`rtl/fub_beats/scheduler_beats.sv`) has **no credit
management** (its header says so), so there is nothing to re-verify. The
beats tile credits (rapids TASK-027) are a different mechanism. CLAUDE.md
"RAPIDS Subsystem" already records this as historical and obsolete.
