# Filelist and Test Generation

After RTL emission, `_emit_bridge_variant()` writes the filelist and optionally generates cocotb tests.

## Filelist generation

The filelist is written to `rtl/filelists/<bridge_name>.f`, two levels above the bridge directory. It is a complete compile closure using `$REPO_ROOT`-relative paths.

### Filelist sections

1. **Include directory** — `+incdir+$REPO_ROOT/rtl/amba/includes`.
2. **Reset macro header** — `-f $REPO_ROOT/rtl/amba/filelists/reset_defs.f`.
3. **Monitor packages** — `-f $REPO_ROOT/rtl/amba/filelists/monitor_pkgs.f` (always included, even for `"no"` variants, because the subtractive catch-all references them).
4. **Subtractive catch-all** — `-f $REPO_ROOT/rtl/amba/filelists/axi4_subtractive_slave.f`.
5. **Generated files** — package first, then other generated files sorted by tag.
6. **AXI4/AXI5 wrapper closures** — `axi4_slave_wr.f`, `axi4_slave_rd.f`, `axi4_master_wr.f`, `axi4_master_rd.f`, plus AXI5 variants when needed.
7. **Converter closures** — `axi_data_upsize.f`, `axi_data_dnsize.f`, `axi4_dwidth_converter_{wr,rd}.f`, `axil_to_axi4_wide_align_{wr,rd}.f`.
8. **Protocol shim closures** — APB, AXI-Lite, AXI3, Wishbone, AXI5 atomic filters/read-return trackers as needed.
9. **CDC closures** — `axi4_cdc_wr.f`, `axi4_cdc_rd.f` if any slave has `cdc=true`.
10. **Monitor infrastructure** — `_monlite` wrapper filelists and `monbus_arbiter.f`, plus the selected `monbus_<p1>_<p2>_group.f` for `"mon"` variants.
11. **Verilator waiver** — `bridge_regblock.vlt` when a cfg regblock is present.

The filelist is generated by string construction in `bridge_generator.py`, not by a template. Every dependency is pulled in via the owning component's closure filelist rather than by hand-listing individual `.sv` files.

## Test generation

When `--generate-tests` is passed:

- For `"no"` variants, `generate_tests()` emits a TB class in `dv/tbclasses/` and a test runner in `dv/tests/`.
- For `"mon"` variants, `generate_monitor_tests()` emits a TB class and a monitor-stress test runner.

Both functions use Jinja2 templates from `bin/bridge_pkg/jinja_templates/`:

| Template | Output |
|----------|--------|
| `bridge_tb_class.py.j2` | `dv/tbclasses/<class_module>.py` |
| `bridge_test_file.py.j2` | `dv/tests/test_<bridge>.py` |
| `bridge_monitor_test.py.j2` | `dv/tests/test_<bridge>_monitor.py` |

: Test generation

The TB class name is derived from the bridge name by `build_tb_class_name()`. The import block is selected by `_tb_import_block()`; if the output path is not dotted-importable (for example, because of the hyphen in `fabric-gen-ip`), the generated test falls back to a `sys.path` insertion.
