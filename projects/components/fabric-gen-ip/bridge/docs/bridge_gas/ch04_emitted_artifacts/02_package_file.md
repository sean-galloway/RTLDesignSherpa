# Package File

The package file (`<bridge_name>_pkg.sv`) is generated by `PackageGenerator` and is always the first file compiled.

## What it contains

- `BRIDGE_ID_WIDTH` — width of the internal `bridge_id` sideband.
- `NUM_MASTERS` / `NUM_SLAVES` — port counts.
- Localparam constants derived from the topology.
- Typedefs for the internal AXI4 structs used by the crossbar and adapters, such as `axi4_aw_t`, `axi4_w_<width>_t`, `axi4_b_t`, `axi4_ar_t`, `axi4_r_<width>_t`.

The exact set of typedefs depends on the unique data widths present in the bridge. For example, `bridge_mix_e` uses 32-bit and 64-bit paths, so its package defines `axi4_w_32b_t`, `axi4_r_32b_t`, `axi4_w_64b_t`, and `axi4_r_64b_t`.

## Excerpt from a generated package

```systemverilog
package bridge_mix_e_pkg;

    localparam int NUM_MASTERS = 3;
    localparam int NUM_SLAVES  = 4;  // includes subtractive catch-all
    localparam int BRIDGE_ID_WIDTH = 2;

    typedef struct packed {
        logic [3:0]  id;
        logic [31:0] addr;
        logic [7:0]  len;
        logic [2:0]  size;
        logic [1:0]  burst;
        logic        lock;
        logic [3:0]  cache;
        logic [2:0]  prot;
        logic [3:0]  qos;
        logic [3:0]  region;
        logic        user;
    } axi4_aw_t;

    // ... additional structs for W, B, AR, R at each used width ...

endpackage : bridge_mix_e_pkg
```

## Why it matters

Because the top module imports this package, any change to widths or counts changes the package and therefore every generated file in the same variant. This is one reason partial regeneration is unsafe.
