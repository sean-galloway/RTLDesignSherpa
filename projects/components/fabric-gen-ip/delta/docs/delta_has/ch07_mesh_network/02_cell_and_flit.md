# Cell and Flit

## Cell Ports

> **IMPLEMENTED** — `delta_mesh_cell` is generated by `delta_generator.py --topology mesh`. The design is per the delta mesh design spec dated 2026-10-13 (`docs/superpowers/specs/2026-10-13-delta-mesh-design.md`).

Each cell has nine AXI4-Stream interfaces:

- **6 axis neighbor ports** — +X, −X, +Y, −Y, +Z, −Z. Wrap links for any dimension are parameterizable with `--torus=x,y,z`.
- **1 diagonal tetrad port (P_DIA)** — connects the cell to its diagonal mate inside the same 2×2×1 tetrad, making every tetrad a fully-connected K4.
- **1 diagonal tile port (P_DIA2)** — connects the cell to its diagonal-tetrad corner mate inside the same 4×4×1 tile, making the four tetrads of a tile a fully-connected K4.
- **1 local port** — host-facing. Boundary cells expose this port for rapids DMA attachment; interior cells connect to local compute (SERV, CGRA, ocelus) outside delta's scope.

Conceptually, P_DIA and P_DIA2 are two instances of a single diagonal axis: one in-plane diagonal axis at tetrad scale and one at tile scale, plus the out-of-plane Z axis and the in-plane X/Y axes, give the cell four axes and nine ports.

All ports carry `TDATA`, `TVALID`, `TREADY`, and `TLAST`. The head beat also carries the packet header in `TUSER`. AMBA 5 sidebands (`TWAKEUP`, `TDATACHK` and the chapter 5 check signals) are flat-mode only in v1 — mesh mode rejects `--amba5` at generation time (mesh ports carry no sidebands; the check-signal budget is an open item if a monitored mesh port is needed).

## Clock and Reset

The mesh cell uses a single clock (`aclk`) and the active-low asynchronous reset (`aresetn`) common to the rest of delta. This is a deliberate simplification *against* the GALS direction common in the NoC literature. The trade: timing closure and generator predictability win over per-link clock flexibility. If a future system needs independent clock domains, that becomes a boundary problem solved outside the cell.

## Flit Format

A flit is one `DATA_WIDTH` beat. A packet is a head flit, zero or more body flits, and a `TLAST` tail beat. The head flit carries the header in `TUSER`; body and tail flits carry only payload and `TLAST`.

### Head-Flit Header Fields

| Field | Width | Purpose |
|-------|-------|---------|
| dest coord | 3×COORD_W | X, Y, Z destination. COORD_W is sized by the fabric dimensions. |
| src coord | 3×COORD_W | X, Y, Z source, used for responses and counters. |
| QoS class | 2 | 0 = config, 1 = latency, 2 = bulk. |
| VC | 1 | Assigned at injection per §6. |
| multicast | 1 | Set for multicast packets; group/mask reference is mode-specific. |
| misroute budget | 4 | Decremented on each non-minimal hop; packet dropped and counted at 0. |
| source-route ptr | 8 | Indexes an inline port list when source-route mode is active. |
| packet ID | 4 | Tolerates reordering at endpoints under multi-VC or adaptive routing. |

: Head-flit header fields carried in `TUSER` on the head beat.

**Note (2026-10-19):** The checked-in RTL (`delta_mesh_cell.sv`, generated from
`bin/delta_mesh/header.py`) is binding for these widths.

**Proposed (2026-10-16, not implemented):** the compute-engine tile proposes extending this header with a `level` field in the coordinates, a payload type (`cfg` / `prog` / `mem`), a length and a target address. The description lives in [`TILE_SPEC.md`](../../../../../compute-eng-ip/tile/docs/TILE_SPEC.md) Section 11, not here.

Payload streams pass transparently through the cell once the head beat has supplied the route. This is the same pass-through principle used by flat mode's `TDEST` handling, only the routing information now lives in `TUSER` rather than `TDEST`.
