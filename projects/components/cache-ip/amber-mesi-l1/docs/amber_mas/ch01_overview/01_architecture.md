# Architecture Overview

**Component:** amber — Blocking MESI Snoopy L1 Cache
**Version:** 1.0
**Status:** RTL landed; micro-architecture contract for the shared `l1_core` and the amber tops

---

## Introduction

The amber [Hardware Architecture Specification (HAS)](../../amber_has/amber_has_index.md) fixes the module set, interface shapes, and parameter decisions. This Micro-Architecture Specification (MAS) closes what the HAS deferred: the cycle-level behavior of every module, the exact control FSM state encoding, how tag and state pack into the dual-port `sdpram_core`, the replacement-policy datapaths, and the handshake timing of each external interface.

Because amber has **no register block**, there is no CSR programming chapter. All runtime visibility is through the MonBus observation fabric. The MAS therefore replaces the traditional register-map chapter with a MonBus observation map.

### What this book covers that the HAS does not

1. **Per-module micro-architecture** — how `l1_control` advances its FSM, how the pending-fill bypass register (`l1_pending_fill_bypass`) is matched and timed, how `l1_tag_array` and `l1_data_array` use `sdpram_core` port A and port B, how `l1_repl` implements each policy, and how `l1_snoop_resp` stages CR and CD.
2. **Cycle-level interface behavior** — GAXI request/response handshake timing, AXI4/ACE master channel timing, AC/CD/CR snoop ordering including the CR-after-CDLAST rule, and MonBus event emission points.
3. **The kmap workbook as decision-logic contract** — every important combinational decision signal is captured as a K-map with axis equations, checked relations, and a mechanically-derived minimal SOP. The workbook is generated by [`gen_amber_contracts_kmaps.py`](../../gen_amber_contracts_kmaps.py). The workbook was written before the RTL and still carries no `rtl_sop`; now that the RTL has landed, the next step is to diff each derived cover against the RTL expression and apply one of the three methodology verdicts: identical, RTL-redundant, or RTL-differs.

## High-Level Block Diagram

`l1_core` contains all logic shared between the two rig tops. It is the shared L1 core in `cache-ip/common-ip/rtl/top/`, built from the `l1_*` FUBs in `cache-ip/common-ip/rtl/fub/`; amber owns only the tops and `amber_ace_issue`:

```
amber_top  /  amber_ace_top        (amber-mesi-l1/rtl/top/)
+-- l1_core                        (cache-ip/common-ip/rtl/top/)
|   +-- l1_cpu_frontend            (GAXI slave request/response latch)
|   +-- l1_control                 (blocking pipeline FSM)
|   |   +-- l1_pending_fill_bypass (pending-fill bypass register)
|   |   +-- l1_victim              (depth-1 dirty victim buffer)
|   +-- l1_tag_array               (dual-port tag + MESI state)
|   +-- l1_data_array              (dual-port data store)
|   +-- l1_repl                    (replacement policy engine)
|   +-- l1_fill                    (line-fill read interface)
|   +-- l1_drain                   (dirty victim write-back interface)
|   +-- l1_snoop_resp              (ACE snoop adapter)
|   +-- l1_monlite                 (MonBus observer)
+-- amber_ace_issue                (amber_ace_top only; cache events -> ACE transactions)
+-- axi4_master_rd/wr_monlite      (amber_top)  or
|   axi4ace_master_rd/wr_monlite   (amber_ace_top)
+-- monbus_arbiter                 (merges the l1_monlite, rd and wr observer streams)
```

The pair-rig top `amber_top` wraps `l1_core` with the house plain-AXI4 read/write masters (`axi4_master_rd_monlite`/`axi4_master_wr_monlite`) toward memory and the snoop responder toward the peer cache. The onyx-rig top `amber_ace_top` wraps the same core with `axi4ace_master_rd_monlite`/`axi4ace_master_wr_monlite` and adds `amber_ace_issue` to map cache-side events to ACE coherent transactions. In both tops a `monbus_arbiter` merges the core's `l1_monlite` stream with the two master-side observer streams onto the single MonBus port.

There is no `RIG` parameter. The rig is selected by instantiating the appropriate top module.

## Key Architectural Concepts

### 1. Blocking Pipeline

`l1_control` is the only FSM in the cache. A request flows through:

1. **Lookup** — tag/state read on port A.
2. **Hit service** — data read or write on port A, response returned.
3. **Miss resolution** — ask `l1_repl` for a victim way.
4. **Victim drain** — if dirty, stage the victim and launch `l1_drain`.
5. **Fill request** — launch `l1_fill` for a whole-line burst.
6. **Fill completion** — write data and install tag + state on port A.
7. **Replay** — re-present the original request from the front-end latch; it now hits.

Because the pipeline is blocking, no new CPU request is accepted while a miss is in flight. This single-outstanding property is what makes the pending-fill bypass tractable.

### 2. Dual-Port Arrays

`l1_tag_array` and `l1_data_array` are built from the house `sdpram_core` primitive. Port A serves CPU lookups, fill writes, and replay reads. Port B serves snoop lookups and snoop data readout. The arrays themselves need no arbitration because CPU and snoop use separate ports; contention is resolved at the control FSM level.

### 3. Snoop Responder and Ordering

`l1_snoop_resp` is the only ACE-aware block inside `l1_core`. It presents a bus-agnostic `{address, type, response, data}` interface to `l1_control`. The adapter completes all CD beats for a transaction before asserting CR, matching the family convention and the cocotb-framework 1.2.0 compliance checker.

### 4. No Register Block

amber is parameter-only. Configuration, event counting, and debug visibility all come through MonBus. This is deliberate and keeps the CPU-side GAXI port the only software-visible surface.

## Design Decisions

| Decision | Source | MAS consequence |
|---|---|---|
| GAXI CPU-side slave | PRD D2 | `l1_cpu_frontend` is a GAXI slave with a latched request and in-order response stream. |
| Write-back + write-allocate | PRD D5 | Dirty victims are drained; fills are whole-line read-modify-write inside `l1_control`. |
| Plain MESI on 3-bit state | PRD D6 | `l1_pkg` encodes M/E/S/I; one bit is reserved for MOESI O-state. |
| Replacement policies {LRU, tree-PLRU, FIFO, RANDOM} | PRD D7 | `l1_repl` implements all four; LRU/FIFO/RANDOM match `cache_sim`; tree-PLRU is the timing fallback. |
| ACE-shaped snoop port | PRD D4 | `l1_snoop_resp` drives AC-ready, CR-valid, CD-valid; CR follows CDLAST. |
| MonBus observation only | PRD D8 | `l1_monlite` emits event packets and drops-and-counts under backpressure. |
