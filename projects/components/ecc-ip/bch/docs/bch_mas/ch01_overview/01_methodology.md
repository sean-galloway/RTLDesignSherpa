# Methodology

## HAS to MAS relationship

The Hardware Architecture Specification (`../bch_has/`) records what the BCH
codec is, where it sits, what it presents at its boundaries, and what
parameters configure it. This Micro-Architecture Specification carries that
architecture one level down: per-block signal tables, cycle behavior, FSM
policy, and the signal-contract references that became the contract workbook
cited against landed RTL (`ch04_contracts/01_signal_contracts.md`).

The rule in this repo is one source per fact. The MAS does not restate the
PRD decision table or the HAS block diagram; it cross-references them and adds
the implementation detail that belongs at this level. Parameters and
throughput numbers that are not yet fixed are marked **TBD** and tied to the
PRD decision ID that fixes them, following the convention in
`../bch_has/ch06_integration/02_parameters.md`.

## FSM policy

The repo's datapath FSM rule, taken from the design handbook, is:

> **No FSM in the per-beat data path. Not a minimal one, not a two-state one.**
> FSMs belong to control: descriptor lifecycle, schedulers, init sequencers,
> error recovery. If a state machine can observe a data beat, it is in the wrong
> place.
> — `vault/handbook/design/streaming-no-fsm.md`

What replaces a datapath FSM in this block:

| Instead of a state that... | Write |
|---|---|
| counts beats, or waits N cycles | a counter plus a comparator |
| remembers "I am mid-burst" | a `r_valid` flag on the pipeline stage |
| serializes because a resource is shared | an arbiter and a qualifier, not a turn-taking machine |
| gates until a condition holds | a qualifier ANDed into the handshake |

Where a state machine is genuinely justified, the handbook requires:

> Fewest states that carry the real distinctions. A state that only waits one
> fixed cycle, or that differs from a sibling only by a datapath value, is a
> register, not a state. Merge states whose outputs and successors are
> identical. Idiom: `typedef enum logic [N-1:0] {...} state_t;` + two-process
> form - registered `r_state`, combinational `w_next_state` with a default-hold
> first line and a default arm. One FSM per module; nested/communicating FSMs
> are a smell that the block wants splitting. Outputs: prefer registered
> (Moore) at module boundaries; combinational decode of `r_state` internally is
> fine but belongs in the K-maps.
> — `vault/handbook/design/minimal-fsm.md`

Every block page in this chapter states its FSM policy explicitly and cites
this page. Blocks that are purely datapath carry no FSM; the one block that
sequences decoder stages carries exactly one minimal control FSM.

## Prove-by-design / kmap philosophy

The signal-contract and kmap discipline in this repo treats the act of
mirroring RTL expressions in a computed workbook as a design review in itself:

> The act of mirroring expressions IS a design review. The stream workbook's
> first generation surfaced six findings the test suite had not...
> — `vault/handbook/design/signal-contracts-and-kmaps.md`

For the BCH MAS the posture was adopted pre-RTL (the contracts first cited
the MAS pages verbatim) and completed post-RTL: on 2026-10-08 (TASK-003
close) every citation in `bch_signal_contracts.xlsx` moved to the landed
RTL `file:line`, where `verify_citations` gates the build against drift.
The workbook is generated by
`gen_bch_signal_contracts_kmaps.py`; it is never hand-edited.

## Carrying open PRD decisions

Every undecided item in the PRD is carried as **TBD** with the decision ID
that resolves it. Examples in this document:

| Parameter / choice | PRD decision |
|---|---|
| field dimension `m` | D1 |
| correctable bits `t` | D2 |
| block length `N_BITS` | D3 |
| encoder/decoder build mix | D4 |
| erasure support | D5 |
| throughput architecture and cycle counts | D6 |
| bits per beat `BITS_PER_BEAT` | D9 |
| key-equation solver algorithm | D11 |

No numeric value is invented. Cycle-count formulas are stated in terms of the
parameters above (for example, `N_BITS` cycles per syndrome pass in the serial
case), and throughput trade-offs are placeholders tied to D6.
