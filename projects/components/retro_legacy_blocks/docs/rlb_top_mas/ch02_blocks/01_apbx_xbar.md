# RLB Top - The APB Crossbar Block

## Overview

`u_apbx_xbar` is the only address decoder in the subsystem. Every APB
transaction that enters on `s_apb_*` is steered to exactly one of ten
peripheral channels here, and every decode decision a debugger needs to
make — *which block is this address in?* — is answered by this module's
window map and nothing else.

It is not hand-written. It is generated by the shared crossbar generator
and treated as a build artifact: regenerated when the map changes, never
patched.

## Generation

Produced by
`projects/components/fabric-gen-ip/apbx-xbar/bin/apbx_xbar_generator.py`:

```python
generate_apbx_xbar(num_masters=1, num_slaves=10, base_addr=0xFEC00000,
                   addr_width=32, data_width=32, slave_size=0x1000)
```

`rlb_top` instantiates the result as `apbx_xbar_1to10` and passes only
the global bus parameters through: `ADDR_WIDTH`, `DATA_WIDTH`,
`STRB_WIDTH`, `BASE_ADDR`. The slave count and window size are baked into
the generated RTL, not parameterised at the instantiation.

## Slave Index to Window

The generated module names its peripheral channels `s0_apb_*` through
`s9_apb_*`. The mapping to the ten 4KB windows is fixed at generation
time:

| Slave | Window | Block | Base offset |
| --- | --- | --- | --- |
| s0 | 0 | HPET | `0x0000` |
| s1 | 1 | Master 8259 PIC | `0x1000` |
| s2 | 2 | 8254 PIT | `0x2000` |
| s3 | 3 | RTC | `0x3000` |
| s4 | 4 | SMBus | `0x4000` |
| s5 | 5 | PM/ACPI | `0x5000` |
| s6 | 6 | IOAPIC | `0x6000` |
| s7 | 7 | GPIO | `0x7000` |
| s8 | 8 | UART 16550 | `0x8000` |
| s9 | 9 | Slave 8259 PIC | `0x9000` |

The full decode table, including probe registers for each window, lives
in [Chapter 5](../ch05_registers/01_register_map.md) and
[Chapter 3.1](../ch03_interfaces/01_top_level.md). This page owns the
*mechanism*; those pages own the *map*.

Two facts about the map are worth recording where the crossbar is
described:

- **There is no reserved slave.** Window 9 decoded as "Reserved" when
  the crossbar was generated. When the slave 8259 moved into that window
  (RLB/pic_8259 TASK-001) the decode already existed — only the wires on
  `s9_apb_*` changed owner. No regeneration was needed, and no reserved
  window remains in the address map.
- **The window number is the address nibble.** With 4KB windows, the
  slave select is exactly `PADDR[15:12]` above `BASE_ADDR`, so the window
  number, the slave index, and the address nibble are the same value.

## Address Forwarding

The crossbar forwards the **full 32-bit address** on each slave channel.
Each peripheral instantiation slices `PADDR[11:0]` from its own channel,
so every block sees register offsets starting at `0x000` within its own
window and never learns the absolute address. A block that needs no more
than 12 bits of offset is therefore insulated from the base address; only
`rlb_top` knows `BASE_ADDR` (default `0xFEC00000`, a parameter).

## Decode Miss Behaviour

An address that matches no slave completes with `PSLVERR` asserted
instead of hanging the bus. This behaviour is owned by the **generator**,
not by this instance: the generator emits the decode-miss path, and the
hand-rolled crossbar this one replaced had already lost it. That history
is why the rule is *regenerate, don't edit* — a patch on the generated
file is exactly how the fix disappears. The unmapped-address error
response is exercised by the `func` suite (see the book index, "What the
suite proves", item 4).

## What This Block Does Not Do

- **No interrupt involvement.** The crossbar is a pure address/data path.
  Interrupts route around it entirely — see
  [The Interrupt Fabric](02_interrupt_fabric.md).
- **No clock or reset generation.** It runs on `pclk` / `presetn` like
  every block in this configuration; all `CDC_ENABLE(0)`.
- **No slave-side wait-state merging policy** beyond what the generator
  emits: each peripheral's `PREADY` is returned on its own window.
