# DFI Read Aligner (`scoria_dfi_rd_aligner`)

**Module:** `scoria_dfi_rd_aligner.sv`
**Location:** `rtl/fub/`
**Category:** DFI read datapath
**Parent:** `scoria_dfi_layer`
**Status:** implemented

## Purpose

`scoria_dfi_rd_aligner` admits read commands from the command path, drives `dfi_rddata_en_o` after `t_rddata_en_i` DFI cycles, captures returning read data, and pushes one DFI word per cycle into the read CDC FIFO. It supports multiple outstanding reads and backpressures the command path when its tracking slots are full.

## Microarchitecture internals

### Admission and backpressure

A read is admitted on `op_valid_i && op_ready_o`. The ready signal deasserts when `r_outstanding == MAX_OUTSTANDING`:

```text
op_ready_o = (r_outstanding < MAX_OUTSTANDING)
```

`r_outstanding` increments on admission and decrements when the last word of a read is captured. `MAX_OUTSTANDING` is sized at least as large as the read CAM depth so the ready signal does not deassert in steady state.

### Stateless rddata_en delay line

The enable window is generated by a shift register `r_age[PIPE-1:0]`, where `PIPE = MAX_RDDATA_EN + EN_CYC`. An admission shifts in on each cycle; the enable output is the OR of `EN_CYC` consecutive taps starting at `t_rddata_en_i`:

```text
w_en = OR over b in [0, EN_CYC-1] of w_fired[t_rddata_en_i + b]
dfi_rddata_en_o = w_en ? all-ones : 0
```

This handles contiguous or `tCCD`-spaced reads without an FSM: overlapping windows from multiple outstanding reads simply OR together.

### `EN_CYC` versus `BL_WORDS`

`EN_CYC` and `BL_WORDS` are separate on purpose:

| Quantity | Meaning |
|---|---|
| `EN_CYC` | True DQ-bus occupancy: `ceil(DRAM_BL / DFI_RATE)` DFI cycles |
| `BL_WORDS` | Number of DFI words captured and pushed per read |

: Table 2.24.3: `EN_CYC` versus `BL_WORDS`

`scoria_core` passes `RD_EN_CYC_CORE = ceil(DRAM_BL / DFI_RATE)` as `EN_CYC`. The old default of `BL_WORDS` would have halved the enable window for narrow devices and lost half of every burst. The build must satisfy `EN_CYC >= BL_WORDS`.

### Enable-window credit

The PHY asserts a preamble `dfi_rddata_valid` one cycle before the real data window. A simple outstanding-read gate would capture that preamble and shift the whole burst. The aligner uses an enable-window credit: one credit is minted for every enable cycle and spent for every captured word.

```text
w_credit_avail = r_credit + (w_en ? 1 : 0)
w_word_valid   = |dfi_rddata_valid_i && (w_credit_avail != 0)
w_cap_fire     = w_word_valid && (r_outstanding != 0) && rd_ready_i
```

The credit **must be combinational**. A registered credit reads zero on the first enable cycle when data and enable arrive together (the a7_read_gated model), dropping the first word. That is why the credit includes the current cycle's enable contribution.

### Capture and last-word marking

Captured data is pushed to the CDC FIFO with `rd_resp_o = RESP_OKAY`. `rd_last_o` is asserted when `r_rcnt == BL_WORDS - 1`. `r_rcnt` resets on the last word so the next read's capture starts at word 0.

The capture gate has three conditions:

```text
1. at least one bit of dfi_rddata_valid_i is set
2. w_credit_avail is non-zero (inside the real data window)
3. at least one read is outstanding
4. rd_ready_i is high (downstream FIFO can accept)
```

`rd_valid_o` is asserted whenever conditions 1-3 hold; `rd_data_o` and `rd_resp_o` are driven combinationally. Only the actual push (condition 4) decrements credit and advances `r_rcnt`.

### Debug probes

Under `!SYNTHESIS`, the block maintains counters for returned and captured beats, plus the two blocked-beat counters. A nonzero `dbg_blocked_real` means a real data beat was discarded, which shifts every later beat by one and corrupts the burst stream. The first-block snapshot records how many cycles the enable had run and how many words had already been captured, making it easy to distinguish a preamble from a credit-accounting bug.

## FSM policy

There is no FSM. The aligner is a delay line, a credit counter, and an outstanding-read counter.

## Timing

- `dfi_rddata_en_o` asserts `t_rddata_en_i` DFI cycles after admission.
- The enable window lasts `EN_CYC` DFI cycles.
- Captured words are pushed one per cycle starting in the first data-valid cycle inside the window.

## Notes

- The non-synthesis assertion `assert (!(rd_valid_o && !rd_ready_i))` fires if a read beat is lost because the return FIFO is full. The return-path sizing contract makes this unreachable; the assertion turns any future sizing break into a hard failure.
- Debug probes `dbg_blocked_pre` and `dbg_blocked_real` count valid beats rejected before any read is outstanding (preamble/stray) and while a read is outstanding (dropped real data). `RD_ALIGN_TRACE` enables cycle-by-cycle `$display` logging under `!SYNTHESIS`.
- The module comment header and some internal names still say "LPDDR2" because the file was inherited from pumice; the operational targets are DDR3 and LPDDR3.
