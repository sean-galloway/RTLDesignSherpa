# RAPIDS Network Planes

**Location:** `projects/components/dma-ip/rapids/rtl/plane/`
**Status:** New (2026-10-15)

---

## Overview

A RAPIDS network plane is the endpoint between the core's network-side stream and the pins: the sink ingress (RX) on one half and the source egress (TX) on the other, each with its monitor-lite. The planes used to sit inside `rapids_src` and `rapids_snk`. They now sit in the top, so one core can drive either an AXI-Stream or a CXS network and the choice is made by the module name alone.

Every plane takes the same parameters and presents the same inner interface:

- `fub_axis_*`: the core-facing AXIS stream (TDATA, TSTRB, TLAST, TID = channel, TDEST, TUSER)
- `cfg_mon_*` in, `sts_mon_*` out: the SRC.RDMON_* and SNK.WRMON_* monitor CSRs (rapids TASK-015)
- `monbus_*` out: client 1 of the half's `monbus_arbiter`, in the core (`src_plane_mon_*`, `snk_plane_mon_*`)

| Plane | Contents | Outer pins |
|---|---|---|
| `rapids_plane_axis_rx` | `axis4_slave_monlite` (the original sink endpoint) | `s_axis_*` |
| `rapids_plane_axis_tx` | `axis4_master_monlite` (the original source endpoint) | `m_axis_*` |
| `rapids_plane_cxs_rx` | `cxs_slave_monlite` + `cxs_to_axis` | `s_cxs_*`, `snk_cxs_*` status |
| `rapids_plane_cxs_tx` | `axis_to_cxs` + `cxs_master_monlite` | `m_cxs_*`, `src_cxs_*` status |

Both trees (byte-granular `rtl/top`, beat-granular `rtl/top_beats`) share the same planes. Filelists: `rtl/filelists/plane/*.f`.

## Tops

| Top | Tree | Filelist |
|---|---|---|
| `rapids_top` | byte | `rtl/filelists/top/rapids_top.f` |
| `rapids_cxs_top` | byte | `rtl/filelists/top/rapids_cxs_top.f` |
| `rapids_beats_top` | beats | `rtl/filelists/top_beats/rapids_beats_top.f` |
| `rapids_beats_cxs_top` | beats | `rtl/filelists/top_beats/rapids_beats_cxs_top.f` |

All four are GENERATED by `bin/gen_plane_tops.py` from the tree's base (`rapids_top_base.sv`, `rapids_beats_top_base.sv`): everything that is not a plane lives in the base, and the generator copies the base's parameter and port text verbatim, then instantiates the base and the two planes. Never hand-edit a top; edit the base or the generator and run

```bash
python3 projects/components/dma-ip/rapids/bin/gen_plane_tops.py          # regenerate all four
python3 projects/components/dma-ip/rapids/bin/gen_plane_tops.py --check  # fail if any is stale
```

The AXIS tops keep exactly the interface they had before the split (28 parameters, 203 ports), so existing instantiations, the FPGA harnesses and the AXIS test suites are unchanged.

## The CXS link

The CXS planes use one fixed link profile. It is Arm IHI 0079 Issue D, chosen because only Issue D has the SRCID, TGTID and USER sidebands:

| Property | Value |
|---|---|
| Links | one per direction (write path into RAPIDS, read path out); `CXSSRCID` carries the channel |
| `CXSMAXPKTPERFLIT` / start alignment | 2 / 16 bytes; one AXIS packet = one CXS packet, never two per flit |
| Stream framing | per stream on the channel bits of `CXSSRCID` (`CXS_STREAM_SRCID_BITS` = CIW): channels interleave mid-packet |
| `CXSSRCID` / `CXSTGTID` | `TID` (the RAPIDS channel) / `TDEST` |
| `CXSUSER` | `{TUSER, TSTRB}`; `TUSER` is dropped when `DATA_WIDTH/8 + AXIS_USER_WIDTH > 128` |
| Link control | explicit credit return, activation and deactivation on; idle deactivation after `CXS_IDLE_CYCLES` |
| Parity | off |

CXS top parameters:

- `CXS_MAX_CREDIT` defaults to `SRAM_DEPTH`, one channel's SRAM in beats. Override it lower if you like.
- `CXS_RX_FIFO_DEPTH` defaults to the credit count; the receive FIFO is the credit pool.
- `CXS_CREDIT_BEYOND_SPEC` is derived as `CXS_MAX_CREDIT > 63`: past the spec's 63 the link is built beyond spec, and the far end must be too.
- `CXS_IDLE_CYCLES` is 32.

Credits are a single pool for the whole link: a grant carries no ID, so it can't be reserved for one channel. Status pins: `src_cxs_link_state`, `snk_cxs_link_state`, `*_cxs_protocol_error` (sticky), and `snk_cxs_unsupported` (sticky: a flit that AXIS framing cannot represent arrived; see [the adapters](../../../../../docs/markdown/rtl-amba/cxs/axis_to_cxs.md)).

Carrying `TSTRB` in `CXSUSER` is what keeps the byte-granular RAPIDS exact over CXS. Its partial last beats and unaligned starts cross the link intact. The cost is a `DATA_WIDTH` limit of 1024: CXSUSER is at most 128 bits.

Why per-stream framing is load-bearing: the byte-granular source arbitrates round-robin per drain block while a packet spans the whole descriptor. With two or more source channels active, the egress therefore switches channel mid-packet. That is legal AXIS (TID interleaving) and legal CXS (stream interleaving, IHI 0079D 2.5.2), provided every block on the link frames packets per stream. Before 2026-10-16 the CXS family tracked one open packet per link, and this traffic broke it.

The byte-granular sink contract carries over unchanged. Where the AXIS plane holds `s_axis_tready` until the channel's descriptor has been fetched, the CXS plane's receive FIFO fills and it stops granting credits.

## Monitoring

The CXS planes program `cxs_monitor_lite` from the same CSRs as the AXIS planes and use the same agent IDs (sink 0x09, source 0x0A). Packets are tagged `PROTOCOL_CXS`. The top's monbus group filters CXS through its AXIS mask slot (see `docs/markdown/rtl-amba/monitor/monbus_group_core.md`). A PACKET_END completion carries the channel (CXSSRCID) in `event_data[55:48]`; `channel_id` holds `{PRCLTYPE[2:0], TGTID[5:0]}`. The lite drops and counts when events outrun its 4-entry output queue. The beats tree's one-beat egress packets at FUNC depth do that: 12 of 16 completions are delivered and 4 come back as Error/EVENT_DROPPED. The test checks delivered + dropped == issued.

## Verification

| Suite | Cells |
|---|---|
| `dv/tests/top/test_rapids_cxs_top.py` | source, sink, source_bytes, sink_bytes, source_concurrent, sink_concurrent, cxs_mon, ext_addressing |
| `dv/tests/top_beats/test_rapids_beats_cxs_top.py` | source, sink, source_concurrent, sink_concurrent, cxs_mon, ext_addressing |

The concurrent cells launch four channels with one `KICK_ENABLE` write. On the source side, the egress must actually switch channels mid-packet on the byte tree, or the cell fails for not exercising the case. On the sink side, four channels' flits are interleaved beat by beat on the link.

The testbench is `dv/tbclasses/rapids_cxs_top_tb.py`. It reuses the AXIS top testbench as-is and swaps only the network BFMs: an RDS-DV `CXSTransmitter` on `s_cxs_*`, a `CXSReceiver` on `m_cxs_*`, and a `CXSMonitor` on each link. Every cell also requires the link to be clean: no BFM or monitor violation, and the DUT's error flags low. Scenarios that never touch the network ports (status, perf windows, the control path, the monitors-off build) run only against the AXIS tops. The core testbenches inject packets on the `plane_mon_*` ports and require them on the monbus output (`check_plane_monbus`).
