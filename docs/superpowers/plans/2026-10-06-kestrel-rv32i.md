# kestrel-rv32i Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the kestrel single-cycle RV32I core end to end — RTL, cocotb verification, riscv-tests battery with spike lockstep, riscv-formal ISA proofs, and the *Simplified RV32I* doc book — proving the falcon-suite flow at the smallest scale.

**Architecture:** One SystemVerilog core (`kestrel_core`) with combinational-read Harvard memories and a decode truth table (no control FSM). RVFI retire signals are first-class ports from the start — they feed both the cocotb lockstep TB and riscv-formal. The doc book sources live in the rung's `docs/simplified_rv32i/` and build through the repo's `bin/md_to_docx.py` pipeline, exactly like the Simplified DFI books.

**Tech Stack:** SystemVerilog, cocotb 1.9.2 + cocotb-test (venv via `source env_python`), rds-dv framework (`cocotb-framework` 1.2.0), Verilator/Icarus + Yosys/sby/smtbmc (oss-cad-suite at `/mnt/data/tools/oss-cad-suite/bin`), sv2v (`/tmp/sv2v/sv2v-Linux/sv2v`), xpack RISC-V toolchain, spike ISS, riscv-tests, riscv-formal.

**Spec:** `docs/superpowers/specs/2026-10-06-riscv-falcon-suite-design.md` — the plan argues from it, and the executor reads both.

## Global Constraints

- XLEN = 32; RV32I base only at this rung — **no** M extension, **no** C extension, **no** CSR file (spec, Rung 1).
- Module/identifier prefix is `kestrel_`; the directory is the compound `kestrel-rv32i` (suite README naming doctrine).
- Memories are combinational-read, Harvard (spec "Memory contract"); loads/stores complete in the issue cycle.
- All RTL under `projects/components/riscv-ip/kestrel-rv32i/rtl/` must be reachable from a `.f` under a `filelists/` dir, and the area must be registered in `bin/filelists.toml` (repo filelist contract).
- Run all Python/pytest/cocotb through the venv: `source env_python` first. oss-cad-suite and sv2v are added to PATH per command below.
- TDD: every RTL task writes the cocotb test first, watches it fail, implements, watches it pass, commits.
- Every commit must pass `python3 bin/filelist_registry.py --check --audit --blindspots --ratchet --placement` and `python3 bin/check_broken_links.py --ratchet` before pushing (the pre-commit gates run them anyway; run them yourself so a foreign lane's noise is distinguishable from yours).
- **Spec-silent decision made here (documented in the book):** misaligned loads/stores are handled *in hardware* (byte-lane rotation) rather than trapped, so kestrel passes `rv32ui-p-ma_data` without a trap mechanism. RISC-V permits either; hardware costs little in a single-cycle datapath.

## Review Focus

Inputs/behaviors the spec implies but no obvious task's test covers — each is pinned to an owning task below.

1. **Writes to x0 are discarded; x0 always reads zero.** A reasonable person assumes `addi x0, x0, 5` changes nothing. Pinned in Task 3 (regfile) and re-pinned via RVFI in Task 5.
2. **Back-to-back dependent ALU ops** (write lands on the clock edge, read by the next instruction) must produce the forwarded-in-time value, since single-cycle has no explicit forwarding. Pinned in Task 5.
3. **Reset vector is defined** (`RESET_ADDR` parameter, first fetch there). A reasonable person expects the first fetch at a known address. Pinned in Task 5.
4. **After ECALL/EBREAK the machine halts and holds** — no runaway fetches into undefined memory. Pinned in Task 8.
5. **FENCE / FENCE.I retire as NOPs** with no state change (spec: documented NOP). Pinned in Task 8.
6. **Misaligned LW/LH/LHU/LB/LBU/SW/SH/SB work via byte-lane rotation** (per the spec-silent decision above). Pinned in Task 7 (`ma_data`-shaped vectors).

```
│   ├── top/kestrel_core.sv       # datapath + PC + RVFI + halt (top)

│       (kestrel_pkg.f, fub/*.f, top/kestrel_core.f, kestrel_all.f)

├── docs/simplified_rv32i/      # book sources + generate_pdf.sh + outputs
formal/kestrel/riscv-formal/    # riscv-formal wrapper + checks.cfg (outside
                                # the component tree, per repo formal/ pattern)
```

RTL layout follows the dma-ip/stream convention (the repo-approved
per-component layout): packages in `rtl/includes/`, leaf blocks in
`rtl/fub/`, tops in `rtl/top/`, and one filelist per block under
`rtl/filelists/` (each declaring its own complete closure, foreign
sources only via their own filelists) with `kestrel_all.f` as the
aggregate. Own-area filelist paths use `$KESTREL_ROOT`, registered in
`env_python`, `bin/TBClasses/shared/filelist_utils.py`, and
`bin/filelist_registry.py` — renamed 2026-10-07 from the flat Task 2
layout, which predated this convention note.

`bin/filelists.toml` gains one `[[area]]` block; `make/tests.mk` may need a
one-line nested-area adjustment (verified in Task 2).

The core top interface (fixed here; every task and both verification flows
build against it):

```systemverilog
module kestrel_core #(
    parameter logic [31:0] RESET_ADDR = 32'h0000_0000
) (
    input  logic        clk,
    input  logic        rst_n,
    output logic [31:0] imem_addr,      // combinational read
    input  logic [31:0] imem_rdata,
    output logic        dmem_req,
    output logic [31:0] dmem_addr,      // combinational read
    input  logic [31:0] dmem_rdata,
    output logic [3:0]  dmem_wstrb,     // byte strobes (rotated for misaligned)
    output logic [31:0] dmem_wdata,     // rotated to strobes
    output logic        halt,
    output logic [3:0]  halt_cause,     // 0 none, 1 ecall, 2 ebreak, 3 misaligned target, F illegal
    output logic        rvfi_valid,
    output logic [63:0] rvfi_order,
    output logic [31:0] rvfi_pc_rdata,
    output logic [31:0] rvfi_pc_wdata,
    output logic [31:0] rvfi_insn,
    output logic        rvfi_trap,
    output logic [4:0]  rvfi_rs1_addr,
    output logic [4:0]  rvfi_rs2_addr,
    output logic [31:0] rvfi_rs1_rdata,
    output logic [31:0] rvfi_rs2_rdata,
    output logic [4:0]  rvfi_rd_addr,
    output logic [31:0] rvfi_rd_wdata,
    output logic [31:0] rvfi_mem_addr,
    output logic [3:0]  rvfi_mem_rmask,
    output logic [3:0]  rvfi_mem_wmask,
    output logic [31:0] rvfi_mem_rdata,
    output logic [31:0] rvfi_mem_wdata
);
```
