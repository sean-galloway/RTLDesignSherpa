# PUMICE 100 MHz Convergence — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure pumice's FRFCFS pick core and read aligner so the controller closes timing at aclk 100 MHz / dfi_clk 200 MHz (WNS ≥ 0 both domains) with zero-bubble steady-state issue and no functional/perf regression.

**Architecture:** Known-ahead winner per the approved spec: CAM push-side pre-decode, two registered pick stages (A: pool qualify vs registered bank image; B: window overlay + age-oldest select), speculative `r_pick_next` (pool minus firing winner — index only, no payload in cone), hold-on-not-fired at the unchanged live fire authority; aligner capture decoupled from the rd CDC FIFO full flag via a 1–2 entry dfi_clk skid.

**Tech Stack:** SystemVerilog (Verilator sim, cocotb pytest harness), Vivado 2025.1 OOC synthesis for timing, `bin/vivado_timing_failures.py` for cone bucketization, `bin/render_block_diagram.py` for diagrams.

**Spec:** `docs/superpowers/specs/2026-10-20-pumice-100mhz-design.md` (read it; this plan argues from it).

## Global Constraints

- Sim environment: `source env_python` from repo root, `export PYTHONPATH="$(pwd)/bin"`, Verilator only (never icarus). Clean `local_sim_build` dirs after RTL changes.
- **No assertions/`$error`/SVA added to synthesizable RTL** (mem-ctrl-ip AGENTS.md); pre-existing legacy assertion blocks stay but are not extended.
- **Shared tree discipline:** ~55 files from other lanes are staged and ~197 modified — commit ONLY with `git commit --only <paths>`; include both sides of any rename (open/X.md AND closed/X.md) in the pathspec.
- `CLOSE_ON_DRAIN` stays a `pumice_core` parameter, default **0**; `PUMICE_CLOSE_ON_DRAIN=1` rebuild must keep the close_drain probe passing.
- `mc_cmd_arbiter`, the CAMs, and the DFI fubs are shared with granite (frozen — no granite edits, no granite validation); record every shared-module change in the final report.
- Timing target: WNS ≥ 0 on aclk (10 ns) and dfi_clk (5 ns), OOC synth `xc7a100tcsg324-1`, async clock groups, same flow as the 2026-10-20 baseline run (`/tmp/pumice_timing_head/`, regenerate per run — /tmp is not durable).
- Perf pass band: bw within ±2%, latency within ±5 ns of the Task-1 baselines per cell.
- No board programming (owner's call). No submodule interface changes outside the files this plan names.

## Review Focus

1. **Hold under prolonged gate block** — live JEDEC gate fails for many cycles (refresh episode, tRFC window): winner must hold stable, `cmd_valid_o` must not glitch, and the first fire after the window must be correct and legal (dropped picks are NOT acceptable per spec §3.4).
2. **Pop-dependency winner** — the speculative next-winner after a commit/issue pop must match what the old comb logic would have chosen for the shrunk pool; a wrong speculative pick fires an illegal/ out-of-order command (cmd_stream_checker is the tripwire).
3. **Speculation vs maintenance override** — refresh/init/ZQ/maintenance grants preempt the demand pick; the speculative `r_pick_next` must be discarded (not latched) when an override wins the cycle.
4. **CLOSE_ON_DRAIN=1 build** — with the parameter on, the auto-precharge tracker interacts with the new registered stages; the close_drain probe and func suite must pass in both parameter values.
5. **Order-mode / BANK_IN_ORDER interaction** — the per-bank in-order mask (`w_wr_head`/`w_rd_head` application at mc_cmd_arbiter.sv:790-810) must apply identically inside the new Stage B, or in-order SKUs issue out of order.
